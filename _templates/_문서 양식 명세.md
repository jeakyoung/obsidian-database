# 문서 양식 명세 v2

이 저장소의 **모든 개발 문서**는 아래 5단계 골격 하나를 공유한다.
골격(단계 수·순서·의미)은 고정이고, **단계 이름만 디렉토리 유형에 따라 달라진다.**

> v1 → v2 변경점: 단계 번호(`## 1. 개요`)를 떼고 **아이콘 + 이름**(`## 📋 개요`)으로 바꿨다.
> 메타 표는 항목명을 굵게 쓰고 빈 칸을 `—` 로 채운다.
> 블로그 모양은 저장소 루트의 `quartz.custom.scss` 가 담당한다.

---

## 1. 골격

```markdown
# {문서 제목}          ← 파일명 / frontmatter title 과 동일

## 📋 개요             ← 메타 표 + 한 줄 요약. 모든 유형 공통
## {아이콘} {배경 단계}  ← 왜 이 문서가 생겼는가
## {아이콘} {본문 단계}  ← 무엇을 했는가 / 무엇이 정해졌는가
## {아이콘} {결과 단계}  ← 확인·검증·후속
## 🔗 참고             ← 관련 문서/링크. 모든 유형 공통
```

- H2 는 이 5개만 사용한다. 세부 구분은 **H3 이하**로 내려쓴다.
- 빈 단계는 지우지 말고 그대로 둔다. 문서 간 비교가 가능해야 한다.
- 본문 맨 위 `# {제목}` 은 그대로 둔다.
  블로그에서는 Quartz 가 제목을 따로 출력하므로 CSS 로 숨겨진다(중복 방지).
  Obsidian·GitHub 에서는 평소대로 보인다.

## 2. 유형별 단계 이름

**유형 전용 폴더** — 폴더 위치로 유형이 정해진다.

| 단계 | `01_Tasks`<br>작업 | `02·03_TechDocs`<br>기술문서 | `03_Meetings`<br>회의록 | `04_References`<br>참고자료 |
|:--:|:--|:--|:--|:--|
| 1 | 📋 개요 | 📋 개요 | 📋 개요 | 📋 개요 |
| 2 | 🔍 현상 및 원인 | 🎯 배경 및 요구사항 | 💬 논의 내용 | ⚙️ 환경 및 전제 |
| 3 | 🔧 조치 내용 | 🏗 설계 및 구현 | ✅ 결정 사항 | 📖 상세 내용 |
| 4 | ✅ 검증 및 결과 | ✅ 검증 | 🔜 후속 조치 | ⚠️ 주의사항 |
| 5 | 🔗 참고 | 🔗 참고 | 🔗 참고 | 🔗 참고 |

**그 밖의 폴더** — frontmatter 의 `type` 으로 유형이 정해진다.
(`03_Learning`, `02_Career`, `99_UNI` 등. 새 문서용 템플릿은 두지 않는다.)

| 단계 | `학습자료` | `경력문서` | `프로젝트문서` |
|:--:|:--|:--|:--|
| 1 | 📋 개요 | 📋 개요 | 📋 개요 |
| 2 | 🧩 핵심 개념 | 🧭 경력 요약 | 🎯 목표 및 범위 |
| 3 | 📖 상세 내용 | 🛠 주요 수행 내용 | 🏗 진행 내용 |
| 4 | 💡 정리 및 활용 | 🏆 성과 및 역량 | ✅ 결과 및 회고 |
| 5 | 🔗 참고 | 🔗 참고 | 🔗 참고 |

아이콘까지 포함해 **글자 하나까지 동일**해야 한다.
`tools/apply_body_format.py` 가 이 이름으로 단계를 찾기 때문이다.

> 골격은 **모든 문서에 예외 없이** 씌운다(폴더 안내 페이지인 `index.md` 만 제외).
> 내용이 많고 단계에 딱 안 맞는 기존 문서는 **3번 단계 아래에 통째로** 들어간다.
> 원래 제목들은 H3 이하로 내려가고, 지워지는 줄은 없다.
> 내용이 없던 문서는 **빈 골격만** 남는다.

## 4. 본문 작성 규칙

개발 문서이므로 아래를 지킨다.

1. **코드·쿼리는 반드시 코드 펜스 안에 둔다.**
   언어를 명시한다: ` ```sql `, ` ```java `, ` ```javascript `, ` ```bash `
   펜스 없이 두면 블로그에서 `#FFFACD` 같은 값이 태그로 잘못 인식된다.

2. **변경 대상은 표로 정리한다.** 정렬은 `|:--|` 로 통일한다.

   | 구분 | 대상 | 변경 내용 |
   |:--|:--|:--|
   | SP | `SP_WMA624_01_LIST` | 조인 조건 수정 |
   | 화면 | `WPR559_CT.js` | CSS 주입 추가 |

3. **검증은 체크박스로 남긴다.** `- [ ]` / `- [x]`
   완료된 항목은 블로그에서 흐리게 표시된다.

4. **후속 조치는 담당·기한을 함께 적는다.**

   | 조치 | 담당 | 기한 | 상태 |
   |:--|:--|:--|:--|

5. **한 줄 요약은 인용문(`>`)으로 쓴다.** 개요 표 바로 아래에 둔다.

6. **이미지는 `Jeakyoung_Blog/resources/` 에 두고** `![[파일명.png]]` 로 삽입한다.

## 6. 블로그 스타일 (Quartz)

`quartz.custom.scss` 하나가 블로그 겉모양을 전부 담당한다.
GitHub Actions 가 빌드할 때 이 파일을 Quartz 의 `quartz/styles/custom.scss` 자리에 복사한다.

| 대상 | 적용 내용 |
|:--|:--|
| 본문 첫 `# 제목` | 숨김 (Quartz 가 제목을 따로 출력하므로 중복 제거) |
| H2 단계 | 아래 밑줄 + 위 여백 확대 |
| H3 | 왼쪽 강조선 |
| 표 | 둥근 테두리, 머리글 음영, 행 호버 |
| 개요 메타 표 | 굵은 항목명 칸을 라벨처럼 음영 처리 |
| 인용문 | 카드형 배경 (한 줄 요약용) |
| 코드 | 둥근 모서리 + 배경 |
| 체크박스 | 완료 항목 흐리게 |
| 태그 | 알약 모양 |

색은 전부 `quartz.config.ts` 의 테마 변수만 쓰므로 라이트/다크 모드가 함께 맞는다.
수정 후에는 `quartz.custom.scss` 를 커밋하면 배포가 자동으로 다시 돈다.

## 7. 도구

```bash
python tools/apply_body_format.py --apply   # 본문을 이 명세에 맞춰 정렬
python tools/build_format_docs.py --apply   # 각 디렉토리 index.md 에 양식 안내 갱신
python tools/build_index.py --apply         # 각 디렉토리 index.md 문서 목록 갱신
```

`apply_body_format.py` 는 여러 번 돌려도 안전하다(멱등).
이미 양식을 갖춘 문서는 단계 제목과 메타 표만 현재 명세로 맞추고,
이미 채워 넣은 값은 그대로 보존한다.
