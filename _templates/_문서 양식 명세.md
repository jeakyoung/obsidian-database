# 문서 양식 명세 v1

이 저장소의 **모든 개발 문서**는 아래 5단계 골격 하나를 공유한다.
골격(단계 수·순서·의미)은 고정이고, **단계 이름만 디렉토리 유형에 따라 달라진다.**

---

## 1. 골격

```markdown
# {문서 제목}          ← 파일명 / frontmatter title 과 동일

## 1. 개요             ← 메타 표 + 한 줄 요약. 모든 유형 공통
## 2. {배경 단계}       ← 왜 이 문서가 생겼는가
## 3. {본문 단계}       ← 무엇을 했는가 / 무엇이 정해졌는가
## 4. {결과 단계}       ← 확인·검증·후속
## 5. 참고             ← 관련 문서/링크. 모든 유형 공통
```

- H2 는 이 5개만 사용한다. 세부 구분은 **H3 이하**로 내려쓴다.
- 빈 단계는 지우지 말고 그대로 둔다. 문서 간 비교가 가능해야 한다.

---

## 2. 유형별 단계 이름

| 단계 | `01_Tasks`<br>작업 | `02·03_TechDocs`<br>기술문서 | `03_Meetings`<br>회의록 | `04_References`<br>참고자료 |
|:--:|---|---|---|---|
| 1 | 개요 | 개요 | 개요 | 개요 |
| 2 | 현상 및 원인 | 배경 및 요구사항 | 논의 내용 | 환경 및 전제 |
| 3 | 조치 내용 | 설계 및 구현 | 결정 사항 | 상세 내용 |
| 4 | 검증 및 결과 | 검증 | 후속 조치 | 주의사항 |
| 5 | 참고 | 참고 | 참고 | 참고 |

## 4. 본문 작성 규칙

개발 문서이므로 아래를 지킨다.

1. **코드·쿼리는 반드시 코드 펜스 안에 둔다.**
   언어를 명시한다: ` ```sql `, ` ```java `, ` ```javascript `, ` ```bash `
   펜스 없이 두면 블로그에서 `#FFFACD` 같은 값이 태그로 잘못 인식된다.

2. **변경 대상은 표로 정리한다.**

   | 구분 | 대상 | 변경 내용 |
   |------|------|-----------|
   | SP | `SP_WMA624_01_LIST` | 조인 조건 수정 |
   | 화면 | `WPR559_CT.js` | CSS 주입 추가 |

3. **검증은 체크박스로 남긴다.** `- [ ]` / `- [x]`

4. **후속 조치는 담당·기한을 함께 적는다.**

   | 조치 | 담당 | 기한 | 상태 |
   |------|------|------|------|

5. **이미지는 `Jeakyoung_Blog/resources/` 에 두고** `![[파일명.png]]` 로 삽입한다.

## 5. Frontmatter

양식과 별개로 모든 문서는 아래 속성을 가진다. 상세는 `Jeakyoung_Blog/README.md` 참고.

```yaml
title / date / type / project / status / tags
```

유형 전용: 작업 `priority`·`assignee` · 기술문서 `category`·`assignee` · 회의록 `attendees` · 참고자료 `category`
