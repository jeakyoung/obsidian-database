# 배열 탐색·정렬 기초 문제

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **분류** | 코딩테스트 |
| **관련 기술** | Java, 배열, 정렬, 탐색 |
| **정리일** | 2026-10-13 |

> 코딩테스트에서 가장 자주 나오는 기초 유형인 정렬·탐색·투 포인터·해시 활용 문제 모음. 면접 코딩테스트 대비용.

## 🧩 핵심 개념

- 정렬 알고리즘의 기본 동작(버블 정렬)과 시간복잡도 O(n²)을 직접 구현으로 설명할 수 있어야 함
- 이분 탐색(Binary Search)은 **정렬된 배열**에서만 쓸 수 있다는 전제조건이 핵심
- "두 수의 합" 같은 탐색 문제는 이중 for문(O(n²)) → 해시맵(O(n))으로 최적화하는 흐름이 단골 질문

## 📖 상세 내용

### 문제 1 — 버블 정렬 구현

배열을 오름차순으로 정렬한다. 인접한 두 원소를 비교해 swap하는 방식.

```java
public static void bubbleSort(int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        for (int j = 0; j < arr.length - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}
```

- 바깥 루프 한 번 돌 때마다 가장 큰 값이 뒤로 "가라앉는다" → 안쪽 루프 범위를 `- i`만큼 줄여도 됨 (이미 정렬된 뒤쪽은 다시 볼 필요 없음)
- 시간복잡도 O(n²) — 면접에서 "더 빠른 정렬은?"이라고 물으면 병합정렬/퀵정렬 O(n log n)을 언급하면 충분 (실제 구현까지 요구하는 경우는 드묾)

### 문제 2 — 이분 탐색 구현

정렬된 배열에서 특정 값의 인덱스를 찾는다. 없으면 -1 반환.

```java
public static int binarySearch(int[] arr, int target) {
    int left = 0, right = arr.length - 1;
    while (left <= right) {
        int mid = (left + right) / 2;
        if (arr[mid] == target) {
            return mid;
        } else if (arr[mid] < target) {
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }
    return -1;
}
```

- 전제조건: 배열이 **정렬되어 있어야** 함 — 정렬 안 된 배열이면 선형 탐색(O(n))부터 해야 한다고 먼저 언급하는 게 중요
- 매번 탐색 범위를 반으로 줄이므로 시간복잡도 O(log n)

### 문제 3 — 두 수의 합 (Two Sum)

배열에서 합이 `target`이 되는 두 수의 인덱스를 찾는다.

```java
// 방법 A: 이중 for문 - O(n^2)
public static int[] twoSumBrute(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[i] + arr[j] == target) {
                return new int[]{i, j};
            }
        }
    }
    return new int[]{-1, -1};
}

// 방법 B: 해시맵 - O(n)
public static int[] twoSumHash(int[] arr, int target) {
    Map<Integer, Integer> seen = new HashMap<>(); // 값 -> 인덱스
    for (int i = 0; i < arr.length; i++) {
        int complement = target - arr[i];
        if (seen.containsKey(complement)) {
            return new int[]{seen.get(complement), i};
        }
        seen.put(arr[i], i);
    }
    return new int[]{-1, -1};
}
```

- 방법 A는 직관적이지만 느림. 방법 B는 "지금까지 본 값"을 해시맵에 저장해두고, 짝이 되는 값(`target - 현재값`)이 이미 나왔는지 바로 확인 — 한 번의 순회로 끝남
- 면접에서 가장 흔한 꼬리질문: "왜 더 빠른가요?" → 매번 배열 전체를 다시 뒤지는 대신 해시맵 조회가 O(1)이라서

### 문제 4 — 배열에서 두 번째로 큰 값 찾기

정렬을 쓰지 않고 한 번의 순회로 두 번째로 큰 값을 찾는다. (중복값 처리 주의)

```java
public static int secondMax(int[] arr) {
    int max = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
    for (int num : arr) {
        if (num > max) {
            second = max;
            max = num;
        } else if (num > second && num != max) {
            second = num;
        }
    }
    return second;
}
```

- 가장 많이 실수하는 지점: `[5, 5, 3]`처럼 최댓값이 중복될 때 두 번째로 큰 값을 `5`가 아니라 `3`으로 처리해야 함 → `num != max` 조건이 그 역할
- 정렬해서 뒤에서 두 번째를 꺼내는 방법(O(n log n))도 가능하지만, 한 번 순회(O(n))가 더 효율적이라고 비교해서 설명하면 가산점

## 💡 정리 및 활용

- 모든 풀이에서 "이 방법의 시간복잡도는 얼마고, 왜 그런지"를 한 문장 붙이는 습관이 중요 (면접관이 거의 항상 물어봄)
- brute-force(이중 for문) → 최적화(해시맵/투포인터) 흐름으로 설명하는 패턴을 다른 문제에도 그대로 적용 가능
