# 면접 예상 질문 정리

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **분류** | 면접준비 |
| **관련 기술** | Java, SQL, 웹 개발, PLM/ENOVIA |
| **정리일** | 2026-10-13 |

> ENOVIA(PLM) 유지보수/개발 신입 포지션 면접 대비 예상 질문 및 답변 포인트 정리.

## 🧩 핵심 개념

- 지금까지의 실무 경험(백엔드 API, 멀티테넌트, DB 저장 프로시저, JWT 인증, FTP 연동)을 PLM 도메인 요구사항과 연결지어 답변하는 것이 핵심
- PLM/ENOVIA처럼 직접 다뤄본 적 없는 영역은 솔직히 모른다고 말하고, 빠른 학습 의지로 마무리
- 역질문은 반드시 1~2개 준비

## 📖 상세 내용

### 1. 인성/기본 질문

| 질문 | 답변 포인트 |
|:--|:--|
| 자기소개 해주세요 | 백엔드 API/DB 경험 + ENOVIA는 처음이지만 빠르게 적응 가능하다는 흐름으로 마무리 |
| 지원 동기는 무엇인가요? | 엔지니어링에 ICT를 접목하는 알텐코리아의 사업 방향이, 지금까지 해온 백엔드/DB 작업을 PLM 도메인으로 확장할 기회라고 생각함 |
| 왜 이 직무(ENOVIA PLM)에 관심이 있나요? | 익숙한 백엔드/DB 영역이 PLM 도메인에도 그대로 적용된다는 점, 새로운 도메인 지식을 실무로 배울 수 있다는 점 |
| 본인의 장점/단점은 무엇인가요? | 장점: 낯선 시스템·레거시 코드 분석/적응력 / 단점: 솔직한 약점 + 보완 노력 한 문장 |
| 3개월 인턴 후 정규직 전환이 안 될 수도 있는데 괜찮나요? | 각오와 책임감을 보여주는 방향으로, 불안보다 성장 기회로 답변 |
| 협업하다 의견 충돌이 있으면 어떻게 하나요? | 사실/근거 기반으로 논의하고, 필요하면 상위 판단에 맡긴다는 식의 균형 잡힌 답변 |

### 2. 기술 경험 질문 (실제 프로젝트 기반)

| 질문 | 답변 포인트 |
|:--|:--|
| 백엔드 API를 설계할 때 가장 신경 쓰는 부분은? | 일관된 응답 포맷, 예외 처리, 인증/인가 분리 |
| 멀티테넌트 구조를 설계/운영해본 경험을 설명해주세요 | 요청 헤더로 테넌트를 구분하고, 테넌트별 DB 커넥션/설정을 분기해서 조회한 구조 — 구체적으로 어떻게 분기했는지 설명 준비 |
| 저장 프로시저 기반으로 로직을 짠 이유는? 애플리케이션 레벨 처리와 차이는? | DB에 가까운 로직(집계, 트랜잭션 묶음)은 SP로, 그 외 흐름 제어는 애플리케이션에서 — 트레이드오프(유지보수성 vs 성능) 설명 |
| SQL Server, PostgreSQL, Oracle을 각각 다뤄봤다고 했는데 문법/동작 차이로 겪은 어려움이 있나요? | 날짜/문자열 함수, 페이징 문법(TOP vs LIMIT vs ROWNUM) 차이 경험 위주로 |
| JWT 인증을 구현할 때 고려한 점은? | 만료 처리, 갱신(refresh) 흐름, 서명 검증 |
| FTP 연동 중 겪은 트러블슈팅 경험이 있나요? | 경로/인코딩 이슈, 연결 실패 시 재시도 처리 등 실제 겪은 사례 하나 준비 |
| 트랜잭션 처리 중 겪은 이슈가 있나요? | DB 롤백, 동시성 충돌, 여러 서비스 호출을 하나의 트랜잭션으로 묶을 때의 주의점 |

### 3. PLM/ENOVIA 관련 (모른다고 솔직히 답할 영역)

| 질문 | 답변 포인트 |
|:--|:--|
| PLM이 무엇인지 설명해보세요 | "제품의 설계부터 생산, 폐기까지 전체 라이프사이클 데이터를 관리하는 시스템"이라고 개념만 답변 |
| ENOVIA나 유사 솔루션(PDM, ERP 연동)을 다뤄본 적 있나요? | 직접 다뤄본 적은 없지만, 설계 변경·버전 관리 흐름이 기존에 해온 데이터 이력관리/트랜잭션 처리와 개념적으로 닿아있다고 이해하고 있다고 답변 |
| CAD나 기구설계 프로그램 경험이 있나요? | 솔직히 없다고 답하고 학습 의지 강조 |

### 4. Java/SQL/웹 기본기 확인

| 질문 | 답변 포인트 |
|:--|:--|
| Java에서 String과 StringBuilder의 차이는? | String은 불변(immutable), 수정 시마다 새 객체 생성 / StringBuilder는 가변(mutable)이라 반복적인 문자열 조작에 효율적 |
| JSP와 최신 프론트엔드(Vue/React)를 같이 쓰는 이유/구조는? | 레거시 화면은 JSP로 유지하면서, 신규 화면은 Vue/React로 점진적으로 전환하는 구조일 가능성 — 모르면 일반론으로 답변 |
| SQL에서 JOIN 종류와 차이는? | INNER JOIN(교집합), LEFT/RIGHT JOIN(기준 테이블 전체 + 매칭), FULL OUTER JOIN(합집합) |
| 인덱스는 왜 쓰고, 언제 성능에 안 좋은 영향을 주나요? | 조회 성능 향상 목적, 단 INSERT/UPDATE가 많은 테이블에는 인덱스 과다 시 쓰기 성능 저하 |

### 5. 역질문 (마무리 — 반드시 준비)

- "이번 포지션은 실제로 어떤 고객사의 ENOVIA 환경에 투입되는 구조인가요?"
- "인턴 기간 동안 어떤 식으로 온보딩/교육이 이루어지나요?"
- "팀 구성이 어떻게 되어 있고, 신입이 주로 맡는 업무 범위는 어디까지인가요?"

## 💡 정리 및 활용

- 2번(본인 프로젝트 경험 꼬리질문 대응)이 가장 중요 — 멘트를 외우지 말고 "왜 그렇게 했는지"를 2~3문장으로 설명하는 연습
- 3번(PLM/ENOVIA)은 모른다고 솔직히 말하되, 학습 의지로 마무리하는 멘트 하나만 준비
- 역질문 1~2개는 반드시 준비해서 마무리
