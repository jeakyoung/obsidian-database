# 처음 보는 코딩테스트 실전 대비 가이드

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **분류** | 면접준비 |
| **관련 기술** | 코딩테스트 일반, 면접 전략 |
| **정리일** | 2026-10-13 |

> 코딩테스트를 한 번도 본 적 없고 전공시험만 봐온 상태에서, 알텐코리아 ENOVIA(PLM) 신입 면접의 코딩테스트를 어떻게 준비할지 정리.

## 🧩 핵심 개념

- 전공시험은 "외운 지식을 재현"하는 시험, 코딩테스트는 "문제를 눈앞에서 직접 풀어가는 과정을 보여주는" 시험 — 평가 기준 자체가 다름
- 면접 중 코딩테스트는 대부분 **화이트보드/노트북 라이브 코딩** 형태일 가능성이 높음 (온라인 플랫폼 사전 시험이 아니라 면접관이 그 자리에서 지켜봄)
- 정답을 맞히는 것보다 "막혔을 때 어떻게 행동하는가"가 더 크게 평가됨

## 📖 상세 내용

### 1. 진행 방식 예상 시나리오

| 형태 | 특징 | 대응 |
|:--|:--|:--|
| 노트북/종이에 직접 구현 | 면접관이 옆에서 지켜봄 | 생각을 소리 내어 말하면서 작성 |
| 화이트보드 코딩 | 컴파일러 없이 손으로 씀 | 문법 실수는 크게 감점 안 됨, 로직이 중요 |
| 온라인 플랫폼 (사전 과제형) | 혼자 풀고 제출 | 시간 배분과 엣지케이스 검증이 중요 |

ALTEN 공고는 "면접 시 코딩 테스트 진행"이라고 명시 → 라이브 코딩에 가까울 확률이 높음. 즉 **침묵하며 혼자 코드만 짜는 연습보다, 말로 설명하면서 짜는 연습**이 실전에 더 가깝다.

### 2. 문제 풀이 5단계 (전공시험과 가장 다른 지점)

1. **문제를 소리 내어 다시 말해보기** — "입력이 ~이고, 출력이 ~이군요" 하고 요구사항을 확인
2. **예시 입력으로 손으로 먼저 풀어보기** — 코드를 짜기 전에 직접 값을 대입해서 어떤 로직이 필요한지 눈으로 확인
3. **접근 방법을 말로 먼저 설명** — "투 포인터로 양쪽에서 좁혀가며 비교하겠습니다" 등 코드 짜기 전에 전략 한 문장
4. **코드 작성** — 막히면 "일단 무식하게(brute-force) 풀고, 시간 남으면 최적화하겠습니다"라고 말하고 진행해도 괜찮음
5. **검증** — 빈 배열, 길이 1, 중복값, 음수 등 엣지케이스를 스스로 언급

> 전공시험 버릇대로 "정답이 틀리면 안 된다"는 압박에 조용히 혼자 고민하는 게 가장 흔한 실수. 중간 과정을 계속 말로 내보내는 것 자체가 점수.

### 3. 막혔을 때 대처법

- 모르면 "지금 이 부분이 막혔는데, ~한 방식으로 접근하면 될 것 같은데 맞을까요?" 처럼 힌트를 유도하는 질문을 던져도 됨 (완전히 혼자 풀어야 하는 시험이 아님)
- 완벽한 풀이가 안 떠올라도, 아는 범위의 brute-force(O(n²)이라도) 로직부터 말하고 시작하는 게 백지보다 훨씬 나음
- 문법이 헷갈리면 "Java였으면 `StringBuilder.reverse()`를 쓰면 되는데, 정확한 메서드명이 헷갈립니다"처럼 개념은 알고 있다는 걸 드러내기

### 4. 입출력 기본 템플릿 (Java, 온라인 환경 대비)

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = Integer.parseInt(sc.nextLine().trim());
        // 입력 처리 후 로직
        System.out.println(n);
    }
}
```

- 온라인 저지형이면 입력 파싱 실수(공백, 줄바꿈)로 틀리는 경우가 실제 로직 실수보다 많음 — `trim()` 습관화
- 라이브 코딩이면 입출력 코드는 생략하고 메서드 로직만 짜도 되는 경우가 많으니, 면접관에게 "입출력 처리는 생략하고 로직만 작성해도 될까요?"라고 먼저 물어보기

## 💡 정리 및 활용

- 지금 가장 먼저 할 일은 "정답을 많이 외우기"가 아니라 "말하면서 코드 짜는 연습"을 몇 번 해보는 것 — 혼자 풀 때도 소리 내어 설명하며 풀어보기
