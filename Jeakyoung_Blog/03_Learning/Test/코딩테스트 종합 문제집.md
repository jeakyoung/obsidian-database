## 📖 상세 내용

### 문제 1 (코딩형) — 배열 최댓값 찾기

정수 배열이 주어졌을 때, 가장 큰 값을 반환하는 함수를 작성한다.

```java
public static int findMax(int[] arr) {
    int max = arr[0];
    for (int i = 1; i < arr.length; i++) {
        if (arr[i] > max) {
            max = arr[i];
        }
    }
    return max;
}
```

### 문제 2 (코딩형) — 문자열 뒤집기 (반복문 직접 구현)

`StringBuilder.reverse()` 없이 반복문으로 문자열을 뒤집는다. 투 포인터로 양 끝 문자를 swap.

```java
public static String reverseString(String s) {
    char[] chars = s.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
        char temp = chars[left];
        chars[left] = chars[right];
        chars[right] = temp;
        left++;
        right--;
    }
    return new String(chars);
}
```

### 문제 3 (코딩형) — FizzBuzz

1부터 N까지 출력하되, 3의 배수면 "Fizz", 5의 배수면 "Buzz", 둘 다 배수면 "FizzBuzz" 출력.

```java
public static void fizzBuzz(int n) {
    for (int i = 1; i <= n; i++) {
        if (i % 15 == 0) System.out.println("FizzBuzz");
        else if (i % 3 == 0) System.out.println("Fizz");
        else if (i % 5 == 0) System.out.println("Buzz");
        else System.out.println(i);
    }
}
```

- 15로 먼저 나눠보는 게 핵심 (3과 5의 공배수를 가장 먼저 체크해야 "FizzBuzz"가 "Fizz"로 덮이지 않음)

### 문제 4 (SQL형) — 부서별 직원 수 조회

`직원(EMP_ID, NAME, DEPT_ID)`, `부서(DEPT_ID, DEPT_NAME)` 테이블에서 부서명과 직원 수를 함께 조회.

```sql
SELECT D.DEPT_NAME, COUNT(E.EMP_ID) AS EMP_COUNT
FROM 부서 D
LEFT JOIN 직원 E ON D.DEPT_ID = E.DEPT_ID
GROUP BY D.DEPT_NAME;
```

- 직원이 한 명도 없는 부서도 결과에 포함시키려면 `LEFT JOIN` 사용 (INNER JOIN이면 직원 없는 부서는 빠짐)

### 문제 5 (SQL형) — 조건에 맞는 부서만 조회

부서별 직원 수가 3명 이상인 부서만 조회.

```sql
SELECT E.DEPT_ID, COUNT(*) AS EMP_COUNT
FROM 직원 E
GROUP BY E.DEPT_ID
HAVING COUNT(*) >= 3;
```

- `WHERE`는 그룹화 전 행 단위 필터, `HAVING`은 그룹화 후 집계 결과 필터 — 이 차이가 핵심

### 문제 6 (개념형) — 배열 vs 연결리스트

| | 배열(Array) | 연결리스트(LinkedList) |
|:--|:--|:--|
| 메모리 구조 | 연속된 공간 | 노드가 포인터로 연결 |
| 인덱스 접근 | O(1) | O(n) |
| 삽입/삭제 | 중간 삽입 시 뒤 요소 전체 이동 필요 | 위치를 알면 O(1) |
| 유리한 상황 | 조회가 많을 때 | 삽입/삭제가 많을 때 |

### 문제 7 (개념형) — String이 불변(immutable)인 이유와 성능 이슈

- **불변인 이유**: 여러 스레드가 동시에 읽어도 안전(thread-safe), 문자열 리터럴을 String Pool에 캐싱해 재사용 가능, 보안(예: 문자열이 중간에 바뀌면 안 되는 상황 방지)
- **성능 이슈**: 문자열을 `+=`로 반복 연결하면 매번 새 객체가 생성되어 메모리/성능 낭비
- **해결**: 반복적인 문자열 조작에는 `StringBuilder`(가변 객체) 사용

### 문제 8 (개념형) — 트랜잭션 격리 수준(Isolation Level)

- **필요성**: 여러 트랜잭션이 동시에 같은 데이터에 접근할 때 데이터 일관성을 보장하기 위함
- **격리 수준이 낮을 때 생기는 문제**
  - Dirty Read: 커밋되지 않은 다른 트랜잭션의 데이터를 읽어버림
  - Non-repeatable Read: 같은 트랜잭션 안에서 같은 쿼리를 두 번 했는데 결과가 다름
  - Phantom Read: 트랜잭션 중간에 다른 트랜잭션이 행을 추가해서 집계 결과가 달라짐

## 💡 정리 및 활용

- 코딩형은 배열/문자열 기본 조작 + 반복문 로직 위주로 연습
- SQL형은 JOIN과 GROUP BY+HAVING의 차이(그룹화 전/후 필터)를 명확히 설명할 수 있으면 충분
- 개념형은 외운 답보다 "왜 그런지"를 한 문장으로 덧붙이는 연습이 중요 (면접관이 꼬리 질문할 가능성 높음)
