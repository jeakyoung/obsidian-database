### 도면 가공 시연 — 포장 단독 생산 시 창고코드 버그

- 첫 창고 시작점 규칙: 출하 창고는 있으면 안 됨(하드코딩되어 있음) → 포장에서 정남영업일 경우 3300, 나머지는 3100창고로 잡아줘야 함
- 조치사항: 기존 포장 공정 창고 선택 로직을 그대로 사용, 생산수량은 잔량으로 기본 표기, 포장작업 시 해당 창고 내 재고수량이 보여야 함, 수주관리 - 수주용도2에 MES상 수량항목 뒤 콤보 추가
- ERP에 넘어간 데이터는 정상 — MES 내부 연동 확인 필요
- 테스트데이터를 출하처리까지 진행했으면 ERP 출하처리에서 삭제하기

**버그 상세:** `ProdSLService.java` 라인 982~990에서, 이전 실적 유무(`SL_ETC`)와 무관하게 창고코드를 `plantCode` 기준으로 무조건 016(출하창고, 000001) / 225(000002)로 고정하고 있음이 확인됨. 정상 동작은 이전 실적이 있으면 출하창고, 포장 단독(이전 실적 없음)이면 제품창고로 가야 함. 제품창고 코드는 `TCO102`에서 확인 후 반영하기로 함.

```sql
SELECT WAREHOUSE_CODE, WAREHOUSE_NAME, WORK_STATUS, ETC
FROM TCO102
WHERE FACTORY_CODE = '000001'
ORDER BY WAREHOUSE_CODE
```

> [!warning] 2026-09-18 기준 미해결
> 이 버그는 회의 시점에 수정 방향까지 논의됐지만, 실제 코드(`ProdSLService.java`)는 2026-09-18 확인 결과 아직 수정되지 않았다. 상세 분석과 현재 상태는 [[신진SM 포장 단독 생산 시 창고코드 오류 (미해결)]] 참고.

### ERP "고아" 데이터 조회 쿼리

`MM_OHSLINVD`에는 출고 수량이 있는데 대응하는 `MM_QTIO` 레코드가 없는 건을 찾는 쿼리:

```sql
SELECT D.CD_ITEM, D.CD_SL, D.DT_IO, D.QT_GOOD_GI
FROM MM_OHSLINVD D
WHERE D.CD_COMPANY = '1000'
AND D.QT_GOOD_GI > 0
AND NOT EXISTS (
    SELECT 1 FROM MM_QTIO Q
    WHERE Q.CD_COMPANY = D.CD_COMPANY
    AND Q.CD_ITEM = D.CD_ITEM
    AND Q.DT_IO = D.DT_IO
    AND Q.CD_QTIOTP = D.CD_QTIOTP
    AND Q.CD_SL = D.CD_SL
)
```
