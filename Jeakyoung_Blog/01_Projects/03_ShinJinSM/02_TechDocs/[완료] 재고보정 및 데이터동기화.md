# 재고 보정 및 ERP/MES 데이터 동기화

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | 신진SM ERP(`iPlusERP_SJ`) + 더존(DZ) ERP |
| **적용 범위** | 계정대체 입출고(TMA536) 정정, 월말 재고 집계(MM_OHSLINVM) 정정 |
| **관련 모듈** | `SP_WMA624_01_IUD`, `TMA536`/`TMA922`/`TMA922M`, `MM_OHSLINVM`/`MM_OHSLINVD`/`MM_PINVN` |

## 🎯 배경 및 요구사항

[[신진SM 중복 포장문제 ( 05.22 )]]로 발생한 더존 쪽 마이너스 재고를 계정대체 입고로 정정하는 작업(6월)과, 별개로 8~9월에 발견된 더존 월말 재고 집계(`MM_OHSLINVM`) 불일치를 바로잡는 작업 — 시점과 원인이 다른 두 건이 같은 "재고 보정"이라는 이름 아래 있었다. 이 문서는 둘을 구분해서 정리한다.

## 🏗 설계 및 구현

### A. 계정대체 정정 입고 (TMA536 / 더존, 2026-06)

포장 중복으로 더존에 발생한 마이너스 재고를 `SP_WMA624_01_IUD`로 계정대체 입고 처리해서 정정하는 방식. 실제 호출 형태는 [\[SQL\] SP_WMA624_01_IUD](<../04_References/[SQL] SP_WMA624_01_IUD.md>) 참고 — `@ACC_FLAG`(계정 코드), `@IN_WAREHOUSE_CODE`, `@SYSTEM_LOT_NO`, `@IO_QTY` 등을 채워 입고(`@IO_FLAG='1'`)로 호출한다.

이 SP 자체는 더존을 반영하지 않으므로([\[통합\] 더존ERP 동기화](<../04_References/[통합] 더존ERP 동기화.md>)), 정정 입고가 더존 장부까지 맞으려면 반드시 `jvWMA624_01_IUD.java` 경유로 처리해야 한다 — SP만 직접 호출하면 MES(TMA536)만 맞고 더존은 여전히 어긋난 상태가 된다.

관련 테이블:

```
TMA536 (계정대체출고) — FACTORY_CODE, IO_NO, IO_FLAG, MATERIAL_CODE, SYSTEM_LOT_NO, IO_QTY, WAREHOUSE_CODE, IO_DATE ...
TMA922 / TMA922M (재고 이력 / 재고 현황 뷰) — 창고·품목·LOT 단위 입출고 누계
```

> [!note] 진행 상태
> 이 정정 방식 자체는 확인됐지만, "어떤 LOT/창고에 얼마를 정정 입고했는지"에 대한 실행 기록이 이 문서에는 남아있지 않다. 실제 실행 이력은 `TMA536`/더존 `MM_QTIO` 원장을 직접 조회해서 확인해야 한다.

### B. 더존 월말 재고 집계(MM_OHSLINVM) 불일치 정정 (2026-08~09)

08.31/09.10 태스크([[신진SM ERP 기말 재고 오류]], [[신진SM ERP 기말 재고 오류 ( 입 출고 내역에 이상이 없을경우 )]])에서 다룬, A와는 별개인 더존 쪽 문제. 전제:

- `MM_OHSLINVD`(일별 상세) = 정상
- `MM_PINVN`(연간 집계) = 정상
- `MM_OHSLINVM`(월별 집계) = 틀어진 상태

`MM_OHSLINVD`를 `CD_SL/CD_PLANT/CD_COMPANY/CD_ITEM/YY_INV/YM_IO/CD_QTIOTP/CD_PJT/SEQ_PROJECT` 기준으로 SUM해서 `MM_OHSLINVM`과 대조하는 방식으로 불일치 품목을 탐지하고, 발견되면 `MM_OHSLINVM`을 직접 UPDATE해서 맞춘다(실제 쿼리는 [[신진SM ERP 기말 재고 오류 ( 입 출고 내역에 이상이 없을경우 )]] 참고).

> [!warning] 프로시저 호출로 고치면 안 된다
> 해당 태스크 노트에 명시된 주의사항: `MM_OHSLINVM`은 **누적가산(+=) 방식**이라, 정정을 프로시저 호출(정상 입출고 흐름)로 하면 `MM_PINVN`(연간 집계)에 이중으로 반영된다. 반드시 `MM_OHSLINVM`을 직접 UPDATE해야 하며, `MM_PINVN`까지 틀어진 경우엔 별도 확인 후 추가 조치가 필요하다.
