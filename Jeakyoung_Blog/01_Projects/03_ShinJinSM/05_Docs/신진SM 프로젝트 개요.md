# 신진SM 프로젝트 개요

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **프로젝트** | 신진SM ERP · MES |
| **기간** | 2026-04 ~ 진행중 |
| **역할** | MES 개발 담당 (POP은 기술지원만) |
| **기술 스택** | Sencha Ext JS(FE), Java 서블릿(BE), MSSQL, 더존 ERP 연동 |

> 신진SM 자체 ERP/MES(`iPlusERP_SJ`) 운영·개발 지원. 더존(DZ) ERP와 실시간에 가깝게 데이터를 주고받아야 해서, 이 프로젝트의 기술 이슈 대부분은 "MES/신진ERP ↔ 더존ERP" 두 시스템 사이의 정합성 문제로 수렴한다.

## 🎯 목표 및 범위

| 영역 | 경로/위치 | 비고 |
|:--|:--|:--|
| 웹 화면 | `WebContent/app/**` | Sencha Ext JS (MVC: `store`/`view`/`controller`) |
| 서버 | `src/com/**` | 순수 서블릿(`HttpServlet`) + JDBC, 프레임워크 없음 |
| DB | MSSQL `iPlusERP_SJ` | 저장 프로시저 중심 (`EXEC SP_...`) |
| 더존 연동 | `urlDZ`/`usernameDZ`/`passwordDZ` (web.xml) | 별도 JDBC 커넥션으로 더존 DB에 직접 연결, `NEOE.*` 스토어드 프로시저 호출 |
| POP(기술지원만) | `E:/ajk/devgit/shinjin` (C# WPF, 별도 리포지토리) | MES 개발 범위 밖, 필요 시 참고용 소스 분석만 |

로깅은 Lombok `@Log4j2` + `log4j2.xml`(콘솔 + `C:/logs/` 일자별 롤링 파일) 하나로 전 영역이 통일돼 있다 — 프레임워크 레벨의 APM/구조화 로그는 없다.

## 🏗 진행 내용

2026년 4월 말부터 정기 업무 미팅을 이어오며 아래 축으로 작업이 진행 중이다.

- **더존 ERP 연동 정합성**: 계정대체 입출고(TMA536, `SP_WMA624_01_IUD`)를 더존 수불(`NEOE.UP_PU_ITR/CGI_INSERT`)에 반영하는 구조. 포장 중복 → 더존 마이너스 재고로 이어지는 문제가 5월부터 반복 관찰됨 — [[신진SM 개발 이력]] 참고.
- **월말 재고 집계 정합성**: 더존 `MM_OHSLINVM`(월별 집계)이 `MM_OHSLINVD`(일별 상세)와 어긋나는 문제를 8~9월에 다수 발견, 개별/일괄 정정 진행 중.
- **생산실적(WPR559) 화면 개선**: 도면가공 여부 표시, 출하량 컬럼, 재고조정 엑셀 업로드 배치화 등 현장 요청 기반 개선(2026-09-08).
- **도면가공 체계 신규 동기화**: POP 시스템의 도면가공(WORK_CODE=008) 처리 흐름을 MES에도 이식하는 작업 — 설계는 끝났고(2026-09-14) DB 스크립트 일부·Java 반영은 진행 중.

## ✅ 결과 및 회고

- 더존 연동은 **"MES 저장 확정 → 더존은 best-effort로 반영"** 구조라, 더존 쪽 실패가 사용자에게 드러나지 않는다는 점이 반복적으로 문제의 근원이 되고 있다 — 로그를 직접 봐야만 더존 미반영을 알 수 있다.
- 같은 "재고 보정"이라는 이름 아래 실제로는 서로 다른 두 문제(계정대체 정정 입고 / 월말 집계 UPDATE)가 섞여 있었다 — [\[완료\] 재고보정 및 데이터동기화](<../02_TechDocs/[완료] 재고보정 및 데이터동기화.md>)에서 분리 정리.
- 포장 중복 방어는 WMA624(계정대체) 쪽과 WPR559(생산실적) 쪽이 서로 다른 코드 경로인데, 실제 방어 로직(`ISEXISTS_OUT` 가드)은 WPR559 쪽에만 구현 중 — WMA624의 IO_NO 채번 레이스 컨디션은 아직 구조적으로 남아 있다.
- 자동화된 테스트, 응답시간 모니터링, 재시도 메커니즘은 모두 없음 — 장애/이상 감지는 여전히 로그 파일 확인과 수동 SQL 대조에 의존한다.
