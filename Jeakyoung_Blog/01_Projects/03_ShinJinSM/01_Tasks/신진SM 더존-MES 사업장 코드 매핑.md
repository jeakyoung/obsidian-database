# 신진SM 더존-MES 사업장 코드 매핑

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | 신진SM 현장(재고조정 담당) |
| **요청일** | 2026-06-26 |
| **대상 시스템** | MES ↔ 더존 ERP |
| **관련 화면·프로그램** | 재고조정 화면 — 정확한 파일은 이번 조사에서 특정하지 못함 |

## 🔍 현상 및 원인

재고조정 화면에서 더존 사업장 코드가 `1000`(신진에스엠 장수)으로 하드코딩되어 있어, 다른 사업장 데이터를 다룰 때도 항상 장수 사업장으로 고정되는 문제. 같은 품목코드가 사업장만 다르게 존재하는 경우를 구분하지 못함.

## 🔧 조치 내용

더존 사업장 코드와 MES 사업장 코드가 1:1로 다르게 채번돼 있어, 매핑 테이블을 확인하고 검증 쿼리로 대조함.

| MES 사업장 | MES 코드 | 더존 사업장명 | 더존 코드 |
|:--|:--|:--|:--|
| 정남사업장 | `000001` | 신진에스엠(정남) | `2000` |
| 장수사업장 | `000002` | 신진에스엠(장수) | `1000` |
| 동탄사업장 | `000003` | 신진에스엠(동탄) | `3000` |
| 직영사업장 | `000004` | 신진에스엠(직영점) | `4000` |
| 천안사업장 | `000005` | 신진에스엠(천안) | `5000` |
| 남인천사업장 | `000006` | 신진에스엠(남인천) | `6000` |
| 향남사업장 | `000007` | 신진에스엠(향남) | `7000` |
| 경기북부사업장 | `000008` | 신진에스엠(경기북부) | `8000` |
| 기획실 | `000009` | 기획실(CS) | `9000` |
| 대전사업장 | `000010` | 신진에스엠(대전) | `9100` |
| 서울사업장 | `000011` | 신진에스엠(서울) | `9200` |
| 정남직영사업장 | `000012` | 신진에스엠(정남직영) | `9300` |

검증 쿼리 (더존 `NEOE.MA_PLANT`와 대조, 12건 전부 `Success` 확인됨):

```sql
WITH MES_MAPPING AS (
    SELECT '000001' AS MES_PLANT_CODE, '2000' AS CD_PLANT_매핑값, '정남' AS MES_사업장명 UNION ALL
    SELECT '000002',                   '1000',                    '장수' UNION ALL
    SELECT '000003',                   '3000',                    '동탄' UNION ALL
    SELECT '000004',                   '4000',                    '직영' UNION ALL
    SELECT '000005',                   '5000',                    '천안' UNION ALL
    SELECT '000006',                   '6000',                    '남인천' UNION ALL
    SELECT '000007',                   '7000',                    '향남' UNION ALL
    SELECT '000008',                   '8000',                    '경기북부' UNION ALL
    SELECT '000009',                   '9000',                    '기획실' UNION ALL
    SELECT '000010',                   '9100',                    '대전' UNION ALL
    SELECT '000011',                   '9200',                    '서울' UNION ALL
    SELECT '000012',                   '9300',                    '정남직영'
)
SELECT
    m.MES_PLANT_CODE,
    m.CD_PLANT_매핑값,
    m.MES_사업장명,
    p.CD_PLANT      AS DZ_CD_PLANT,
    p.NM_PLANT      AS DZ_공장명,
    CASE WHEN p.CD_PLANT IS NULL THEN 'Error' ELSE 'Success' END AS 검증결과
FROM MES_MAPPING m
LEFT JOIN NEOE.MA_PLANT p
    ON p.CD_COMPANY = '1000'
    AND p.CD_PLANT  = m.CD_PLANT_매핑값
ORDER BY m.MES_PLANT_CODE
```

## ✅ 검증 및 결과

매핑 자체는 06-26에 쿼리로 검증 완료(12건 전부 `Success`). 다만 **이 매핑을 코드에 재사용 가능한 형태(상수/설정 테이블)로 반영했는지는 확인되지 않음** — 이번 코드베이스 조사에서 `MES_MAPPING`류의 CTE나 이에 대응하는 상수 테이블을 찾지 못했고, `ProdSLService.java` 등에서는 여전히 `"000001".equals(plantCode)` 같은 개별 하드코딩 분기 방식이 쓰이고 있다(예: [[신진SM 포장 단독 생산 시 창고코드 오류 (미해결)]]). 즉 "1000 하드코딩 제거"라는 원 요청의 취지(사업장별 유연한 매핑)는 검증 쿼리 수준에서만 확인됐고, 실제 재고조정 화면 코드에 반영됐는지는 별도 확인이 필요하다.
