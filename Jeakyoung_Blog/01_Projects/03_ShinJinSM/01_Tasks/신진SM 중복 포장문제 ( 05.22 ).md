# 신진SM 중복 포장문제 ( 05.22 )

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | 신진SM 현장 |
| **요청일** | 2026-05-22 |
| **대상 시스템** | MES(계정대체 입출고, WMA624) ↔ 더존 ERP |
| **관련 화면·프로그램** | `SP_WMA624_01_IUD`, 더존 연동부(당시 미상, 이후 규명) |

> 이 문서는 신진SM 프로젝트에서 "포장 중복" 문제가 최초로 보고된 시점(04-28 회의록의 "출하 처리 삭제 시 중복" 관찰의 연장선)을 기록한다. 근본 구조는 이후 [\[완료\] 포장중복문제 분석](<../02_TechDocs/[완료] 포장중복문제 분석.md>)에서 규명됐고, WPR559(생산실적) 쪽 재발 방지는 [[신진SM - 더존 중복 문서처리 방어]]로 이어진다.

## 🔍 현상 및 원인

계정대체 입출고(WMA624) 처리 중 타임아웃·재시도가 겹치면 같은 작업이 중복 실행되는 문제. MES 쪽 DB(`SP_WMA624_01_IUD`)는 이미 프로시저 레벨에서 중복을 제한하고 있어 MES 자체 데이터에는 중복이 없는 것으로 확인됐으나, 더존 ERP 연동부에서는 여전히 중복 문서가 다수 생성되는 것이 관찰됨. 이 시점에는 더존 연동부의 정확한 코드 위치·원인까지는 규명하지 못한 상태였음 — "코드상 더존 연동부 확인 필요"로 다음 단계를 남김.

## 🔧 조치 내용

- MES 상 중복 포장 문제는 `SP_WMA624_01_IUD` 프로시저 레벨에서 제한하는 작업을 완료 — MES 쪽 DB에는 중복 데이터 없음
- 그러나 더존 ERP 연동부에서는 중복 포장 문제가 다수 발생 중 — 이 시점 기준 해결 필요 상태로 남음
- 다음 조치: 코드상 더존 연동부 확인 필요 → 이후 [\[완료\] 포장중복문제 분석](<../02_TechDocs/[완료] 포장중복문제 분석.md>)에서 `jvWMA624_01_IUD.java`가 더존 전용 커넥션으로 `NEOE.CP_GETNO`/`UP_PU_ITR_INSERT` 등을 best-effort로 호출하는 구조(실패해도 MES 커밋은 유지)임이 규명됨

## ✅ 검증 및 결과

MES 쪽 중복 제한은 검증됨(우리 DB에 중복 없음). 더존 연동부의 근본 해결(원자적 커밋 보장)은 이 시점 기준 미해결 — 이후 개별 가드(`ISEXISTS_OUT`, [[신진SM - 더존 중복 문서처리 방어]])로 부분 대응.
