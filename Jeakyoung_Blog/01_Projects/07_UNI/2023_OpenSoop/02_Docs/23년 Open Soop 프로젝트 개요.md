# 23년 Open Soop 프로젝트 개요

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **프로젝트** | 대학프로젝트 |
| **기간** | 2023-03 ~ 2023-09 |
| **역할** | BE 팀원 — 관리자용 게시판 모니터링 API(`admin` 패키지) 담당 |
| **기술 스택** | Java 11, Servlet 3.1, MyBatis 3.5.6, MariaDB, React Native 0.72(Expo) |

> 대학교 재학생을 위한 커뮤니티 앱. 학교/학과 인증 기반 회원가입 위에 공지·일정·자유·질문건의·장터 5종 게시판과 익명 투표를 올린 구조다.

## 🎯 목표 및 범위

- **일반적 의도**: 학교 공식 채널로는 흩어져 있던 공지·일정·게시판·투표를 학생들이 한 앱에서 확인하고 참여하게 만드는 것.
- **범위 (BE, `OpenSoopBack`)**: 회원가입/로그인/토큰, 대학교·학과 검색 및 인증, 공지사항, 일정(캘린더), 자유게시판, 질문/건의게시판, 장터게시판, 익명 투표, 회비 게시판, 관리자용 게시판 모니터링.
- **내 담당 범위**: `admin` 패키지 — 자유/건의/장터/질문 4종 게시판을 관리자가 한 곳에서 조회할 수 있는 모니터링 API 4개. 자세한 내용은 [[01_Projects/07_UNI/2023_OpenSoop/01_Tasks|작업 목록]].

## 🏗 진행 내용

| 저장소 | 경로 |
|:--|:--|
| Back-End | `OpenSoopBack` (Java Servlet + MyBatis) |
| Front-End | `OpenSoopFront` (React Native / Expo) |

- 디자인은 Figma(`PTU_UNI`)로 별도 관리했다.
- 팀 구성 (총 5명, BE 2 · FE 3):

| 이름 | 역할 | 비고 |
|:--|:--|:--|
| 김도원 | 프로젝트 리더, BE 팀장 | 회원가입/로그인/토큰, 게시판 CRUD 등 API 대부분 구현 |
| 안재경 (본인) | BE 팀원 | 관리자용 게시판 모니터링 API 4종 구현 |
| 정은유 | FE, UI 디자이너 | |
| 장현빈 | FE | |
| 최서은 | FE | 관리자 로그인 API 개발 담당 |

- 화면 기능은 크게 회원가입/로그인(학교·학과·학번·이메일 등록), 메인페이지, 일정 게시판(캘린더, 관리자만 등록·수정·삭제 가능), 자유게시판(작성자 본인 또는 관리자만 수정·삭제 가능), 질문/건의게시판(답변은 학생회 이상 권한만 가능), 익명 투표(마감 시 선택지 비공개), 공지사항(최대 4장 이미지 첨부)으로 구성됐다.
- BE 쪽 구조와 실제 코드 흐름은 [\[기술\] Servlet-Process-MyBatis 계층 구조](<../03_TechDocs/[기술] Servlet-Process-MyBatis 계층 구조.md>) 참고.
- 자세한 진행 경위는 [[23년 Open Soop 개발 과정]] 참고.

## ✅ 결과 및 회고

- 학기 프로젝트로 기획한 기능(회원가입~투표~관리자 모니터링)까지는 API 단위로 다 구현했다.
- 백엔드 저장소(`OpenSoopBack`)의 GitHub 커밋 히스토리가 `3th_OpenSoopBack` 커밋 1개로 뭉쳐 있어, 실제 작업 순서는 코드 내 작성자 주석(`YYYY.MM.DD 이름 <생성/수정>`)을 근거로 재구성했다.
- 내가 맡은 관리자 모니터링 API는 동작은 했지만, 코드를 다시 읽어보니 다건 응답 처리·이미지 목록 연결에 실제로 놓친 부분이 있었다 — 자세한 내용은 [[게시판 모니터링 페이지 구현]]과 [\[기술\] 게시판 모니터링 API 응답 구조와 한계](<../03_TechDocs/[기술] 게시판 모니터링 API 응답 구조와 한계.md>).
