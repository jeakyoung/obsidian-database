# 데이터 바우처 입고·이미지·라벨 등수삭 구현 완료 07.09

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | — |
| **요청일** | 2026-07-09 |
| **대상 시스템** | F1Soft.Starmap.Service — Input, Image, Search |
| **관련 화면·프로그램** | `InputSaveController`, `ImageController`, `SearchListController` |

> 입고(Input)·라벨 이미지(Image) 등록/수정/삭제(CRUD) 흐름 완성. 이 때 확정된 `Iud`("IU"/"D") 필드 규약이 지금 [[01_Projects/04_DataBoucher/02_TechDocs/[기술] 입고 라벨 이미지 촬영·업로드·적재 파이프라인]]에서 다루는 파이프라인의 뼈대.

## 🔍 현상 및 원인

### 재현 조건

입고 저장/수정/삭제 요청 필드가 초기 버전(`iru` 필드, `InputSeqNo` 등 프로토타입 네이밍)이라 실사용 시나리오(신규 저장/수정/삭제 각각의 필수값)와 Swagger 문서가 맞지 않았다.

### 원인

초기 구현은 기능 스텁 수준이라 필드명(`iru`→`iud`), 파일명 규칙, 이미지 선택 업로드 등 실제 운영 흐름에 맞춘 정리가 필요했다.

## 🔧 조치 내용

| 구분 | 대상 | 변경 내용 |
|:--|:--|:--|
| 컨트롤러 | `Controllers/Input/InputSaveController.cs` | 신규 저장/수정/삭제 3가지 시나리오별 샘플 요청으로 XML 문서 정리, `iru`→`iud` 필드명 통일 |
| 컨트롤러 | `Controllers/Image/ImageController.cs` | 라벨 이미지 등록/수정/삭제 엔드포인트 정리 |
| 컨트롤러 | `Controllers/Search/SearchListController.cs` | 입고 연계 검색 조건 확장 |
| 모델 | `Models/Image/{LabelListRequest,LabelListResponse}.cs` | 라벨 목록 조회용 모델 추가 (현재는 서비스단에서 주석 처리된 상태로 남아있음) |
