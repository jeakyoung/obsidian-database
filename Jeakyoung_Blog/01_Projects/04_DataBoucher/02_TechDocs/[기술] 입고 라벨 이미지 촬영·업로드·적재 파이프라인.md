# 입고 라벨 이미지 촬영·업로드·적재 파이프라인

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | F1Soft.Starmap.Service — Image |
| **적용 범위** | 이미지 파이프라인 (모바일 촬영 → 업로드 → DB 적재) |
| **관련 모듈** | `ImageController`, `ImageService`, `FtpService`, `TB_LabelMaster` |

> 이 파이프라인은 AI 함량표시 변경 분석의 "데이터 수집" 단계다. 지금 구현된 범위는 모바일에서 입고대상 라벨을 촬영해 FTP에 저장하고 `TB_LabelMaster`에 이력을 쌓는 부분까지이며, 사진을 분석해 함량표시 변경 여부를 판별하는 AI 모듈 자체는 이 저장소 범위 밖이다.

## 🎯 배경 및 요구사항

데이터 바우처 프로젝트는 [[01_Projects/02_iFrog/index.md|I-Frog]] 프로젝트(같은 `F1Soft.Starmap.Service` 코드베이스)를 카피해 새로운 시스템으로 구현한 신규사업이다. 프로젝트 전체 목표는 입고등록 대상 라벨 사진을 대량으로 모아 AI 모듈로 라벨 내 함량표시가 변경됐는지 여부를 자동 분류·모니터링하는 것이다.

이 저장소에서 직접 만든/담당한 부분은 그 중 **데이터 수집 단계** — 모바일에서 입고대상 라벨 사진을 찍고, 서버에 저장하고, DB에 이력을 쌓는 과정이다. AI 분석(라벨 함량표시 변경 판별) 자체는 별도 모듈이며, `TB_LabelMaster`에 이미 `LABEL_STATUS`/`ANALYSIS_STATUS` 컬럼이 예약돼 있어 이후 분석 결과를 이 테이블에 반영하는 구조로 이어질 것으로 보인다(아래 「이후 연동 지점」 참고).

## 🏗 설계 및 구현

### 흐름

```
모바일 앱 (사진 촬영, Base64 인코딩)
  └─ POST /api/Image/SaveLabel  { factoryCode, customerCode?, materialCode?, iud: "IU", imageBase64, imageExtension, inputNo?, inputSeqno?, opmanCode? }
       └─ ImageController.SaveLabel
            └─ ImageService.UploadAsync(request)
                 ├─ SP_APP_LABEL_NEXT_SEQ  → 공장·일자별 당일 순번 채번
                 ├─ 파일명 생성: DO{yyyyMMdd}{순번:D4}, 저장 경로: yy/MM/DO....jpg
                 ├─ FtpService.UploadAsync(경로, stream)   ← 날짜 디렉토리 자동 생성
                 └─ SP_APP_LABEL_IUD (IUD="IU")  → TB_LabelMaster 저장
                      (FACTORY_CODE, SUPPLIER_CODE, ITEM_CODE, INPUT_NO, INPUT_SEQNO,
                       FILE_NAME, FILE_EXTENSION, FILE_PATH, STORAGE_URI, LABEL_ID, OPMAN_CODE)
       └─ 응답: { fileName, imageUrl }
```

### 등록 경로 두 가지

| 경로 | 용도 | 필수 필드 |
|:--|:--|:--|
| **단순 라벨 등록** | 거래처/원료 기준 단독 등록, 입고 번호 없이 | `factoryCode`, `iud`, `imageBase64`, `imageExtension` (`customerCode`/`materialCode`는 선택 — [[01_Projects/04_DataBoucher/01_Tasks/데이터 바우처 이미지 업로드 거래처코드 선택값 전환 09.18]] 참고) |
| **입고 연결 등록/수정/삭제** | 실제 입고(Input) 건에 이미지를 연결 | 위 필드 + `inputNo`, `inputSeqno`. `Input/SaveInput`의 `images` 배열을 통해서도 처리됨 (컨트롤러 XML 주석 참고) |

`Iud` 값에 따라 동작이 갈린다: `"IU"`는 저장/수정(FTP 업로드 + `SP_APP_LABEL_IUD`), `"D"`는 FTP 처리 없이 `SP_APP_LABEL_IUD(IUD="D")`만 호출해 DB에서 제거한다.

### 조회/다운로드

- `POST /api/Image/ImageList` — `LABEL_ID`로 `TB_LabelMaster` 조회 후 FTP에서 스트림을 받아 Base64로 응답 (모바일에서 미리보기용으로 쓰는 흐름으로 보임).
- `GET /api/Image/DownloadImage?customerCode=&materialCode=` — 거래처+원료 기준으로 FTP 파일을 직접 스트리밍 다운로드.

### 이후 연동 지점 (AI 분석 결과 반영, 미구현)

`ImageController`/`ImageService`에 `SP_APP_LABEL_LIST` 기반의 `GetLabelList`/`GetLabelListAsync`가 **주석 처리된 채로 남아 있다.** 이 메서드가 매핑하려던 `LabelListResponse`에는 이미 `LabelStatus`, `AnalysisStatus` 필드가 정의돼 있다 — 즉 AI 분석 결과(함량표시 변경 여부 등)를 조회하는 목적의 엔드포인트가 스케폴딩만 되어 있고 아직 활성화되지 않은 상태다. AI 모듈 연동 작업을 시작할 때 이 주석 블록을 기준점으로 삼으면 된다.

```csharp
// LabelListResponse.cs — 이미 정의돼 있는 분석 상태 필드
public string? LabelStatus { get; set; }
public string? AnalysisStatus { get; set; }
```

> [!note] 관련 문서
> FTP 저장 경로(날짜 디렉토리 자동 생성)는 [[01_Projects/04_DataBoucher/01_Tasks/데이터 바우처 FTP 업로드 디렉토리 자동생성 08.31]]에서 별도로 다뤘다. SECURITY_CODE 기반 커넥션 분기는 [[01_Projects/04_DataBoucher/02_TechDocs/[기술] SECURITY_CODE 기반 멀티테넌시 구조 (TickerMiddleware)]] 참고.
