# 생산·반납 화면과 보고서 기능명세

원본 12개 프로젝트 중 POPREG의 폼 8개, POPRET의 폼 3개와 REPORT의 빌드 대상 보고서 13개를 대조했다. 원본의 상세 이벤트 목록은 운영 소스 저장소의 `.team/REVIEW-PRODUCTION.md`와 `.team/FORM-EVENTS.csv`에 있다. API는 [[30-Spring-API-명세]]에 연결한다.

## 합성 데이터로 재현

Spring을 demo 프로필로 기동할 때 `--shinjin.demo.dataset=tools/demo-dataset/process-003.json`을 지정한다. 상대 경로는 전환 저장소 루트 기준이다. DEMO-A는 스캔 로그인 0000 → 생산 → 폭 절단에서 frmProcess1을 연다. DEMO-A2의 같은 메뉴는 frmProcess3이다. 첫 화면에서 보이는 샘플 열과 창을 열었을 때 보이는 후보는 별도 파일에서 읽는다. 103 장바구니는 스캔창에 2030-01-02/1을 입력해 표를 채울 수 있다. 오른쪽 정보는 거래처명, 수주번호, 수주일, 납기, 비고 순이다.

003 쓰기 검증은 별도 인스턴스에 `tools/demo-dataset/process-003-write.json`을 지정한다. 이때 DEMO-A의 단일 슬롯이 003을 바로 열고 DEMO-A2의 계획 권한은 조회 전용이다. 2030-01-01/1은 GRADE-DEMO, /2는 GRADE-B다. 두 행을 스캔해 둔 상태에서 GRADE-DEMO를 발행하면 재질 오류가 발생한다. 작업지시의 재질·그리드 병합 키는 `demo/basket-plan-columns.json`에서 단말·일자·순번으로 가져온다.

현황 보고서 검증 시 적용 단말의 문서 프린터를 합성 프린터로 지정하고 설정을 다시 읽는다. 한글 글꼴은 기동 인수 `--shinjin.demo.output-font=C:/Windows/Fonts/malgun.ttf`로 지정할 수 있다. 같은 발행 수주의 2030-01-02/1·/2와 다른 발행 수주의 2030-01-01/3을 사용해 결과와 횟수를 대조했다.

## 보고서와 프린터

frmProcess1의 자동 프린트 체크는 SetPrintStatus의 사업장과 선택한 슬롯 공정 코드를 사용한다. 000001의 001·003·004·006은 기본 해제, 000002의 001은 기본 선택이다. 다른 조합은 숨긴다. 완료 시 수주번호 일곱 번째 문자가 S인 행은 제외한다. 합성 단말은 적용된 문서 프린터 설정과 로컬 글꼴로 보고서를 만들고 결과를 한 번 기록한다. 일반 화면의 수동 프린트는 frmProcess1.cs 9617 및 frmProcess3.cs 12860에 실행 코드가 없다. 현황 출력은 [[32-공통팝업-기능명세]]의 ComReportSelect를 따른다.

웹 1280×800 터치 전후와 네 역발행 창의 캡처는 운영 소스 작업트리의 `.team/screen-review/web-process/`에 보관한다. 원본 단독 폼과 웹 공용 헤더의 차이를 고려해 자식 화면 안쪽에서 비교한다. 실제 투입·반납 검색창의 전체 열과 운영 보고서 용지는 추가 대사가 필요하다.

## 원본 DB 계약

`SP_POP_REG_PROCESS1_01_LIST`는 division 및 단말·공정·지시 문맥에 따라 다른 그리드에 결과를 붙인다. `SP_POP_COM_WORKORDERSCAN_01_LIST`는 날짜+순번, `SP_POP_COM_ORDERNOSCAN_01_LIST`는 16자리 수주 스캔에서 복수 계획을 반환할 수 있다. `SP_POP_WORK_HISTORY_LIST`의 조회 인수는 작업일과 작업자다. 운영 설치 버전의 파라미터 타입·빈 값 및 트리거 효과는 추후 읽기 대조가 필요하다. 호출 인수·에러 및 결과 사용처는 원본 저장소 `.rework-process1-plan/sp-contracts.md`에 있다.

## 16자리 수주 바코드 · 데모에서의 확인

원본 ComWorkOrderNoScan.cs 919–1084행은 7번째 문자가 대문자 S인 16자리 바코드에서 수주 12자리와 품목재질 4자리를 분리한다. SCAN2 결과 중 이미 올라온 생산계획일·순번을 거른 뒤 모든 계획을 조회한다. 1차 포장 생략 여부는 스캔창 안에서 한 번만 묻고, frmProcess7.cs의 스캔 종료 처리에서 마지막 행으로 이동한다.

기본 샘플 POP A의 도면가공 스캔창에서 `202611S00001Q01S`를 입력하고 Enter를 누른다. 생략을 승인하면 20261125/1과 /2가 들어오고 두 번째 행을 선택한다. 각 행을 다시 선택해 투입 수량을 입력할 수 있다. 같은 바코드를 다시 읽으면 두 행 모두 중복이라는 안내가 표시된다. 같은 수주의 일부 계획만 이미 표시된 상태라면 남은 계획만 추가한다. POP B에서는 이 수주를 조회할 수 없으며, 별도 샘플 `202611S00004Q01S`가 등록돼 있다. 데이터는 `src/api/src/main/resources/demo/drawing-orders.json`에 있다.

원본 SP의 사업장·작업센터·공정·양품창고 조건에 대응하는 결과를 데모의 인증 사업장·배정 단말·적용 창고·재질로 검증했다. 설치된 프로시저 내부의 조인과 결과 순서는 운영 연결 시 확인해야 한다.


## 일반 포장 006·106과 완료 후 다음 스캔

일반 포장 단말은 공정 슬롯 구성에 따라 바로 진입하거나 메뉴 타일로 연다. 수주 조회는 일정·재질·품목유형·거래처를 좁혀 적용한다. 시작·중단·재시작·선택삭제는 확인을 거치며, 복사행은 LOT 선택부터 다시 한다. 재고 선택창은 바코드와 위치 스캔, 다중 후보, 수량 상한, 행 삭제·선택/취소를 처리한다. 저장은 출고 위치별 실적 행을 보존한다.

원본 POPREG/frmProcess6.cs 6751–6770의 작업완료 메시지·체크된 라벨 출력 후 재조회와 다음 스캔 진입을 따랐다. 합본 Chrome에서 응답 유실 동안 초안 유지, 동일 본문 재시도 후 완료행 제거·다음 지시 입력, 다음 정상 완료 후에도 자동 재스캔을 확인했다. 두 행 2+2와 기본/보조 보관 위치 세 행 2+1+1, 부분수량·위치가 모호한 LOT·과량 거절과 저장 뒤 잔량 0을 대조했다. 실제 Printer3와 운영 재고·ERP 프로시저는 현장 검증 대상이다.

## 도면가공 008 작업 중 및 반납

일반 반납의 추가·선택삭제는 단말에서 편집한다. 작업 완료에서 양품수량과 함께 반납을 반영하며 원본에서 숨겨진 독립 저장 버튼은 표시하지 않는다. 그리드의 수량 셀을 터치하면 키패드가 열리고 취소 시 기존값, 확정 시 입력값이 셀에 보인다. STOP 중단 시 작업을 다시 열어도 재시작 명령이 보이며 완료는 잠긴다. 원본 frmProcess7.cs 4571, 9490 및 10281행. 1280×800 Chrome에서 메뉴·명령·반납 버튼의 위치, 수량 셀 접근과 확정을 확인했다. 008 PLAN 및 일괄삭제, 그룹 반납과 운영 재고 대사는 추적 중이다.

### 도면가공 008 작업목록 다중선택

frmProcess7의 체크된 작업지시를 기준으로 시작·중단·재시작·완료한다. 2건을 체크한 상태에서 시작 확인을 취소하면 재고와 지시가 유지된다. 시작한 뒤 작업장을 다시 열어 각 지시의 숫자 셀에 생산수량을 입력한다. 실제 Chrome과 격리 Spring으로 두 건 모두 수량 1, 완료 기록 각각 1건과 응답 유실 재전송을 확인했다. 008 계획은 별도 작업원장으로 분리했다. 진행중+대기 작업 병합, 그룹 반납·불량, 작업중 자재 편집은 후속이다. 공개 15177에는 이 증분이 포함되지 않았다.
