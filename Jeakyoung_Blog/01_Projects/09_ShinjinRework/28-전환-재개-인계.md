# 전환 재개 인계

기준은 main `8a09e15` / vault `28cb97c`다. 게시 인덱스에는 25 관리계획·배치까지 반영돼 있다. 26과 27은 별도 합성 인수 후보로 보관한다.

## 재개 순서

| 작업 | 현재 상태와 재개 조건 |
| --- | --- |
| 26 008 혼합·일반 포장 | `.rework-008-mixed-packing-staging/release-8a09e15`의 `008-manifest.json`에 있는 7개 파일의 스냅샷 SHA-256을 모두 대조했다. 로컬 전환 저장소의 HEAD는 `8a09e15`이며 같은 7개가 로컬 Git 인덱스에 staged 상태다. 인덱스 raw SHA-256은 3개가 일치하고 4개는 줄바꿈을 LF로 통일하면 일치한다. 7개 모두 줄바꿈 정규화 후 동일하다. 미게시 상태다. |
| 26 검증과 문서 | 최신 `verification/integration.log`의 웹 빌드·전체 lint 경고 0, 혼합 묶음 원자성 및 일반 포장 HTTP, M2 조회·XLSX와 업무 PDF·재출력·권한 HTTP까지 확인했다. 최신 통합 로그에서 Chrome의 혼합·일반 포장, M2·XLSX, 출하 PDF와 RFID 회귀도 통과했다. 최종 독립 판정은 대기 상태다. `.rework-008-mixed-packing-staging`의 26·index·00 후보를 해당 기록 확인 후 확정한다. |
| 27 계획 출력·PDF | `.rework-planning-staging/output-8a09e15`에 별도 `plan-output.patch`, `plan-output.sha256`, HTTP·Chrome 하네스가 있다. 스테이징의 27 계획 출력 초안에 이전 후보의 단일·복수 미리보기와 출력 횟수 검증이 있다. 최신 기준에서 PDF 계약·실행 근거, 25 회귀와 독립 판정을 확인한다. 26의 로컬 staged 파일과 배치를 분리한다. |

## 남은 합성 작업

| 단위 | 범위와 인수 조건 |
| --- | --- |
| 조건부 005/105 | `MainMenu/frmMenu.cs`의 생산 1–5에서 005/105는 `frmProcess5`로 간다. 작업장 타일은 005/105에서 POP 그룹 첫 공정 코드를 넘긴다. `POPSYS/frmSetting.cs`의 그룹 설정은 같은 조건으로 별도 진입한다. 두 코드, 대조군 003/104, 슬롯 코드 유효·빈 값, 그룹 공정 1개·복수와 읽기/편집 권한을 재현한다. 공통 작업지시·세션, 22의 선택 삭제 비교 모드, 19의 설정 버전 계약을 재사용한다. 전체 메뉴·권한 경로는 열린 상태다. 로컬 스테이징의 합성 전환 완료 감사표 |
| 부분 포장·취소 | 26 일반 포장은 등록된 절단 LOT의 전량 완료와 단일 출하 인계를 검증 대상으로 삼는다. 부분 완료의 잔량·실적과 취소·보정 시 재고·감사·출하/M2 연쇄를 별도 설계하고, 실패 무변경과 중복 취소를 검증한다. |
| 포장·008 보류 복구 | `release-8a09e15/008-pending-recovery-followup.md`를 기준으로 별도 작업한다. 단말·작업자·계획/그룹별로 원 키·본문을 보존하고, 성공 응답 유실 → 화면 재진입 → 실제 401 → 동일 작업자 재생을 검증한다. 타 작업자·다른 작업에서 숨김, 늦은 응답 격리, 008 차감·감사 및 일반 포장 출하·M2 행 각 한 번을 확인한다. 서버 작업자 소유권은 별도 계약 검토 대상이다. |

## 운영 인수

LDAP·운영 인증과 권한, ERP 문서·채번·승인 및 재기동 후 영속 복구, 실제 LOT·수불·생산실적·일보 행 대사, 실물 라벨·프린터·스캐너·RFID·카메라와 사진 보존은 각각 운영 환경에서 인수한다. 위 합성 증거는 해당 운영 항목의 완료 근거로 집계하지 않는다. 로컬 스테이징의 합성 전환 완료 감사표와 [[08-남은-전환-작업-인수기준]]을 참조한다.
