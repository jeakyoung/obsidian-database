# 생산 작업지시의 투입 LOT 스캔과 복수 위치

[[04-작업지시와-공정진행]] · [[07-LOT-자재투입과-반납]] · [[32-공통팝업-기능명세]] · [[30-Spring-API-명세]]

## 작업자 경로

생산 메뉴에서 단일 작업지시의 첫 공정을 열고 계획을 선택한다. 투입자재 머리글의 스캐너에서 읽은 문자열을 Enter로 제출한다. 후보가 하나면 부모 투입표에 1을 더하고 다음 스캔을 받는다. 여러 위치에 같은 LOT가 있으면 스캔창이 닫히고 위치별 자재 목록과 적용 목록이 열린다. 왼쪽 추가, 오른쪽 수량 조절, 적용 순으로 선택 행이 부모 투입표에 반영된다. 스캔창을 닫아도 이미 단일 후보로 반영된 행은 유지된다. 위치 선택창에서 닫으면 그 창의 적용 목록은 버린다.

근거는 `MainMenu/frmMenu.cs:495–514`, `POPREG/frmProcess1.Designer.cs:2494–2499`, `POPREG/frmProcess1.cs:2664–2735`, `COMMON/ComMaterialNoScan.cs:207–295`, `COMMON/ComLocationOutPut.cs:620–746,892–1026`이다.

## 합성 Spring 조회

`POST /api/pop/work-orders/{date}/{sequence}/material-scan`은 demo 프로필에서만 등록된다. 경로는 계획일자와 계획순번이며 JSON 본문은 `{"raw":"LOT-A-01"}`이다. 예시 문자열은 저장소 합성 fixture의 키다. 서버가 원문을 그대로 비교한다. 프런트가 LOT 접두어를 만들거나 창고·공장·작업자를 지정하지 않는다.

| HTTP | 의미 |
| --- | --- |
| 200, 배열 | 로그인 공장·단말의 계획, 원 주문 및 항번, 재질코드, 두께·폭, 투입 품목 유형, 현재 허용 창고, 양수 잔량이 일치한 위치들. 일치하지 않으면 빈 배열 |
| 400 | 입력 본문 또는 raw 누락 |
| 401 | 인증 세션 없음 |
| 403 | 첫 공정의 단일 작업지시를 사용할 수 없는 단말 |
| 404 | 인증 단말에서 해당 계획을 찾을 수 없음 |
| 409 | 적용된 투입창고 설정 없음 또는 작업 목록에 완료 행 존재 |

후보는 `factory, warehouse, location, lot, material, name, quality, thickness, width, length, workStatus, available`을 반환한다. 위치·창고 식별자가 합성 표시값도 겸한다. 부모 합산 키는 창고·위치·LOT·품목이며, 단일 후보 재스캔은 원본처럼 부모의 같은 LOT를 먼저 찾는다. 조회 응답은 캐시하지 않는다. 조회, 적용, 닫기는 서버의 수량·작업 이력·revision을 바꾸지 않는다. 선택은 작업지시 화면 메모리에 단말·작업자·계획별로 머문다. 작업 시작 처리에 선택 행을 전달하는 쓰기 계약은 이번 증분의 후속 통합 항목이다.

## 기존 MSSQL 호출과 대응 범위

`COMMON/ComMaterialNoScan.cs:153–202`에서 관찰되는 기존 호출은 `SP_POP_COM_SCANLOTNO_01_LIST`다. 인수는 division, factory_code, plant_code, warehouse_code, material_quality, **thicknes**, spec_x, system_lot_no, work_status 순서다. 창고 인수는 로그인 단말의 투입창고 키를 쉼표로 연결한다. 원본은 결과의 창고·위치 코드/명칭, 품목·재질, 규격, 현재 수량, LOT 등을 사용한다. 원본 조회 예외는 안내창을 연다. 프로시저 본문, 내부 부작용, 현장 라벨 문법과 유효한 현장 값은 이 호출 코드로 확정할 수 없다.

복수 후보는 부모가 이미 얻은 결과표를 그대로 넘긴다. AutoMaterial 분기는 이를 다시 조회하지 않는다. 반납 창고 변경, 위치 자체를 읽는 스캔, 수동 재고 선택, 잔재 추가와 투입보조 설정은 각자의 계약이 있다. 이 인수 범위는 스캔에서 부모 투입표까지다.
