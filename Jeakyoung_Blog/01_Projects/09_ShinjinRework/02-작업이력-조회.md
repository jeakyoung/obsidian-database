# 일자별 작업이력 조회

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 작업자와 날짜 조건으로 작업이력을 조회 |
| **대상 시스템** | React 작업이력 및 Spring 조회 API |
| **최종 확인일** | 2026-11-25 |

## ⚙️ 환경 및 전제

조회는 합성 목록을 사용하고 Vite 프록시를 통해 전달한다.

## 📖 상세 내용

### 기존 동작

`POPREG/frmWorkHistory.cs`는 로그인 작업자와 작업일을 `SP_POP_WORK_HISTORY_LIST`에 전달한다. 작업일은 SQL에 `yyyyMMdd` 문자열로 전달하며 결과를 DevExpress 그리드에 바인딩한다. 화면 진입 시 오늘 날짜로 조회하고, 조회 버튼으로 다시 조회한다.

### 분리와 구현

| 책임 | 구현 |
| --- | --- |
| 조회 폼과 진행 상태 | React `App.tsx`가 조건과 로딩·빈 결과·실패·성공 상태를 관리한다. 조건을 바꾸면 진행 중 요청을 취소하고 이전 결과를 지운다. |
| HTTP 계약 | `workHistoryApi.ts`가 쿼리 문자열을 생성한다. `GET /api/pop/work-history`는 단말, 작업자, ISO 날짜를 받는다. |
| 입력 및 조회 | Spring 컨트롤러가 단말 범위를 검증하고 합성 제공자가 단말·작업자·기준일로 필터링한다. 유효한 조건에 결과가 없으면 HTTP 200과 빈 배열을 반환한다. |
| 결과 필드 | 수주번호, 품목, 공정, 계획·실적수량, 입출고 구분, 창고, 시작·종료 시간을 표시한다. |

현재 화면은 합성 데이터가 있는 기준일을 기본값으로 표시하고 사용자가 조회 버튼을 누르면 요청한다. 운영 이관 단계에서 화면 진입 시 오늘 날짜 자동 조회, 전체 그리드 컬럼과 표시 규칙, SQL 날짜 바인딩을 대조한다.

### 검증과 후속

Maven 빌드, React lint와 빌드를 확인했다. 로컬 브라우저와 Vite 프록시를 통해 정상 조회, 단말·작업자 변경, 빈 날짜, 서버 오류 표시를 확인했다. 잘못된 단말·작업자 조합과 유효하지 않은 날짜는 HTTP 400으로 확인했다. 실제 DB 호출과 결과 일치 검증은 수행하지 않았다.

## ⚠️ 주의사항

현재 표시 필드는 기존 화면의 일부다. 실제 SQL 반환 형식과 결과 일치는 후속 검증 범위다.
