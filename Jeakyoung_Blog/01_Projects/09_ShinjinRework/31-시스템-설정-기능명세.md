# 시스템 화면 대조

## 로그인 전 프린터와 정보 확인

프린트 설정은 사번 로그인과 사업장 선택보다 먼저 열 수 있다. 작업지시서·거래명세서·라벨 프린터를 각각 터치한 뒤 아래 장치 행을 누른다. 하나의 장치를 여러 역할에 지정할 수 있다. 역할을 먼저 고르지 않거나 세 역할 중 하나가 비어 있으면 원본 안내창이 열린다. 세 역할을 선택한 뒤 저장 확인에서 예를 눌러야 적용된다. 아니오는 선택창으로 돌아가고 취소·닫기는 편집값을 버린다. 원본 근거는 POPSYS/frmPrinter.cs 39–70, 85–179, 200–273행과 frmPrinter.Designer.cs의 각 역할 라벨이다. 데모 장치 목록은 단말별 합성 장치이며 브라우저의 프린터나 실제 스풀러를 열지 않는다.

원본 정보 확인은 Info/Ftp_Info.ini와 Info/Db_Info.ini의 FTP 주소·포트·이미지 경로·파일 경로·버전, DB 주소·포트·DB명을 라벨로 표시하고 확인 또는 닫기만 제공했다. 사용자 지시로 같은 FTP·DB·버전 표 안에서 여덟 값을 수정하고 저장·취소할 수 있게 했다. 두 주소 행은 주소와 포트를 나란히 표시한다. 버전은 FTP 업데이트 프로필의 VERSION이며 실행 중인 웹·Spring의 배포 버전과 독립적이다. 주소가 비어 있으면 NONE과 연결 정보 안내를 표시한다. 원본 근거는 POPSYS/frmInformation.cs 33–115행과 frmInformation.Designer.cs 109·150–151·217–417행이다.

두 설정은 브라우저·단말별 로컬 파일에 저장하고, 사원 로그인 때 그 단말의 세 프린터를 세션에 적용한다. 주소와 경로는 편집 가능한 로컬 프로필이다. 운영 INI 원문·DB 연결문자열·FTP/DB 계정과 암호는 읽거나 표시하지 않는다. 프로필을 저장해도 주소에 접속하거나 업데이트를 내려받지 않는다. 업무 화면의 PDF·문서·라벨에는 세션에 고정한 역할값을 전달한다. 계약 및 독립 인수 도구는 [[30-Spring-API-명세#로그인 전 프린터 및 연결 프로필]]을 참조한다.

독립 Chrome에서 1024×768·1280×800·1366×768·1920×1080 화면을 확인했다. 작은 화면의 장치 목록은 원본처럼 스크롤한다. 서로 다른 브라우저와 단말, 별도 JVM 재시작, 미설정 상태의 로그인 차단 해소, 저장 전후 세션을 비교했다. 작업지시서 PDF는 Printer1로 설정한 A-DOC2를 참조했다. 타 사업장 합성 포장 완료 시 Printer3의 B-SHIP으로 라벨 접수 결과를 반환했고, 그 포장을 출하 확정한 거래명세서 미리보기는 Printer2의 B-DOC2를 반환했다. 실장치 출력은 실행하지 않았다. 비교 이미지는 원본 저장소의 `.team/screen-review/ui-matrix/expanded/prelogin-*`에 있다.

15179의 15:13 공개 합본에서 새 Chrome 프로필로 여덟 입력 필드와 세 장치 재개방·로그인 반영을 반복 확인했다. 인쇄 메뉴에서 작업지시서를 열고 작업반 전체로 조회한 12건 중 한 건을 선택해 Multiple 보고서를 만들었다. 설정한 문서 장치를 반환했고, PDF 열기를 눌러 1쪽 PDF가 새 탭에 열렸다. 다섯 업무분류의 27개 타일에 샘플·진단 화면 항목은 없었다. 담당자 헤더에는 실제 로그인한 합성 작업자의 표시명이 표시된다. 근거는 `.team/menu-screen/15179-current/print-basket-public/verified.json`이다.

## 로그인 전 공장·작업장, POP ID, 설비 배정

로그인 화면 설정에서 작업자 로그인 없이 세 양식을 연다. frmSetting.cs 377·555·824에서 호출되는 frmPlant, frmMachine, frmPopId의 상단 선택란·그리드·확인창을 로그인 후 화면과 공유한다. POP ID와 설비는 모두 사업장·작업장과 공정이 먼저 설정돼야 하며, 두 항목 사이에는 선행 순서가 없다.

서버 측 읽기참조본은 바인딩된 회사·사업장·작업장 한 곳에 한정한다. 2026-11-26 14:59 KST 읽기 전용 추출에서는 설비 마스터 193개, POP ID 후보 95개, 원본 단말 설비설정 1개였다. SP_POP_SYS_MACHINE_01_LIST SELECT 정의는 회사와 COMPANY_CODE=선택 사업장·EQUIP_KIND=000002, 미삭제를 사용하고 설비 시스템 코드 순으로 정렬한다. SP_POP_SYS_POPID_01_LIST SELECT는 회사와 PLANT_CODE=선택 사업장, EQUIP_KIND=000005·KIND2=000010·KIND3=000001, 미삭제를 사용한다. 목록은 설비코드, 시스템코드 순이다. 원본의 사업장 목록은 SP_POP_SYS_PLANT_01_LIST SELECT1의 회사 000001·분류 132, 작업장은 SELECT2의 같은 회사와 선택 사업장이다. 일반 합성 모드에서 두 사업장과 여러 작업장 간 전환을 검증했다. 지정한 실참조본의 범위를 벗어난 운영 사업장 전체를 제공하지 않는다.

마스터의 표시명·설명·코드 순서와 선택은 private 참조본으로 확인했다. 메인보드 원시 시리얼은 저장·응답하지 않고 현재 단말 또는 다른 단말의 소유 여부를 표시한다. 실제 운영 설비/POP ID 배정 UPDATE는 실행하지 않는다. 원본/브라우저 캡처와 정상·취소·재시작 검증은 원본 작업트리 `.team/screen-review/web-parity/로그인전-사업장-POP-설비`에 있다.

## 최초 실행 시 업데이트와 정보 설정의 버전

원본 frmLogin은 ProductVersion과 FTP 설정 VERSION을 문자열로 비교한다. 값이 다르거나 비어 있으면 로그인보다 먼저 frmUpdate를 연다. 목록·파일 크기 확인, 내려받기, 누적 진행률 표시 후 Update.exe 실행과 로그인 종료를 요청한다. 파일 단위 실패를 다음 파일로 넘기는 예외 분기도 있다. 운영 연결을 대체한 과거 원본 격리 시험 11개 분기로 이 동작을 확인했다.

공개 웹과 동일한 정적 파일·JAR에서 정보 확인의 FTP 프로필 버전을 다른 값으로 저장한 뒤 새로고침했다. 저장한 정보가 다시 열렸고 정상 로그인으로 이어졌다. 현재 웹 릴리스 식별은 이 편집값과 별개다. 공개 15179 index-BTtHD_XE.js의 HTML과 JS는 Last-Modified를 제공하고 명시적 Cache-Control 응답은 없었다. 기존 화면을 사용 중인 단말에서 새 배포를 언제 적용할지 사용자 결정을 기다린다. 실제 릴리스 강제 갱신은 구현 전이다.
