# POP 로그인과 작업자 세션

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 기존 수동·스캔 로그인 진입 경로와 로그인 작업자의 조회 범위 재현 |
| **대상 시스템** | React 및 Spring Boot demo 프로필 |
| **최종 확인일** | 2026-11-25 |

## ⚙️ 환경 및 전제

demo 프로필과 합성 단말·작업자 목록을 사용한다. 운영·개발 DB에는 연결하지 않는다. 화면에 표시되는 샘플 암호와 스캔 코드는 데모용이다.

## 📖 상세 내용

### 기존 패턴

WinForms의 수동 로그인은 `frmLogin`에서 `ComLogin.Login("PC", ...)`을 호출하고, `frmScanLogin`은 `ComLogin.Login("SCANNER", ...)` 경로로 진입한다. 작업이력 조회는 로그인 작업자와 기준일을 사용한다.

### 분리와 구현

| 책임 | 구현 |
| --- | --- |
| React 입력 | `DemoLogin.tsx`에서 POP 단말 선택, ID·샘플 암호 또는 스캔 문자열 입력, Enter 제출과 오류 표시를 담당한다. |
| Spring 세션 | `DemoSessionController`가 합성 작업자와 단말 조합을 검증하고 HttpOnly 세션 쿠키를 사용한다. 로그인 성공 시 기존 세션을 교체하고 로그아웃 시 세션을 무효화한다. |
| 작업이력 조회 | 브라우저는 작업일을 보낸다. 서버는 세션의 단말과 작업자를 조회 조건으로 사용한다. 로그인 시 임의의 단말·작업자 조합을 거절하고, 조회에 추가 사용자 식별자를 보내도 결과 범위는 세션으로 결정된다. |
| 세션 복원·종료 | 페이지를 새로고침하면 서버 세션에서 작업자 표시를 복원한다. 로그아웃 후 또는 조회 응답이 401이면 로그인 화면으로 돌아간다. |

### 검증

Maven과 React lint·빌드가 통과했다. Chrome에서 수동·스캔 로그인, 잘못된 암호와 다른 단말의 스캔 코드 거절, 쿠키 속성, 새로고침, 로그아웃, 무효 세션 처리 및 작업자별 결과 범위를 확인했다.

## ⚠️ 주의사항

실제 로그인 프로시저와 운영 작업장·메뉴 권한 검증은 후속 범위다. 스캔 입력은 키보드로 입력 가능한 합성 형식을 검증했으며 실물 스캐너는 확인하지 않았다.
