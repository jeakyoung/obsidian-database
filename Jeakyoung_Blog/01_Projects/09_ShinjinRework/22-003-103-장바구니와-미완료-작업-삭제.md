# 003/103 장바구니와 미완료 작업 삭제

## 📋 개요

003/103 생산의 자재 저장과 미완료 작업 삭제를 다룬다. 게시 준비 기준은 main `43525f5`, vault `0b3456a`다. `43525f5` 공용 App과 독립 P2 검증을 통과했다.

## 📖 상세 내용

- WinForms `frmProcess3`에서 003/103은 같은 폼으로 진입한다. 장바구니에 스캔한 계획, 선택 행과 투입자재가 필요하다. 시작한 작업과 길이 0인 반납 행은 거절한다. `frmProcess1/3`은 조회 목록 전체 삭제, `frmProcess5`는 체크 행 삭제를 사용한다. 완료 행이 섞인 목록은 차단하며 일반 작업 시작 취소와 별도 동작이다.
- 합성 데모는 원 계획·주문 참조를 보존하고 준비 → 장바구니 저장 → 시작을 구분한다. 저장 시 합성 LOT 잔량을 예약하고 시작 시 중복 차감하지 않는다. 공유 그룹에 작업이 남으면 예약을 유지하고 마지막 작업을 삭제하면 준비 상태와 잔량을 복원한다. 이 잔량은 기존 LOT·입고·재고이동 원장과 분리되어 있다.
- Spring demo는 세션에서 작업자·단말을 구하고 003/103을 분리한다. 오래된 버전, 다른 작업자와 완료 혼재는 상태를 바꾸지 않는다. 동일 요청 재생은 기존 응답을 반환한다. React App은 명령을 보내기 전에 단말·작업자별 탭 저장소에 키와 본문을 보존한다. 같은 작업자는 응답 유실이나 401 뒤 화면에 다시 들어와 동일 요청을 재생할 수 있다. 다른 작업자의 재생은 거절되며, 화면을 떠난 요청의 응답은 화면·저장소·세션을 바꾸지 않는다.

## ✅ 검증 및 인수

- `basket-handoff.md`의 `aef2479` 독립 Java·HTTP·Chrome 통과를 확인했다. 전체/선택 삭제와 공유 그룹 정리는 Java, 실제 Chrome에서는 독립 화면의 저장 → 시작 → 삭제 및 완료 행 보존·잔량 복원을 확인했다.
- `integration-44c751a/basket-integration-handoff.md`에서 실제 App Chrome 및 Vite 빌드 통과를 확인했다. 스캔·저장·재스캔 시 공유 그룹 복원·시작·삭제, 완료 혼재 거절, 응답 유실 뒤 401과 동일 작업자 복귀, 다른 작업자의 보류 사본 숨김과 403, 화면 이탈 후 늦은 성공·401 차단을 검증했다. 최종생산조회·생산계획·재고이동·단말 설정 메뉴 전환도 통과했다.
- `integration-43525f5/basket-integration-handoff.md`와 `basket-review.md`에서 최종 통합과 독립 P2 통과를 확인했다. 독립 실행에 사용한 App과 WorkBasket의 SHA-256 앞 16자리는 각각 `810E1EEC30C7C673`, `EBA84D261E0A982E`로 인계 해시와 일치했다. 현장 단말·스캐너, 운영 실적·LOT 차감·반납 원장 및 영속 복구는 별도 인수다.

### 최신 독립 검증

- 실제 Chrome에서 서버 성공 뒤 응답 유실을 재현했다. 재진입과 실제 401 뒤 같은 단말·작업자의 원 키·본문 재생은 200이었으며 예약량·revision·이력은 그대로였다. 다른 작업자에게 보류 요청이 표시되지 않았고 서버 재생은 403이었다.
- 003과 103의 목록 전체 삭제에서 완료 혼재는 409 및 원장 무변경이었다. 완료 행을 제외하면 한 행만 체크해도 표시된 미완료 그룹 전체를 초기화했다. 비교용 선택 삭제에서는 나머지 멤버와 공용 예약을 보존했고 마지막 멤버 삭제에서만 잔량을 복원했다.
- Java·Spring HTTP·Vite·Chrome이 정상 종료됐다. 최신 Chrome에서 M1 출고·반납과 M2 최종생산조회 메뉴를 확인했다. javac의 JAR 닫기 접근 진단 뒤 생성 클래스로 검증을 마쳤다.
