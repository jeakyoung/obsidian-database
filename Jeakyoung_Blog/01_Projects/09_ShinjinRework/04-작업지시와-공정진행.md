# 작업지시 목록과 공정 진행 현황

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 단말별 생산계획과 선택한 계획의 공정 진행 현황 조회 |
| **대상 시스템** | React 및 Spring Boot demo 프로필 |
| **최종 확인일** | 2026-11-25 |

## ⚙️ 환경 및 전제

합성 단말 두 개와 생산계획 세 건을 메모리에서 제공한다. 업무 DB 접속과 상태 변경은 없다.

## 📖 상세 내용

### 기존 패턴

WinForms `POPREG/frmProcess1.cs`의 `FnSearchGrid3`은 `SP_POP_REG_PROCESS1_01_LIST`의 `SELECT_GV3`에 공장·작업장·공정·설비·작업자·POP ID를 넘긴다. 목록 행 선택 후 `SELECT_GV4`에 행의 공장·작업장과 생산계획일·순번을 넘겨 공정 진행 현황을 조회한다. 도면가공 `008`의 목록은 별도 상태 조건이 있다.

### 분리와 구현

| 책임 | 구현 |
| --- | --- |
| 목록 조회 | Spring `GET /api/pop/work-orders`가 세션의 단말 범위에서 합성 계획을 조회한다. 선택적 진행 상태는 대기·진행 중·완료를 받는다. |
| 상세 조회 | `GET /api/pop/work-orders/{planDate}/{planSequence}`가 생산계획일과 양의 계획순번을 받고, 같은 단말의 계획과 공정 상태를 반환한다. 다른 단말의 키와 미등록 키는 HTTP 404로 응답한다. |
| 화면 상태 | `WorkOrders.tsx`는 목록·상세 상태를 분리하고 조건 변경 시 상세를 지운다. 요청이 바뀌면 이전 요청을 취소한다. 공통 조회 코드에서 401을 로그인 화면으로 연결한다. |
| 데이터 제공자 | `WorkOrderFixtures`가 새로 작성한 합성 목록을 제공한다. 나중에 운영 조회를 연결할 때 업무 API를 유지하면서 실제 SQL 입력과 결과를 어댑터에서 매핑할 수 있다. |

### 검증

Maven 빌드와 React lint·빌드가 통과했다. Chrome에서 목록·공정 상세, 상태 필터, 빈 결과, 오류 후 재조회, 기존 작업이력 화면 전환을 확인했다. Vite 프록시를 거친 HTTP 호출에서 로그인 전 401, 다른 단말 상세 404, 잘못된 날짜·순번·상태 400을 확인했다.

## ⚠️ 주의사항

운영에 연결할 때 공장·작업장 코드, 공정·설비·작업자 범위를 서버에서 확인해야 한다. 운영 SQL의 전체 컬럼, 도면가공 008 분기와 작업 시작·완료·취소는 후속 범위다.
