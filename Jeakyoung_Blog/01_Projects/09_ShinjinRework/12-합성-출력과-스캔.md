# 합성 스캔·RFID와 출력 인수 범위

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 작업지시·LOT 스캔과 RFID·파렛트 합성 통합 결과 기록 |
| **대상 시스템** | React·Spring Boot demo |
| **확인 상태** | D1·D2 통합 실행 확인. 독립 리뷰 P1 통과, P2 독립 Chrome 재검토 통과. D3는 별도 검토 중 |

## ⚙️ 환경 및 전제

기준 소스는 `fdfad1d`, 상위 문서는 `b066c7f`다. Chrome은 루프백 demo 서버와 합성 데이터로 실행했다. RFID 상태와 영수증은 서버 프로세스 메모리에 보관한다.

## 📖 상세 내용

### D1 스캔

초점이 있는 입력에서 Enter로 작업지시를 조회하거나 현재 작업의 LOT를 선택한다. 복수 후보면 기존 화면에서 위치를 선택한다. 스캔 전후 작업지시 상세는 동일했다. 투입은 별도 사용자 조작으로 기존 서버에 LOT·수량·창고·위치·revision을 전달한다.

Chrome에서 투입 성공 후 기존 revision으로 같은 요청과 수량·위치가 달라진 요청을 보내 각각 409와 재고·이력 보존을 확인했다. 스캔 어댑터에는 업무 쓰기가 없으며 재고·이력·revision의 반영은 기존 서버 경계에 있다.

### D2 RFID·파렛트

태그 캡처는 입력값만 전달한다. 서버는 매 명령에서 세션의 공장·단말·작업자와 최신 등록·매칭·이동 상태를 확인한다. 등록 소유자만 매칭하고 매칭 소유자만 적재·입출고한다. 공장 범위 이벤트 키의 영수증은 정규화한 명령과 단말·작업자를 보존한다. 같은 본문은 재생하고, 바뀐 본문은 충돌 처리한다. 상태·이력·영수증을 하나의 스냅샷으로 반영한다.

| 실행 증거 | 확인 범위 |
| --- | --- |
| 실제 Chrome 158 | 태그 스캔 → 등록 → 매칭 → 적재 → 수동 입고·재생 → 출고·이력. 미인증 401, 다른 작업자의 기존 키 재생 및 새 키 이동 403, 원래 작업자 재인증 후 이력 조회. |
| Java 17 하네스 | 발행 직전 예외의 무변경, 동시 동일 키 성공 한 건과 재생 한 건, 변경 본문 충돌, 다른 단말의 기존 키 및 새 이동 거절. |
| 빌드와 회귀 | React 빌드·lint, 작업이력·LOT 상세·단일 008 접근, 공장이송의 정상·부분 커밋·역순 취소와 401 후 재시도. |

### D2 P2 응답 유실 복구

등록·매칭·적재·입출고는 송신 전 같은 탭의 단말·작업자별 저장소에 합성 본문과 키를 보관한다. 응답 유실과 401 이후 동일 단말·작업자만 사본을 복원한다. 성공·충돌 같은 확정 응답과 명시 종료는 사본을 정리한다. 명시 종료는 이미 반영된 서버 명령을 취소하지 않는다.

Chrome에서 등록·매칭·적재 성공 응답을 각각 유실시킨 후 같은 키와 본문으로 재생했다. 타 작업자 재실행은 403, 성공 키의 다른 본문은 409였다. 충돌·종료 후 사본 정리와 적재·이력 무중복을 확인했다. 독립 Chrome 재검토에서도 세 명령의 동일 키 복구, 재시도 중 401 이후 동일 단말·작업자 복원, 다른 작업자의 사본 격리를 확인했다.

### D3 출력과 미검증 범위

D3 합성 PDF·미리보기와 양식별 수용 판정은 별도 검토 중이다. D1·D2의 독립 통합 리뷰에서 P1을 통과했다. P2도 합성 루프백 Chrome에서 통과했다. 응답 유실 복구 범위는 같은 브라우저 탭의 동일 단말·작업자다.

실물 스캐너 설정·연속 판독, RFID 리더와 다중 태그, 물리 프린터·라벨과 스풀러, 운영 원장과 재기동 이후의 영속 복구는 미검증이다. 008 묶음 전체 동작 및 출하·출력 연결은 이번 D1·D2 통합 회귀에 포함되지 않았다.
