# 작업 시작과 완료 상태 전이

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 선택한 생산계획의 시작·완료를 업무 명령으로 분리 |
| **대상 시스템** | React 작업지시, Spring Boot demo 프로필 |
| **최종 확인일** | 2026-11-25 |

## ⚙️ 환경 및 전제

서버 메모리의 합성 생산계획을 변경한다. 서버가 재시작되면 초기 상태로 복원된다. 작업지시 조회와 명령 모두 단말 세션을 사용한다.

## 📖 상세 내용

### 기존 패턴

WinForms `POPREG/frmProcess1.cs`의 `WorkStart`는 실적·투입자재·작업시간 행을 여러 SQL 호출로 처리하고 한 트랜잭션으로 커밋한다. `WorkEnd`는 선택 작업·투입자재·양품창고 등 선행 조건을 검사하고 실적 및 연동 업무를 처리한다.

### 분리와 구현

- React는 상세의 최신 상태에 따라 시작 또는 완료를 표시한다. 완료의 입력은 실적수량이며 API 처리가 끝날 때까지 재제출을 막는다. 성공하면 상세와 목록을 갱신하고, HTTP 409를 받으면 최신 상태를 다시 조회한다.
- Spring의 `POST /api/pop/work-orders/{planDate}/{planSequence}/actions`는 세션 단말과 작업자를 읽고 합성 계획에 `START` 또는 `COMPLETE`를 적용한다. 단말 범위를 벗어나면 HTTP 404, 상태가 이미 바뀌었거나 순서가 맞지 않으면 409, 실적 입력이 유효하지 않으면 400을 반환한다.
- 상태 검사와 갱신은 단일 메모리 저장소에서 원자적으로 수행한다. 대기 → 진행 중 → 완료만 허용하고 완료 시 실적수량과 작업자 ID를 기록한다. 실적은 계획수량 이내의 양수, 소수 셋째 자리까지로 제한한다. 이 수량 제한은 합성 데모의 기준이다.

### 검증

Maven과 React lint·빌드가 통과했다. Chrome에서 시작·완료와 실적 표시, 최신 상태 재조회, 이전 목록·상세·작업이력 회귀를 확인했다. HTTP에서 미인증, 다른 단말, 잘못된 수량, 순서 위반과 완료 중복을 검증했다. 시작을 동시에 두 번 요청했을 때 하나는 200, 하나는 409를 반환했다.

## ⚠️ 주의사항

작업지시 상태와 실적수량만 모의한다. 투입자재·작업시간·양품창고·재고 트리거·ERP 전표·작업이력 연동, 중지·재개·취소와 도면가공 008 분기는 후속 작업이다. 메모리 동시성 확인은 실제 SQL 트랜잭션 검증과 범위가 다르다.
