# 단말 설정과 세션 적용

## 📋 개요

M3 기준정보·단말 설정 노트 19. 코드 기준은 `5c31b30`, vault는 `543a88a`다. 최신 App HTTP·Chrome과 이전 독립 HTTP의 범위를 구분해 기록한다.

## 📖 상세 내용

### 설정과 적용

WinForms의 로그인 설정 하위 화면은 공정, 창고 및 장치 역할을 단말 설정으로 다룬다. demo는 서버 세션의 공장·단말과 합성 후보를 사용한다. 같은 단말의 조회 전용 작업자는 읽기와 세션 새로고침을 할 수 있고, 설정 저장은 편집 권한이 필요하다. 다른 단말의 조회나 변경은 거절한다.

로그인 성공 시 현재 설정 버전을 세션에 고정한다. 새 저장값은 이미 로그인한 세션에 자동 적용되지 않는다. 일반 조회·브라우저 갱신과 명시적인 세션 새로고침을 구분한다. 새로고침은 요청 세션만 바꾸고 재로그인은 최신 저장 버전을 고정한다.

LOT 조회와 투입은 해당 세션의 창고 정책을 따르며 반납 위치는 서버가 정한다. 정책 적용 후 이전 창고로 투입하면 서버가 거절한다.

### 검증

| 근거 | 확인 범위 |
| --- | --- |
| 최신 Spring HTTP (`5c31b30`) | 첫 설정 조회 전 로그인 버전 고정, 저장 경쟁 한 건 성공, 명시 갱신의 세션 격리, 로그아웃 후 401과 재로그인 적용, 이전 창고 거절 후 상태·재고·이력 보존, 새 반납 위치의 실제 합성 재고 증가. |
| 최신 App Chrome 158 (`5c31b30`) | 본인 설정 저장으로 저장 버전만 증가하고 명시 갱신으로 적용 버전이 증가했다. 조회 전용 작업자는 저장 버튼을 사용할 수 없고 직접 요청도 403이며 읽기와 갱신은 가능했다. |
| 기존 화면과 권한 비교 | 동일 단말 조회 전용 작업자도 기존 출하 PDF와 발주 상세를 조회했다. 타 단말은 본인 아닌 설정 및 출하 PDF에 403, 발주 상세에 404를 받았다. 미인증 상태의 세 조회는 401이었다. 게시된 재고이동 메뉴와 인증 조회는 유지됐다. |
| 독립 HTTP (`f2d9f0d`) | 로그인 당시 버전 유지, 요청 세션만 갱신, 이전 창고·오래된 작업 revision의 무변경 거절, 새 위치의 합성 반납을 확인했다. 독립 실행에 사용한 통합 사본과 최신 M3·세션·LOT 소스 5개의 SHA-256을 대조했다. 새 App의 Chrome 판정은 위 최신 실행 결과다. |

## ⚠️ 주의사항

합성 설정은 서버 메모리에서 관리한다. 실물 장치, 운영 설정 이관, 출력 역할의 실제 장치 적용과 영속 복구는 후속이다. 기존 재고이동 화면의 ref cleanup lint 경고 1건을 유지한 상태에서 웹 프로덕션 빌드와 검증을 완료했다.

## 읽기 전용 MES 설정 참조본

`GET /api/pop/admin/terminal-settings/{terminalId}`의 `catalog.processes`는 원본 반환 순서를 유지한다. `processNames`와 `processIndices`는 공정코드별 이름·표시순번이다. `materials[]`에는 code, name, idx가 있고 `processSelection.codes`는 단말이 기록한 1~6번 슬롯 중 지정값만 담는다. 같은 경로의 `GET /equipment`은 현재 사업장·작업장과 설비 설정 유무를 제공한다.

`POST /warehouse/entry`에서 기존 서버의 설정 암호 확인을 통과하면 rows에 idx, plantName, code, name을 반환한다. saved.roles는 5가지 용도별 코드 배열이며 배열 순서가 우선순위다. 일반 설정 응답에서는 참조본의 전체 창고 후보를 생략한다. 타 단말을 지정한 요청과 틀린 창고 암호는 403이었다. 비인증 상태의 관리 설정 요청은 401이었다. 별도 단말의 기존 합성 데이터도 확인했다.

운영 원본의 설정 조회는 `tools/settings-reference/Export-TerminalReference.ps1 -LegacyOutputDirectory <원본의 OUTPUT 경로>`로 재현한다. 조회 결과는 서버 사용자 전용 `%LOCALAPPDATA%/ShinjinPOP/local-reference/terminal-settings.json`에 저장한다. Spring demo 인스턴스에 `shinjin.settings-reference.file` (절대경로), `shinjin.settings-reference.terminal` (검증 단말), `shinjin.settings-reference.scope` (원본 회사/사업장/작업장)를 명시한다. 일반 실행은 기존 합성 데이터를 사용한다. 창고 본인확인에는 검증용 warehouse-test 프로필과 서버 전용 환경변수 `POP_WAREHOUSE_TEST_PASSWORD`를 사용한다. 샘플 계정과 구분한다.

`tools/settings-reference/verify_reference.py --base <로컬 프리뷰 URL>`는 신규 격리 인스턴스의 DEMO-A 기본 설정에서 실행한다. Chrome의 관리→단말 설정을 터치해 행과 체크를 대조하고 DEMO-B의 합성 범위를 확인한다. 이름과 코드의 실제 목록, 비밀번호, DB 주소는 검증 결과에 출력하지 않는다.

격리한 003 검증 인스턴스에서 `--exercise-process`를 지정하면 현재 원본의 4·5·6번 슬롯 상태에서 빈 1번에 후보를 설정해 본다. 관리→단말 설정→공정 설정→1번→공정 행→저장→예 순으로 눌렀다. 같은 로그인에서 메뉴 복귀→생산→폭 절단이 활성화되고 003 장바구니가 열렸다. 로그아웃 후 다시 로그인한 뒤에도 1·4·5·6번과 1번에 저장한 공정코드를 확인했다. 이 검증은 로그인 전에 별도 설정을 변경한 적 없는 브라우저에서 진행했다.

같은 브라우저에 이미 로그인 전 선택값이 있는 경우도 003 작업장에서 별도 검증했다. 로그인 전 2번을 저장하고 관리자 로그인 뒤 공정 설정에 들어가 기존 2번이 표시되는지 확인했다. 관리자가 1번을 추가 저장하고 같은 세션·브라우저별 저장소·다음 로그인 모두 1·2·4·5·6과 두 지정 코드가 유지됐다. 이때 그룹 공정은 비활성이다.

창고의 사업장명은 원본 `frmLocation.cs:312`의 공통 조회 plant/132가 표시하는 약칭이다. 원본 배포 정의에서 사업장명 조회의 회사 조건은 고정 회사코드다. 별도의 읽기 전용 SELECT로 해당 사업장 표시명이 1건이며 이 단말의 INI 명칭과도 일치함을 확인했다.
