# 신진 POP 전환 범위와 작업 순서

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 이관 범위와 구현 상태 추적 |

## ⚙️ 환경 및 전제

초기 구현은 로컬 웹과 합성 데이터로 확인한다.

## 📖 상세 내용

### 전환 범위와 작업 순서

| 작업 단위 | 기존 흐름 | React·Spring에서 분리할 경계 | 상태 |
| --- | --- | --- | --- |
| 단말·작업자 | 로그인 상태, 단말 설정, 작업장별 진입 | React 선택 상태, Spring 컨텍스트 응답, 향후 서버 세션과 단말 등록 | 합성 컨텍스트 구현 |
| 작업이력 | 작업자·기준일 전달, 결과 그리드 바인딩 | React 조회/표, Spring 입력 검증과 조회, 추후 데이터 어댑터 | 합성 조회 구현 |
| 로그인·권한 | 일반·스캔 로그인, 사용자 및 메뉴 활성화 | 인증, 단말과 작업장 인가, 메뉴 권한 | 합성 로그인·세션 구현 |
| 생산·포장 | 조회, 상태 전이, 실적과 재고 반영 | 작업 단위 명령, 상태·동시성·트랜잭션, 화면 진행 상태 | 후속 |
| 공장이송·출하 | POP와 ERP 전표 및 순차 커밋 | 요청·출고·입고·취소, 전표 키 대조, 실패 후 재처리 | 후속 |
| 인쇄·현장 장비 | DevExpress 양식, 스캔·RFID·장치 | 서버 PDF와 React 미리보기, 단말 인쇄와 실물 검증 | 후속 |

현재 구현의 데이터 제공자는 불변 합성 목록이다. 운영·더존 접속정보, 원본 데이터, 공급사 SQL 본문은 코드와 노트에 넣지 않는다. 업무 조회가 추가될 때마다 원본 입력·결과, 구현 경계, 오류·빈 결과, 미검증 항목을 해당 작업 노트에 남긴다.

## ⚠️ 주의사항

운영 연동은 테스트 환경과 업무 계약이 확인된 작업부터 적용한다.
