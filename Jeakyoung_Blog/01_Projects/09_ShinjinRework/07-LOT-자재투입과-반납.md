# LOT 자재 투입과 반납

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 작업지시에서 LOT 자재를 조회·투입하고 남은 수량을 반납한다. |
| **대상 시스템** | React 작업지시, Spring Boot demo 프로필 |
| **최종 확인일** | 2026-11-25 (로컬 합성 검증) |

## ⚙️ 환경 및 전제

로그인한 작업자와 단말 컨텍스트에서 선택한 합성 작업지시를 사용한다. LOT, 품목, 창고·로케이션, 재고와 투입·반납 내역은 합성 데이터로 구성한다. 검증 범위는 스테이징의 수정 구현과 Spring demo 프로필이다.

## 📖 상세 내용

### 기존 패턴

WinForms `COMMON/ComMaterialNoScan.cs`는 스캔한 LOT의 재고 후보를 조회한다. 조회 결과가 없으면 재스캔을 요청한다. 후보가 하나면 투입 목록에 수량 1을 추가하거나 기존 목록 수량을 1 늘리며, 기존 행의 증가분이 현재 재고를 초과하면 거부한다. 후보가 여러 로케이션에 걸쳐 있으면 선택 팝업으로 넘긴다.

`POPREG/frmProcess2.cs`는 투입 처리와 투입 삭제를 별도 버튼으로 다룬다. 일반 반납 등록은 작업 시작 후 완료 전에 가능하며 작업 목록, 재질, 반납 자재 정보와 설정된 반납창고를 확인한다. 반납 목록의 행 삭제에도 상태 확인과 사용자 확인이 있다. 완료 작업의 강제 반납은 별도 진입점과 확인 절차를 사용한다.

레거시 공통 생산 화면은 작업을 고른 뒤 생산그룹으로 투입과 반납을 구분해 읽는다. 투입 후보에는 설정 창고·위치·LOT와 재질·치수 조건이 관여한다. 반납 후보도 설정 창고와 품목·치수 조건을 사용하며, 완료 처리에서 반납 위치·수량·치수를 검증하는 분기가 있다. 현장 예외 및 반납 LOT의 재사용·채번은 별도 업무 계약이다.

### 분리와 구현

| 경계 | 수정 코드에서 확인한 동작 |
| --- | --- |
| React | 작업지시 상세에서 LOT와 투입 위치를 선택하고 수량을 입력한다. 설정된 반납 위치와 투입·반납 이력을 표시한다. |
| Spring | 단말과 작업자는 서버 세션에서 식별한다. 작업지시 버전, 상태, LOT와 위치, 양수 및 유효 소수점 세 자리 이하를 확인한다. 투입은 위치별 가용량, 반납은 해당 지시·LOT의 순투입량을 상한으로 삼는다. |
| 합성 데이터 | 동일 LOT를 여러 투입 위치에 둘 수 있다. 반납 위치는 서버의 단말별 합성 설정으로 결정한다. 재고·작업별 잔량·작업자와 위치를 포함한 이력·버전은 단일 JVM 메모리에서 잠금 아래 함께 교체한다. 전량 반납 후에도 이력이 남는다. |

투입은 완료 전 가능하고 시작에는 투입이 필요하다. 일반 반납은 진행·중지 상태에서 가능하다. 시작 취소는 대기 상태로 되돌리되 투입 잔량과 이력을 보존하며, 대기 상태에서는 반납을 거절한다. 완료 후 일반 반납도 거절한다. 완료 시 남은 투입량의 업무상 소비 확정은 별도 확인 대상이다.

### 검증

초기 초안의 복수 위치 선택, 지정 위치 반납, 투입·반납 이력은 당시 설계 기준이었다. 독립 리뷰는 초기 구현에서 세 기능이 빠져 있고 시작 전 반납도 가능하다고 지적했다. 수정 코드에 위치별 재고 키, 서버 지정 반납 위치, 명령별 이력, 대기 상태 반납 차단이 들어간 것을 정적으로 확인했다.

- 독립 Java 메모리 하네스에서 위치별 차감, 지정 위치 반납, 전량 반납 후 이력 보존, 시작 취소 후 반납 차단, 실패 시 상태 보존 및 두 지시의 동일 재고 경합을 검증했다.
- 워커 검증에서 React lint·빌드와 Spring demo HTTP를 통과했다. 복수 창고·위치, 부분·전량 반납, 작업자 기록, 타 단말 격리, 상태·버전 충돌, 공유 재고와 중지·반납 경합을 확인했다.
- 제한된 Chrome 헤드리스 환경에서 단일·복수 후보 투입, 투입 전 시작 제한, 작업 시작, 지정 위치 반납과 재고·작업자 표시를 확인했다. 기본 헤드리스 실행은 GPU 프로세스 시작 오류로 실패했다.

## ⚠️ 주의사항

합성 범위에는 일반 투입·반납이 포함된다. 재질·치수에 따른 후보 적격성, 완료 후 강제 반납, 실재고와 ERP 반영, 실제 반납 LOT 채번, 다중 서버 동시성은 별도 확인 대상이다.
