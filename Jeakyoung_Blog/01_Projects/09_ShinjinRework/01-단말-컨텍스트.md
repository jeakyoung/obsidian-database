# POP 단말 및 작업자 컨텍스트

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 단말별로 작업자와 작업장을 알아내는 조회 계약 |
| **대상 시스템** | React 화면 및 Spring 컨텍스트 API |
| **최종 확인일** | 2026-11-25 |

## ⚙️ 환경 및 전제

합성 단말 두 개와 작업자 세 명으로 검증한다.

## 📖 상세 내용

### 기존 동작

WinForms에서 공장과 POP ID는 로컬 단말 설정에 있고, 로그인 결과의 작업자와 부서를 화면에서 참조한다. 단말 설정 로딩과 사용자 상태를 `COMMON/ComLogin.cs`에서 확인했다.

### 분리와 구현

- Spring `GET /api/pop/context`는 합성 조회일과 단말별 공장·작업장·작업자 목록을 제공한다. `WorkHistoryController`가 HTTP 응답을 맡고 `WorkHistoryFixtures`가 합성 객체를 보유한다.
- React는 단말을 바꾸면 유효한 작업자를 다시 선택하고 기존 조회 결과를 지운다. 공장·작업장·부서는 현재 선택 정보로 표시한다. 컨텍스트를 불러오지 못하면 다시 요청할 수 있다.
- 작업이력 API도 단말과 작업자의 관계를 검사한다. 이는 합성 데이터 범위 검사이며 실제 사용자의 인증·인가로 쓰이지 않는다.

### 검증과 후속

Chrome에서 단말을 바꿨을 때 작업자가 바뀌고 해당 단말의 이력만 표시되는 것을 확인했다. 다른 단말 작업자로 요청하면 API는 HTTP 400을 반환했다. 실제 로그인·세션·단말 등록과 운영 권한 매핑은 후속 범위다.

## ⚠️ 주의사항

운영에서는 작업자 선택을 인증 및 인가 규칙에 맞춰 제한해야 한다.
