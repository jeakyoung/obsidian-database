# 합성 출력과 PDF 미리보기

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 합성 양식을 선택해 미리보기와 PDF 다운로드를 검증한다. |
| **대상 시스템** | React 출력 메뉴, Spring Boot demo, PDFBox·ZXing |
| **확인 상태** | `dad00d2` 기반 App 리베이스 검증 통과. 인증·글꼴 독립 HTTP 재검토의 기준은 `fdfad1d`. |

## ⚙️ 환경 및 전제

레거시 작업지시서, 작업자 코드, 포장 라벨, 출고 목록, 출하 출력 분기를 합성 예제로 표현한다. 렌더러에는 고정 예제와 로컬 글꼴을 사용한다. 인증된 demo 세션은 예제 목록·미리보기·PDF 다운로드 모두에 필요하다.

## 📖 상세 내용

### 합성 양식과 실패 응답

작업지시서 다섯 양식, 작업자 Code 128·QR, 포장 QR 라벨, 출고 목록, 출하 문서를 제공한다. 사용자는 예제를 골라 화면에서 결과를 확인하고 PDF를 내려받는다. 빈 선택·알 수 없는 양식·입력 오류·렌더 실패를 구분한다. 실패 후 재시도는 기존 문서 참조를 사용한다.

| 글꼴 조건 | 미리보기 | 다운로드 |
| --- | --- | --- |
| 한글 글꼴 사용 가능 | `PDF_READY`, 산출물 1개 | 200, PDF 첨부 |
| 글꼴 설정 누락 | `FONT_NOT_CONFIGURED`, 산출물 0개 | 422, 첨부 없음 |
| 설정된 파일 부재 | `FONT_UNAVAILABLE`, 산출물 0개 | 422, 첨부 없음 |

### 검증

| 근거 | 확인 범위 |
| --- | --- |
| 이전 App 통합 인계 (`fdfad1d`) | Maven 패키징과 React 빌드·lint 통과. 로그인 상태에서 P01–P14를 실행해 PDF를 다시 열고 한글, 페이지·용지, 행·그룹·합계와 Code 128·QR 디코딩을 확인했다. demo 비활성에서는 출력 경로가 404였다. |
| 이전 App Chrome (`fdfad1d`) | 출하 2페이지와 라벨 미리보기, PDF 다운로드, 렌더 실패 후 재시도, 글꼴 파일 부재의 사유와 다운로드 숨김, 다운로드 시 세션 만료 후 로그인 복귀를 확인했다. 기존 작업이력·LOT 투입·008 생략 인계·공장이송도 실행했다. |
| 독립 인증·글꼴 재검토 (`fdfad1d`) | 당시 App 스냅샷의 루프백 HTTP에서 로그인 전·로그아웃 후 목록·미리보기·다운로드가 401이었다. 정상 글꼴은 PDF 첨부로 응답했고, 설정 누락과 파일 부재는 각 상태와 422로 구분됐다. 오류 및 미인증 응답에는 PDF 첨부가 없었다. 이 독립 재검토의 실행은 HTTP와 PDF에 한정했다. |

### 출하 게시 기준 App 리베이스 (`dad00d2`)

최신 실행 로그에서 React 빌드·lint와 P01–P14의 한글 PDF 재열기, 페이지 기하 및 Code 128·QR 디코딩을 확인했다. 실제 Chrome App에서 작업이력, 작업지시·LOT 스캔, RFID, 출하 확정과 공장이송 흐름을 실행했다. 출력 미리보기·PDF 다운로드·재시도·세션 만료를 확인했고, 글꼴 설정 누락과 파일 부재를 각각 표시했다. 이 실행은 최신 App 리베이스 검증이며, 위 독립 HTTP 재검토와 실행 기준이 다르다.

## ⚠️ 주의사항

고정 합성 예제의 인증과 렌더링 범위다. 실제 작업자 출력 권한과 자재·포장·출하 데이터 연결, 운영 글꼴 배치, 프린터 역할·큐·스풀러·실물 여백과 판독은 후속 인수다. 공용 문서 기준은 vault 1ae133b다. 출하 화면의 운영 출하 데이터와 출력 예제를 직접 연결하는 인수는 남았다.
