# COMMON 대화상자와 CONTROL 참조 감사

기준은 레거시 SINJINSM_POP.sln 및 전환 저장소 작업트리다. 솔루션 소속 12개 C# 프로젝트의 Compile 항목을 따라가 COMMON 폼 본체·Designer·resx를 한 단위로 대조했다. 백업과 obj는 제외했다. 아래 호출 줄은 주석을 제외한 생성자/typeof의 파일별 첫 위치다. 생성자 보유 시점과 표시 시점은 다를 수 있다. 외부 바이너리의 동적 호출은 확인 대상 밖이다.

웹 줄은 src/web/src 기준이다. 이번 Chrome 직접 검증은 로그인·메뉴·작업이력과 그룹 단말 권한이다. 아래 폼별 판정은 소스 대조이며 현장 터치·장비·DB 시험을 뜻하지 않는다.

- 샘플 자재의 표시명·규격은 `src/api/src/main/resources/demo/basket-materials.json`으로 분리했다. `shinjin.demo.basket-materials`에 대체 Spring 리소스 경로를 지정할 수 있다. 기존 프로시저 `SP_POP_COM_BASKETADD_01_LIST`의 SELECT1·SELECT2 호출은 각각 원본 261·319줄 부근에 있다. 배포된 프로시저 내부 계산과 운영 데이터 대조는 미검증이다.

### 003·103 작업 중 반납수량 셀

원본 하단 반납자재 그리드의 반납수량을 누르면 `ComNumericKeyPad2`가 0으로 열린다. 숫자·소수점·C·적용·취소를 제공한다. 적용 시 해당 셀을 갱신한 뒤 그룹 전체 반납 행을 저장하고 반납 그리드를 재조회한다. 취소 시 숫자패드 호출만 종료되어 상위 클릭 핸들러가 기존 수량으로 같은 저장을 수행한다. 등록 정보와 반납일자는 유지되고 그룹 전체 반납 행에 수정자와 수정 시각이 반영된다. 별도 ‘저장’ 버튼의 Designer 초기값은 숨김이다. 원본 `POPREG/frmProcess3.cs` 501, 1346, 10087, 10249–10393, 11395–11472와 `frmProcess3.Designer.cs` 1537.

웹은 003·103의 시작된 그룹을 선택하면 반납 그리드를 표시한다. 작업 시작 시점에 임시 장바구니 반납 내역을 복사한다. 셀 저장은 작업 중 반납 내역을 갱신한다. 키패드 입력에는 0과 소수가 포함된다. 지시 목록에 완료 건이 있거나 설정된 반납창고가 없으면 수량 편집을 막는다. 전체 반납 행에 두께·폭·길이가 있어야 저장이 성립한다. 각 행의 순번·품목·LOT·창고·로케이션·날짜와 등록자는 서버가 보유한다.

샘플 Chrome 검증에서 두 반납 행 중 하나를 2.25로 수정한 뒤 취소·0·0.000001을 확인했다. 다른 행의 수량과 임시 장바구니는 보존됐다. 버전 충돌과 동일 요청 재시도, 완료 작업이 섞인 목록과 타 단말 요청도 대조했다. 이번 구현 범위는 기존 반납 행의 수량 셀이다. 규격·창고 변경을 통한 품목 조회, 추가·삭제 버튼과 실제 MSSQL 재고 트리거는 별도 대조 대상이다.

POPRET의 `XtraForm1` 버튼은 `XtraForm2.ShowDialog()`를 호출한다. `XtraForm2`는 생성자 초기화만 수행하고 `XtraForm3`의 클릭 본문은 비어 있다. 프로젝트 참조는 `SJ_SM.csproj` 208줄, 메뉴의 `MainMenu.XtraForm2` 예시는 `MainMenu/frmMenu.cs` 565줄의 주석이다. 이 세 클래스의 C# 코드에서 반납 저장 호출이나 활성 업무 메뉴 진입 근거는 확인되지 않았다. 단말에 외부 설정된 DLL·타입은 운영값 확인 대상이다.

## ComRejectionHistory — frmProcess1 불량수량

frmProcess1.FnRejectionHistoryCall(1200)은 생산계획일·순번·실적순번과 설비·공정을 현재 선택행에서 전달한다. 시작시간이 있고 완료시간이 비어 있으며 불량창고가 설정된 경우에 연다. 준비 단계에서는 불량 셀을 열 수 없다. 일시중단은 등록 가능하다.

원본 ComRejectionHistory.cs의 Load(42), 닫기(484), 적용(502), gv1_RowClick(780)을 기준으로 615×642 창에 불량창고·로케이션과 사유별 수량표, 적용·닫기를 배치했다. 창고 선택에 따라 위치 목록을 바꾸고 이전 저장 위치가 있으면 복원한다. 사유별 +/−는 1씩 바뀌고 최솟값은 0이다. 닫기 및 적용 확인의 아니오는 원장을 바꾸지 않는다. 예를 누르면 수량이 양수인 사유만 저장하고 부모 행 불량합계를 갱신한다.

## 001 작업지시의 양품창고·로케이션

frmProcess1.cs 1573–1611은 완료시간이 비어 있는 gv3의 창고명 또는 로케이션 셀에서 FnWareHousSettingCall3을 호출한다. 시작 여부와 체크 여부는 이 분기의 조건이 아니다. 1154–1188에서 회사·사업장, 행의 창고/위치 코드·명칭과 수주작업상태, 단말의 dLocationInfo3을 넘긴다. 창의 두 조회란에서 창고, 해당 창고의 위치를 고른다. 창고 변경 시 원래 행의 위치 코드를 새 목록에 다시 대입한다. 같은 코드가 없으면 표시명은 비고 원래 위치 코드는 보존된다. 비어 있는 코드만 팝업 자체에서 적용을 거절한다. 대응 DevExpress 런타임 관측은 원본 트리의 .rework-mat-return-location-staging/evidence/native.log에 있다.

합성 Spring GET `/api/pop/work-orders/{date}/{sequence}/good-locations?slot={slot}`는 로그인 단말의 양품창고와 그 지시의 원래 선택을 반환한다. 반환 창고에는 코드·이름·행 기준 작업상태·ETC와 위치 선택쌍이 있다. 대상 위치를 부모에 적용한 후 START 또는 COMPLETE의 `selected[].goodPlace`에 창고·위치 코드와 슬롯을 담는다. 서버는 단말 권한과 창고/위치 관계를 재확인하고 이미 저장된 명칭·상태·ETC를 구해 배치와 함께 반영한다. 목록에 없는 위치도 실제 부모의 기존 코드 또는 같은 로그인 세션·단말·지시·슬롯·revision에서 확인한 코드가 창고 변경으로 남은 경우 빈 이름으로 저장된다. 출처가 확인되지 않은 임의 위치는 422다. 완료된 지시의 재조회는 409다. 조회와 batch는 격리 원장을 사용한다. 프로시저 실행과 운영 수불은 연결하지 않았다.

### 위치 조회와 생산 저장 정의의 운영 카탈로그 대조

2026-11-26 14:36–14:38 KST에 승인된 읽기 연결로 정의와 제약만 확인했다. 운영 SP_POP_COM_LOOKUP_LIST의 location 분기는 TCO102L을 회사·사업장·창고로 필터링하고 삭제 플래그가 1인 행을 제외한다. 정렬은 회사·사업장·위치코드 오름차순이다. 원본 호출이 넘기는 작업장 인수는 이 분기의 WHERE에 사용되지 않는다. SP_POP_REG_PROCESS1_INS_TPR601은 TPR601 직접 INSERT이며 위치마스터와 조합을 비교하지 않는다.
