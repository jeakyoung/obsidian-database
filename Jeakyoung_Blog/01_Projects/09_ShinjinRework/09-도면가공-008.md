# 도면가공 008과 포장·출하 인계

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 1차 포장 산출을 도면가공에 투입하고 완료 결과를 2차 포장과 출하 준비에 인계한다. |
| **대상 시스템** | React 작업 화면, Spring Boot, 로컬 합성 데이터 |
| **최종 확인일** | 2026-11-25 (단일 계획 합성 통합 검증) |

## ⚙️ 환경 및 전제

`POPREG/frmProcess7`의 도면가공, `frmProcess6`의 포장, `COMMON/ComWorkOrderNoScan`의 스캔 분기를 기준으로 한다. 계획행·LOT·버전·단말 소유권과 인계 상태는 합성 계약으로 검증한다. 검증은 격리된 demo 프로필의 단일 계획 흐름에 한정했다.

## 📖 상세 내용

### 기존 패턴과 데모 경계

1차 포장 산출 LOT를 008 스캔과 시작에 사용한다. 1차 포장이 없는 경우 별도 확인으로 진행을 승인하거나 취소한다. 008 완료 후 2차 포장으로 인계하고, 2차 완료는 남은 산출량 전량을 이동해 합성 출하 인계를 한 건 생성한다. 수량을 생략해 직접 완료할 수 있다. 2차 시작은 합성 감사 이벤트나 재고 이동을 추가하지 않는다.

Spring demo는 계획·사업장 범위, 단계 단말 소유권, 버전과 스캔 토큰을 확인한다. 재고·상태·합성 이벤트·출하 인계·요청 영수증은 계획 단위로 함께 반영한다. 같은 요청 키와 동등한 수량은 성공 응답을 재생하고 오래된 버전이나 유효하지 않은 수량은 기존 상태를 보존한다.

### 검증 결과

| 증거 | 통과 범위 |
| --- | --- |
| 워커 검증 로그 | Java 도메인 하네스 6개, React 빌드·lint, Spring HTTP, Chrome UI가 통과했다. HTTP에서 정상·생략 경로, 게이트, 소유권과 버전, 수량·감사 기록, 경합 시 출하 인계 한 건을 확인했다. Chrome에서 정상 흐름, 생략 거절·승인, 직접 인계와 LOT·작업이력 회귀를 확인했다. |
| 독립 통합 재검토 | 단일 계획 통합 통과. 도메인 하네스·HTTP·TypeScript로 빈 세션 식별 거절, 단말·사업장 격리, 극단 수량·일부 수량 거절 후 상태 보존, 동시 완료 한 건과 동등 수치 재요청을 확인했다. 독립 리뷰 범위는 브라우저 실행을 포함하지 않았고, API 컴파일 중 JAR 종료 접근 진단은 전체 프로젝트 빌드 통과로 집계하지 않았다. |

### 별도 미완 인수

- **묶음·공유 재고** — 현재 재고는 계획별로 격리된다. 동일 생산그룹의 후보 중복 제거, 공용 LOT 경합, 공통 일보·수불번호와 계획별 항번, 정상·생략 혼합 묶음의 잔재 배정이 남았다.
- **실제 행 대조** — 합성 이벤트로 발생 횟수와 인계 식별자를 확인했다. 실제 작업시간·실적·일보·수불 및 출하 헤더·명세의 행 수와 연결 키, 취소·보정은 별도 인수다.
- **운영 연동** — 실제 ERP 채번·출하와 출하 화면 연계, 현장 재질·치수 특례, 실재고 보정, 영속 저장 및 재시작 후 중복 방지는 미검증이다.
