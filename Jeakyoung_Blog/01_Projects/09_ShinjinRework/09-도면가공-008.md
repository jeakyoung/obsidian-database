# 도면가공 008과 포장·출하 인계

| 항목 | 내용 |
|:--|:--|
| **용도** | 1차 포장 산출을 도면가공에 투입하고 완료 결과를 2차 포장과 출하 준비에 인계한다. |

## ⚙️ 환경 및 전제

`POPREG/frmProcess7`의 도면가공, `frmProcess6`의 포장, `COMMON/ComWorkOrderNoScan`의 스캔 분기를 기준으로 한다. 계획행·LOT·버전·단말 소유권과 인계 상태는 합성 계약으로 검증한다. 검증은 격리된 demo 프로필의 단일 계획 흐름에 한정했다.

## 📖 상세 내용

### 기존 패턴과 데모 경계

1차 포장 산출 LOT를 008 스캔과 시작에 사용한다. 1차 포장이 없는 경우 별도 확인으로 진행을 승인하거나 취소한다. 008 완료 후 2차 포장으로 인계하고, 2차 완료는 남은 산출량 전량을 이동해 합성 출하 인계를 한 건 생성한다. 수량을 생략해 직접 완료할 수 있다. 2차 시작은 합성 감사 이벤트나 재고 이동을 추가하지 않는다.

Spring demo는 계획·사업장 범위, 단계 단말 소유권, 버전과 스캔 토큰을 확인한다. 재고·상태·합성 이벤트·출하 인계·요청 영수증은 계획 단위로 함께 반영한다. 같은 요청 키와 동등한 수량은 성공 응답을 재생하고 오래된 버전이나 유효하지 않은 수량은 기존 상태를 보존한다.

### 검증 결과

| 증거 | 통과 범위 |

| 독립 통합 재검토 | 단일 계획 통합 통과. 도메인 하네스·HTTP·TypeScript로 빈 세션 식별 거절, 단말·사업장 격리, 극단 수량·일부 수량 거절 후 상태 보존, 동시 완료 한 건과 동등 수치 재요청을 확인했다. 독립 리뷰 범위는 브라우저 실행을 포함하지 않았고, API 컴파일 중 JAR 종료 접근 진단은 전체 프로젝트 빌드 통과로 집계하지 않았다. |

### 별도 미완 인수

- **묶음·공유 재고** — 현재 재고는 계획별로 격리된다. 동일 생산그룹의 후보 중복 제거, 공용 LOT 경합, 공통 일보·수불번호와 계획별 항번, 정상·생략 혼합 묶음의 잔재 배정이 남았다.
- **실제 행 대조** — 합성 이벤트로 발생 횟수와 인계 식별자를 확인했다. 실제 작업시간·실적·일보·수불 및 출하 헤더·명세의 행 수와 연결 키, 취소·보정은 별도 인수다.
- **운영 연동** — 실제 ERP 채번·출하와 출하 화면 연계, 현장 재질·치수 특례, 실재고 보정, 영속 저장 및 재시작 후 중복 방지는 미검증이다.

## 013 자동 반납과 일반 반납의 완료 저장

2026-11-26 17:30 KST 운영 MES의 sys 메타데이터와 frmProcess7.cs 완료 호출부를 대조했다. 운영 수불·마스터 행 조회나 프로시저 실행, 데이터 변경, 출력은 하지 않았다.

일반 반납은 사용자 단말의 반납창고 목록에서 후보를 고른다. 완료 시 창고 013 이외의 화면 반납행은 위치와 수량 1 이상이 필요하며, 다음 검사에서 화면에 있는 모든 반납행의 두께·폭·길이 0을 거부한다(4953–4997). 뒤에서 처리하는 013 자동행은 편집 표에서 제출한 수량이 아니다. 7674–7883에서 현재 재질, 회사·사업장, TCO102M의 창고 013 매핑을 조회해 품목·위치 단위로 생성한다. 0/0/0은 분철량, 1/1/1은 생철량이며 SQL이 반환한 다른 0/1 조합은 초기 수량 0으로 남는다. 008 계산은 002와 같은 분기다. 일반 반납행의 치수·수량은 잔재중량으로 반영되며 생철 자동수량은 투입중량에서 생산·분철·반납중량을 차감한다. 양품 017/000000 입고와 구분한다.

TPR601M 방향 1에는 반납품목, X+품목코드 LOT, 창고·위치, 수량, 0단가, 빈 계획일과 0순번을 기록하는 코드가 있다. TPR601M의 활성 AFTER 트리거는 SP_TMA922_SAVE01을 호출하여 방향 1을 입고, 0을 출고로 전달하고 변경 전 행은 역부호로 전달한다. 해당 트리거에 013 제외 조건은 없다. 008 반납의 별도 ERP 생산일보 호출은 9313행에서 주석 처리되어 있다. 9444–9445의 별도 ERP → MES 순서 커밋을 단일 분산 트랜잭션으로 가정할 수 없다.

합성 구현은 완료 요청에서 일반 반납수량과 창고별 잔량, 013 매핑별 자동반납, 양품 입고를 구분한다. 원본의 음수 생철 산식도 보존한다. 체크된 생산행만 완료하면서 중량 계산에 쓰이는 표의 표시 수량을 별도로 유지한다. 중복 요청에 입고가 한 번만 생겼다. 합성 5개 마스터 행을 쓴 결과이며 운영 LOT별 대사 및 MES와 ERP 사이의 실패 복구는 별도 검증 대상이다.
