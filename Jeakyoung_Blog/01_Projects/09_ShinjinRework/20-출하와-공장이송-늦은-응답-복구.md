# 출하·공장이송 늦은 응답 복구

## 📋 개요

20번 작업 노트. 수정본의 코드 기준은 `5e819df`, vault 기준은 `0b7bd9b`다. 19의 단말 설정과 독립된 변경이다. 최신 수정본과 배치 해시를 대조했다. 구현자 Chrome 검증과 두 모듈의 독립 P2 재검토가 통과했다.

## 📖 상세 내용

### 감사에서 확인한 재현

`3939666` 기준 합성 Chrome에서 출하 확정 A와 새 재출력 B, 공장이송 의뢰 A와 새 의뢰 B를 각각 사용했다. 서버에 반영된 첫 A의 200을 지연한 상태에서 화면을 다시 열고 A를 동일 키로 재생한 뒤 B를 전송했다. B의 키·본문을 저장한 뒤 첫 A의 응답을 전달하자 B의 저장 사본이 삭제됐다. B 응답까지 유실되면 원래 키로 복구할 수 없었다. 이전 요청의 늦은 401이 활성 화면의 세션 만료 콜백에 도달할 수 있는 경로도 정적으로 확인했다.

### 수정 계약

| 경계 | 코드에서 확인한 동작 |
| --- | --- |
| 보류 사본 정리 | 출하는 `requestId`, 공장이송은 `commandId`를 현재 저장값과 비교한다. 확정 응답도 해당 키의 사본만 지운다. |
| 화면 요청 수명 | 화면 이탈 시 진행 중인 명령을 중단한다. 중단된 호출은 현재 화면의 상태·재조회·세션 만료 처리에 관여하지 않아야 한다. |
| 원래 작업자의 복구 | 복구는 같은 탭·단말·작업자와 원래 본문을 사용한다. 기존 서버 권한과 멱등 처리가 적용된다. |
| 공장이송 보류 범위 | 브라우저의 응답 불확실 사본과 ERP 선커밋 후 POP 적용 보류는 별개다. 이 변경은 브라우저 요청·응답 경계를 다룬다. |

### 최신 통합 검증

출하와 공장이송 모두 실제 Chrome에서 A의 지연 200·401, 이전 화면의 후속 조회 401, 현재 사본의 다른 키 보호를 통과했다. 원래 작업자가 B를 같은 키·본문으로 재생했고 출하 재출력 횟수와 공장이송 반영이 중복되지 않았다. 웹 빌드와 C 저장소 배치 빌드가 통과했다. 통합 실행의 lint에는 기존 재고이동 화면의 ref cleanup 경고 1건이 있었다.

### 독립 P2 재검토

독립 검증은 매니페스트의 네 파일과 같은 빌드 입력을 사용해 실제 Chrome 158에서 A/B 순서를 다시 실행했다.

| 경로 | 독립 확인 결과 |
| --- | --- |
| 출하 | A의 늦은 성공 뒤 B가 보존됐고, B 응답 유실·화면 재진입과 이전 화면의 실제 401 이후에도 활성 세션과 사본이 유지됐다. 동일 키·본문으로 B를 재생해 원전표와 재출력 1건이 유지됐다. 미리보기 텍스트가 같았고 업무 PDF 응답은 200이었다. |
| 공장이송 | 첫 A의 늦은 성공, B 응답 유실 후 재진입, 실제 401의 역순 전달에서 B를 보존했다. 원래 명령 ID·본문으로 재생해 이송·잔량 스냅샷이 유지됐고 B 의뢰는 한 건이었다. |

## ⚠️ 주의사항

브라우저 탭의 보류 사본과 합성 서버 상태에 한정한다. 브라우저 저장소 삭제·서버 재시작 후 복구, 실제 ERP 연동과 운영 데이터는 별도 인수다.
