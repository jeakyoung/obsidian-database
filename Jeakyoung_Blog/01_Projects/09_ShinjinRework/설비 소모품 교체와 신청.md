## 원본 데이터 계약

- SP_POP_EXPENDABLES_04_LIST / EXPENDABLES_REQUEST. 목록은 WORKCENTER_CODE·PLANT_CODE에 빈 SYS_LOT_NO·VIEW_SEQ를 전달한다. 저장 시에는 같은 범위에 실제 행의 LOT·항번을 전달하고 첫 행의 TOTAL_QTY 또는 0을 사용한다.
- EXPENDABLES_CHANGE_LIST는 EQUIP_SYS_CD·WORKCENTER_CODE로 설비 내역을 읽는다. EXPENDABLES_EQUIP_CH_NO의 번호 결과와 서버 날짜·일시, 로그인 사번·설비코드·품목코드·수량·원행 OPTIME·LOT를 TPR154H에 기록하는 호출 코드가 있다. 여러 행은 한 트랜잭션이다. 프로시저 내부 번호 규칙·트리거·후속 재고 갱신은 이 호출부로 확정할 수 없다.
- demo는 같은 사업장·작업장의 합성 가용량과 설비별 내역을 한 잠금에서 검증·반영한다. 번호는 DEMO-CH- 순번이고 JVM 재시작 시 초기화된다. fixture 및 기록은 관리 메뉴의 소모품 입출고에서 분리했다. 운영 장치·DB·SQL은 사용하지 않는다.

## 합성 API

기본 경로는 `/api/demo/machine-calls/{machine}`이다. 세 엔드포인트 모두 현재 인증 세션에 고정된 설비 코드인지 서버가 확인한다. 클라이언트가 사번·사업장·설비명을 입력하지 않는다. 일반 작업자도 그 세션에 배정된 설비에서 신청할 수 있다.

| 메서드·하위경로 | 인수 | 결과 |
|---|---|---|
| GET /expendables | 경로의 설비 | row(lot, sequence), 품목명, PART_NO, 입고일, 남은수량 |
| GET /replacements | 경로의 설비 | 해당 설비의 신청 내역 배열 |
| POST /replacements | key(UUID), lines 배열. 원행 row와 정수 quantity | 이번 요청의 replacements. 체크한 수량이 전부 0이면 빈 배열. |

401은 미인증, 403은 현재 세션에 미할당인 설비, 422는 유효하지 않은 행·중복 행·수량, 409는 가용 부족 또는 이미 사용한 키의 본문 변경이다. 수량 부족은 BALANCE_CHANGED와 합성 품목명을 돌려주며 UI가 후보를 다시 조회한다. 같은 작업자·단말의 같은 키와 같은 설비·수량 요청 재시도는 처음 결과를 반환한다. 응답 유실 뒤 열린 창의 신청 버튼은 같은 키·본문을 재전송한다. 장치 간 공유와 별개로 다른 사업장·작업장의 잔량과 내역은 분리한다.
