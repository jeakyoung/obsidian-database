# 합성 창고 재고이동

L3 작업 노트 17. 다음 배치 코드 기준은 `3939666`, 문서 기준은 `22e99cc`다. 08의 L3 인수행과 게시된 18을 유지한다.

## 레거시와 합성 범위

`POPLGS/frmLogistics5`의 창고 이동은 출발 잔량, 품목·LOT, 출발과 도착의 창고·위치를 확인한다. `frmLogistics8`에도 별도 창고이동 분기가 있다. 합성 모델은 같은 사업장의 서로 다른 창고 간에 같은 품목·LOT의 수량을 원자적으로 차감·가산한다. 원 이동 단말의 취소는 목적지 잔량이 충분할 때만 허용하며 원 이동 이력을 취소 상태로 보존한다.

## 인수 상태

독립 리뷰에서 수량 보존, 출발 경합, 권한·버전, 부족 재고 취소 거절과 같은 화면 내 동일 키 재생을 확인했다. `f2d9f0d` App 통합과 독립 재검토에서 503·401·화면 재진입 후 원 작업자의 동일 명령을 복원했고, 타 작업자 재생을 403으로 차단했다. 별도 P2로 이전 마운트의 지연 성공 응답이 새 명령의 저장 사본을 지울 수 있는 경합이 재현됐다. 최신 `3939666` 통합본은 응답의 요청 ID와 현재 저장 사본의 ID가 일치할 때만 사본을 지운다. 화면을 떠난 이전 요청은 현재 화면의 상태·새로고침·세션 만료에 관여하지 않는다.

Chrome 158에서 503 응답 유실, 화면 재진입, 실제 401, 타 작업자 차단과 같은 사용자 복구를 재검증했다. 새 명령 B의 사본은 이전 A의 늦은 200 이후에도 남았고, 이전 화면의 늦은 401은 현재 세션을 종료시키지 않았다. B 재생에는 추가 차감이나 이력이 없었다. 같은 세션에서 출하 확정 후 PDF 미리보기와 PDF 응답, ESCO·발주입고 및 출력 메뉴 진입도 확인했다. Java 도메인·Spring HTTP와 웹 빌드가 통과했다.

최신 통합본의 파일 해시를 대조한 독립 재검증도 P2를 통과했다. 이전 화면의 지연 200 뒤에도 새 요청 사본이 유지됐고, 지연 401은 현재 인증 화면을 종료시키지 않았다. 원래 작업자의 재생이 재고·버전·이력을 추가 변경하지 않는 것을 확인했다. 프로덕션 빌드는 통과했으며 lint에는 화면 수명 추적용 ref 증가에 관한 경고 1건이 남았다.

운영 ERP 전표·트리거, 실제 창고 원장 및 재기동 복구는 후속 인수다.
