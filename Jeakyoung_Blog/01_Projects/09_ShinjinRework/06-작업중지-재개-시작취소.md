# 작업 중지·재개와 시작 취소

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 작업 중지·재개와 진행 중인 작업 시작의 취소 |
| **대상 시스템** | React 작업지시, Spring Boot demo 프로필 |
| **최종 확인일** | 2026-11-25 |

## ⚙️ 환경 및 전제

업무 명령은 로그인한 단말의 합성 작업지시를 변경한다. 상태와 버전은 Spring 서버 메모리에 보관하며 재시작하면 초기화된다.

## 📖 상세 내용

### 기존 패턴

WinForms `POPREG/frmProcess1.cs`의 `btnWorkStop_Click`은 선택 작업, 투입자재, 완료 여부를 확인하고 사용자에게 중지 또는 재시작 확인을 받는다. 작업시간 유형은 중지에 `2`, 재시작에 `1`을 사용한다. 별도 `btnWorkDelete_Click` 경로는 확인 후 실적·자재·작업시간에 걸친 삭제를 처리한다.

### 분리와 구현

| 명령 | 허용 상태 | 합성 결과 |
| --- | --- | --- |
| PAUSE | 진행 중 | 중지 |
| RESUME | 중지 | 진행 중, 기존 시작 작업자 유지 |
| CANCEL_START | 진행 중 또는 중지 | 대기로 복원하고 시작 작업자·실적 입력 초기화 |
| COMPLETE | 진행 중 | 실적수량 기록 후 완료 |

React는 상태에 맞는 중지·재개 버튼을 표시하고, 시작 취소에는 별도 확인을 받는다. 중지 필터를 추가하고, 처리 결과로 목록과 상세를 갱신한다.

기존 작업지시 `/actions`는 상세 응답의 `revision`을 명령의 `expectedRevision`으로 받는다. 시작과 완료를 포함한 모든 명령은 이 값을 전달해야 한다. Spring은 메모리 잠금 안에서 상태와 버전을 확인하고 갱신한다. 취소 후 다시 시작해 상태 이름이 같아져도 옛 버전의 요청은 409로 거절한다. React는 충돌 시 최신 목록과 상세를 재조회한다.

### 검증

Maven 및 React lint·빌드를 통과했다. Chrome에서 중지 표시와 필터, 취소 확인·철회, 재개와 대기 복원, 다시 시작 후 완료, 작업이력 화면을 확인했다. HTTP에서 다른 단말, 버전 누락, 중지 중 완료, 완료 후 취소, 옛 버전 요청을 검증했다. 동시 중지 요청은 하나만 반영됐다.

## ⚠️ 주의사항

시작 취소는 합성 작업의 상태만 되돌린다. 기존 작업지시 일괄 삭제, 자재·재고 복원, 실적 삭제, 작업시간 이력과 생산 재개 시 설비 검사는 후속 작업이다. 실제 DB나 설비에는 접속하지 않았다.
