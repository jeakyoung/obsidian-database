# 008 포장 인계와 합성 출하

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **용도** | 2차 포장 결과를 출하 후보로 받아 확정·재출력 기록·취소를 검증한다. |
| **대상 시스템** | React 출하 메뉴, Spring Boot demo, 008 합성 도메인 |
| **확인 상태** | `07c8ea1` 기반 합성 Chrome 재검증. 새 기반의 독립 P2 기록 확인 대기. |

## ⚙️ 환경 및 전제

레거시 출하는 `POPLGS/frmLogistics6`에서 포장 결과를 조회해 출하를 처리한다. 합성 통합은 인증 범위의 008 `SHIP_READY` 계획에서 포장 계획 키, 인계 ID, LOT·품목·수량을 같은 서버 도메인으로부터 읽는다. 출하 명령은 인계 ID·작업·버전·요청 키를 사용한다.

## 📖 상세 내용

### 출하와 재시도

사업장별로 목록을 격리하고 지정 단말에만 확정·취소·재출력 명령을 허용한다. 같은 버전의 경쟁 명령은 하나만 반영한다. 출하 확정으로 생성된 전표번호를 재출력 기록과 취소에도 유지한다. 재출력은 횟수와 버전을 변경하고, 취소는 최초 확정 정보와 재출력 이력을 보존한다.

요청을 보내기 전 같은 탭의 단말·작업자별 저장소에 합성 본문과 키를 보존한다. 응답 유실·401·화면 재마운트 이후 원래 작업자가 동일 요청을 재생할 수 있다. 다른 작업자에게 재시도 사본이 표시되지 않으며 직접 재생은 403이다. 성공이나 확정 실패에서 브라우저 사본을 제거한다.

### 검증

| 근거 | 확인 범위 |
| --- | --- |
| 독립 Java·HTTP 리뷰 | 서버 소유 포장 인계, 전표 유지, 사업장·단말 범위, 동시 확정 및 취소·재출력 경합을 확인했다. 당시 UI의 401 후 복구는 P2로 남겼다. |
| 최신 통합 인계 | Java 17 도메인과 웹 빌드 통과. Spring HTTP에서 단일 008 포장 인계와 출하 상태 전이를 확인했다. 그룹 008의 공유 LOT 초과 거절, 묶음 완료, 공통 번호·별도 항번과 구성원 2차 포장 인계도 확인했다. |
| 실제 Chrome 158 | 1차 포장 → 008 → 2차 포장 → 출하 확정·재출력·취소를 실행했다. 다른 사업장 목록 격리와 명령 403, 작업이력·LOT·008·공장이송 메뉴 접근을 확인했다. |
| P2 수정본 Chrome | 반영된 재출력의 응답을 폐기하고 같은 요청에 401을 유도했다. 타 작업자의 복원·직접 재생을 제한한 뒤 원래 작업자가 같은 키·본문을 재생했다. 전표 1건, 재출력 1회와 버전이 유지됐다. 이 결과는 수정본 통합 인계의 Chrome 실행 결과다. |
| 새 기반 Java·HTTP | `07c8ea1` 통합 인계에서 단일·그룹 인계, 공유 LOT 과할당의 무변경, 정상 묶음 시작·완료, 출하 범위와 중복·취소·재출력을 재검증했다. |
| 새 기반 Chrome 158 | 작업지시 스캔으로 LOT 상세에 들어가고 RFID 태그 입력 전달을 확인했다. 단일 008 포장 인계와 출하 확정·재출력·취소, 응답 유실·401 후 재생과 사업장 격리가 통과했다. 재생 후 전표 1건, 재출력 1회, 재생 전 버전이 유지됐다. |
| 독립 P2 판정 | `fdfad1d` 통합본의 응답 유실과 401 복구는 독립 재검토를 통과했다. `07c8ea1`의 전체 App 재검증은 최신 통합 인계의 실행 결과이며, 이 기반의 독립 P2 기록은 확인 대기다. |

## ⚠️ 주의사항

재출력은 합성 횟수 기록이다. D3 PDF·미리보기 연결, 실제 인쇄·ERP 전송·전표, 운영 재고 차감·복원과 영속 복구는 별도 인수다. 그룹 전체 경로의 실행 근거는 HTTP이며 새 기반 Chrome은 단일 포장 인계와 출하를 다뤘다. 문서 갱신 기준은 vault 33cd598이다.
