# I-Frog 환경별 설정 및 배포 가이드

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | I-Frog 백엔드 (`F1Soft.Starmap.Service`, `DBfood_temp/f1soft-starmap-service`) |
| **적용 범위** | 서버환경 |
| **관련 모듈** | `Program.cs`, `Services/EnvService/*`, `appsettings.json` |

> 이전 버전 문서가 `Common/Env`, `Contexts/`(복수형), `InputListService` 같은 걸 언급하고 있었는데, 지금 이 저장소 코드엔 그런 경로/클래스가 없음. 실제 코드 기준으로 다시 씀.

## 🎯 배경 및 요구사항

배포본은 하나다. 회사(Ticker)와 환경(Env)은 **요청 헤더로 갈린다.**

## 🏗 설계 및 구현

### 런타임

| 항목 | 값 |
|:--|:--|
| TargetFramework | `net10.0` |
| 주요 패키지 | `Microsoft.Data.SqlClient`, `Npgsql`, `Oracle.ManagedDataAccess.Core`, `SapNwRfc`, `FirebaseAdmin`, `Microsoft.AspNetCore.Authentication.JwtBearer`, `Swashbuckle.AspNetCore` |
| DB | MSSQL(그룹웨어/ERP 주력), PostgreSQL(설정 테이블 + 통합서버), Oracle(연동 헬퍼 존재, 컨트롤러는 비활성화) |

### 빌드 구성

솔루션 구성은 **Debug / Release / Staging** 세 가지 (`F1Soft.Starmap.Service.sln` 기준).

| 구성 | 컴파일 심볼 |
|:--|:--|
| Debug | (없음) |
| Release | `RELEASE` |
| Staging | `STAGING` |

`Program.cs`에서 Swagger 타이틀만 `#if DEBUG/STAGING/RELEASE`로 갈리고, `IEnvService` 등록은 세 분기 다 `AddScoped<IEnvService, EnvService>()`로 동일 — 사실상 구분 없는 조건부 컴파일이 남아있는 상태.

> [!warning] Debug 빌드에서는 인증이 빠질 수 있다
> `SettingController` 등 일부 컨트롤러의 `[Authorize]`가 `#if !DEBUG`로 감싸여 있다. Debug로 띄우면 토큰 없이도 호출이 통과할 수 있으니, **인증 동작 확인은 Release/Staging으로 해야 한다.**

### 설정 파일 구조

`appsettings.json`은 gitignore 대상. 실제 DB 연결 문자열, FTP 계정, JWT 서명키가 들어있다.

**중요:** 회사(Ticker)별 MSSQL 연결 문자열/FTP/이미지 URL은 appsettings.json에 직접 있지 않다. `EnvService`가 앱 기동 시 Postgres의 `tgi000_01_list` 프로시저를 한 번 호출해서 메모리 캐시에 올려두고 그걸 돌려준다. 자세한 구조는 [[[기술] 보안코드 기반 멀티테넌시 커넥션 구조]] 참고.

appsettings.json에서 코드가 실제로 읽는 건:

- `ConnectionStrings:Postgre{Env}Connection` — 설정 테이블 조회용 Postgres 커넥션
- `JwtTokenSettings:{ValidIssuer,ValidAudience,SymmetricSecurityKey}`
- `ApiKeySettings:FcmInternalKey` — FCM 업무연락 발송 API의 서버-to-서버 인증키

`ConnSettings`/`MsSqlDevConnection` 같은 키가 파일에 남아있을 수 있는데, 현재 활성 코드에서는 아무도 참조하지 않는다(주석 처리된 레거시 `Database/*QueryController`에만 흔적이 남아있음).

값을 읽을 때는 반드시 `IEnvService`를 거친다. `IConfiguration`에서 직접 읽으면 멀티테넌트가 깨진다.

### 파이프라인 순서

```csharp
app.UseSwagger();
app.UseSwaggerUI();
app.UseMiddleware<TickerMiddleware>();   // SECURITY_CODE 검사
app.UseAuthorization();
app.MapControllers();
```

> [!warning] `UseAuthentication()`이 파이프라인에 없다
> `AddAuthentication().AddJwtBearer(...)`로 JWT 인증을 등록은 해뒀는데, `app.UseAuthentication()` 호출이 파이프라인에 없다. 일반적으로 JWT Bearer가 `HttpContext.User`를 채우려면 `UseAuthorization()` 전에 `UseAuthentication()`이 있어야 하는데 이게 빠져있어서, `[Authorize]`가 의도대로 동작하는지 실제로 확인이 필요하다. (전역 예외 처리 미들웨어도 등록돼 있지 않음 — `TickerMiddleware`가 던지는 `UnauthorizedAccessException`을 누가 어떤 응답으로 바꿔주는지도 코드상으로는 안 보임.)

### 로컬 실행

```bash
cd DBfood_temp/f1soft-starmap-service
dotnet build F1Soft.Starmap.Service.sln
dotnet run --project F1Soft.Starmap.Service
```

`appsettings.json`이 있어야 뜬다. Swagger UI는 `/swagger`. 호출할 때 `SECURITY_CODE` 헤더를 빠뜨리지 않는다.
