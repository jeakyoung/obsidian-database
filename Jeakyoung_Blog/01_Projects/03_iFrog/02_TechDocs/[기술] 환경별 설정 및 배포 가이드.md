# I-Frog 환경별 설정 및 배포 가이드

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | I-Frog 모바일 백엔드 (`F1Soft.Starmap.Service`) |
| **적용 범위** | 서버환경 |
| **관련 모듈** | `Program.cs`, `Common/Env/*`, `appsettings.json` |


## 🎯 배경 및 요구사항

배포본은 하나다. 회사(Ticker)와 환경(Env)은 **요청 헤더로 갈린다.**
따라서 환경별로 바뀌는 것은 코드가 아니라 `appsettings.json` 의 값과 빌드 구성뿐이다.

## 🏗 설계 및 구현

### 런타임

| 항목 | 값 |
|:--|:--|
| TargetFramework | `net10.0` |
| Web Server | NginX (리버스 프록시) |
| 서버 OS | Ubuntu 22.04.5 LTS |
| DB | MSSQL (주력), PostgreSQL |

주요 패키지: `Microsoft.Data.SqlClient`, `Npgsql`, `Oracle.ManagedDataAccess.Core`,
`Microsoft.AspNetCore.Authentication.JwtBearer`, `Swashbuckle.AspNetCore`, `FirebaseAdmin`

### 빌드 구성

`Configurations` 는 **Debug / Release / Staging** 세 가지다.

| 구성 | 컴파일 심볼 |
|:--|:--|
| Debug | (없음) |
| Release | `RELEASE` |
| Staging | `STAGING` |

> [!warning] Debug 빌드에서는 인증이 빠진다
> 일부 컨트롤러의 `[Authorize]` 가 `#if !DEBUG` 로 감싸여 있다.
> Debug 로 띄우면 토큰 없이도 호출이 통과하므로, **인증 동작 확인은 Release 나 Staging 으로 해야 한다.**

### 설정 파일 구조

`appsettings.json` 은 **gitignore 대상**이다. 실제 DB 연결 문자열, FTP 계정, JWT 서명키가 들어 있다.
커밋하거나 내용을 공유하지 않는다.

키 구조만 적으면 다음과 같다.

```
ConnSettings
  DBG
    MsSqlDevConnection / MsSqlStgConnection / MsSqlPrdConnection
    FtpDevUrl      / FtpStgUrl      / FtpPrdUrl
    FtpDevUser     / FtpStgUser     / FtpPrdUser
    FtpDevPassword / FtpStgPassword / FtpPrdPassword
    FtpDevMaterialImageHttpsUrl / ...
  SYN
    (동일 구조)
JwtTokenSettings
  ValidIssuer / ValidAudience / SymmetricSecurityKey
```

값을 읽을 때는 **반드시 `IEnvService` 를 거친다.**

```csharp
// 올바른 방법 — 요청의 Ticker/Env 에 맞는 값이 나온다
public MyService(IEnvService envService)
{
    _connectionString = envService.GetConnectionString();
    _ftpUrl = envService.GetFtpUrl();
}
```

```csharp
// 하지 말 것 — 멀티테넌트가 깨진다
_connectionString = _configuration["ConnSettings:DBG:MsSqlPrdConnection"];
```

`IEnvService` 가 제공하는 것: `GetConnectionString()`, `GetFtpUrl()`, `GetFtpUser()`,
`GetFtpPassword()`, `GetMaterialImageHttpsBaseUrl()`.
설정 키가 없으면 `KeyNotFoundException("설정값 없음: ...")` 이 난다.

> [!warning] HTTP 요청 밖에서는 쓸 수 없다
> `EnvService` 는 `TickerContext` 에 의존하고, `TickerContext` 는 미들웨어가 채운다.
> 배치·스타트업 코드처럼 미들웨어를 타지 않는 곳에서 호출하면
> `InvalidOperationException("Ticker 호출 실패")` 가 난다.

### 파이프라인 순서

```csharp
app.UseExceptionHandler(...);   // 처리되지 않은 예외를 ApiResponse 모양 JSON 으로
app.UseSwagger();
app.UseSwaggerUI();
app.UseMiddleware<TickerMiddleware>();   // SECURITY_CODE 검사. 여기서 401 로 끊긴다
app.UseAuthentication();                 // JWT
app.UseAuthorization();
app.MapControllers();
```

`TickerMiddleware` 가 인증보다 **앞**이다. 토큰이 아무리 정상이어도
`SECURITY_CODE` 가 없으면 401 이 먼저 난다.

### 로컬 실행

```bash
cd foodlink-service/foodlink-service
dotnet build F1Soft.Starmap.Service.sln
dotnet run --project F1Soft.Starmap.Service
```

`appsettings.json` 이 있어야 뜬다. Swagger UI 는 `/swagger`.
호출할 때 `SECURITY_CODE` 헤더를 빠뜨리지 않는다.

### 서버 배포

NginX 가 앞단에서 .NET 런타임으로 넘긴다. 설정 변경 후에는 문법 검사부터 한다.

```bash
sudo nginx -t                      # 설정 문법 검사
sudo systemctl reload nginx        # 무중단 재적용
sudo systemctl restart nginx       # 완전 재시작
sudo systemctl status nginx        # 상태 확인
```

## ✅ 검증

- [ ] Release/Staging 빌드에서 `[Authorize]` 가 실제로 동작하는지
- [ ] `SECURITY_CODE` 만 넣고 토큰 없이 호출 → 401 (인증 필요) 인지
- [ ] 보안코드 Env 자리를 `00` / `02` 로 바꿔 서로 다른 DB 를 보는지
- [ ] `appsettings.json` 이 커밋 목록에 올라오지 않는지
- [ ] `nginx -t` 통과 후 reload 로 다운타임 없이 적용되는지
