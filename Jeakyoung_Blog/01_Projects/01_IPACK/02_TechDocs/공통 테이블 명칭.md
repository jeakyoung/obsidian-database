# 공통 테이블 명칭

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | iPlusERP (아이팩 MES/ERP) |
| **적용 범위** | 공통 (업무 전 영역) |
| **관련 모듈** | 영업(SA) · 생산(PR) · 구매(MA) · 인사(HR/TIN) · 공통/창고(CO) |

## 🎯 배경 및 요구사항

아이팩 MES/ERP는 업무 영역별로 접두어가 붙은 테이블 체계(TMA=구매, TPR=생산, TSA=영업, TIN=인사, TCO=공통/창고)를 쓴다. 업무 흐름을 따라가며 MAIN/DETAIL 테이블 쌍과 주요 PK를 정리해두는 문서.

### 업무 프로세스 개요 (IPACK 기준)

| 영역 | 흐름 |
|:--|:--|
| 영업(Sales) | 주문 → 품목마스터(`TCO403`) → 수주등록 → 수주승인 |
| 생산(Production) | 생산계획수립(`TPR301`/`TPR301R`/`TPR302`) → 생산실적현황·POP(`TPR601`) |
| 출하(Delivery) | 출하 납기(`TSA407`) — 기본은 영업 소관, 타 부서 조율이 다수 필요 |
| 구매(Purchase, TMA) | 구매 요청 → 구매 승인 → 입고 관리 |
| 품질관리(TQC) | 미확인 — 담당 테이블 정보 없음 |
| 인사(TIN) | 이 문서 범위에서는 테이블 정리 없음. 근태 쪽 코드 체계는 [[01_Projects/01_IPACK/02_TechDocs/근태_1기본개념/[참고] IPACK 근태 구분 공통코드\|IPACK 근태 구분 공통코드]] 참고 |

### 공통 규칙

- DETAIL 페이지는 항상 DETAIL 테이블 이전에 MAIN 테이블에 동일 키값이 존재해야 한다.
- **수주처**: 주문을 한 회사 / **발주처**: 외주작업이 필요해 주문을 넣는 회사 / **납품처**: 제품 제작 완료 후 재고를 보낼 회사
- **OEM**: 자재 관리 관련 구분

### 테이블 정보

> [!note]
> 이 코드베이스(`iPlusERP`)에는 저장 프로시저(SP) 본문이 소스로 존재하지 않는다 — Java 서블릿이 `EXEC SP_xxx`를 문자열로 호출만 할 뿐, 테이블 접근 로직은 DB 안의 SP 안에 있다. 아래 표에서 **확인** 열이 ✅인 것은 `iPlusERP/src` 자바 소스 안에서 테이블명이 리터럴로 등장하는 걸 grep으로 직접 찾은 것이고, 미확인은 이 레포에서 못 찾았다는 뜻이지 틀렸다는 뜻은 아니다.
