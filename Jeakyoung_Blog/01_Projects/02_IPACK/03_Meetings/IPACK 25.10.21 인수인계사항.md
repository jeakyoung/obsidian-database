### 2. 상세 화면

#### 2-1. 수주등록

거래처, 제품등록 먼저 진행 (용기인지 펌프인지 선택)

BOM 관리 → 어떤 재료가 들어가는지 (구성품 등록)

- 캡 등록은 구성품등록과 별개로 진행
- 펌프, 튜브 → 뚜껑(캡)

**프로세스 순서:** 주문 → 수주확정 → 생산 자동등록

BOM(자재명세서) = 특정 제품을 생산하는 데 필요한 원자재, 부품, 반제품 등의 종류와 수량을 정리한 목록

**특이점**

- 출하계획단계에서 납품기사 등록이 가능
- 아이팩은 수입검사를 진행하지 않음

#### 2-2. 공정라인

- 캡마스터 공정 등록방식 → 자동 입력
- 수주관리 시 샘플 제품 납품처럼 포장이 빠지는 예외상황 처리: 수주승인처리 → 생산계획수립. 단, 포장은 반드시 수동으로 등록
- 각 공정마다 계산에 문제가 있는 경우 생산계획관리를 통해 필요한 공정을 수주에 추가시킬 수 있음

**Q. 반드시 다른 공정보다 압출을 먼저 해야 하는 이유?**
→ 무엇이든 뽑아내야 가공이 가능하기 때문

**Q. 사출과 압출의 방식 차이?**
→ 압출은 용융 수지를 일정한 형상의 압출구로 밀어내 연속적으로 길고 균일한 제품(파이프 등)을 만드는 방식이고, 사출은 용융 수지를 복잡한 형상의 금형에 주입하고 냉각하여 개별 부품을 만드는 방식

**Q. CAPA는 무엇인가?**
→ 생산계획, 생산진행상황 등을 종합한 전체적인 생산능력

- 포장계획 → 다르게 생긴 라벨모양을 분리 저장 (인쇄 이름 지정)
- 포장 공정: 포장 + 조립을 동시에 진행하기 때문에 캡마스터를 확인한 뒤 포장 계획수립
- 포장완료 후 확정납기일 지정 → 이후 출하계획으로 가야 하지만 단계는 분리됨
- 생산량은 실시간 등록, 총생산량은 수주내용으로 계산
- 생산량이 수주량을 못 따라갔을 경우 → 초록색으로 표시

개별 사용자별 UI 배치 설정 저장 가능

- 사용자별로 드래그앤드롭을 사용하여 지정한 UI 모습을 개별 저장할 수 있음
- 단, 컬럼 추가 시 초기화를 피할 수 없음

QC공정별 데이터입력 → 품질검사 항목 저장 (감사 대비용). 입력된 특이사항이 없으면 정상으로 표시됨

구 IPACK과의 차이점: 틀은 비슷하지만 BOM이 추가되어 있음

### 3. 주요 업무 및 고객 요구사항

- 가끔씩 데이터가 이상하게 나오는 부분이 존재함 (생산라인)
  - 예: 실크매수가 0으로 없는데 파기체크됨 — 이전부터 발생하던 문제
- 컬럼명이나 기능수정 요구사항 다수 (상세 미기록)

### 4. 근태 관리 수정 필요 사항

#### 4-1. 근무조별 일근태등록 (WHR314_VW)

1. 입출시간 뒤에 따라붙는 근무시간·외출시간·근태정보가 수정되었을 때 선택사항이 같이 체크될 수 있도록 처리 필요
2. 계산식을 거친 뒤 나오는 값(예: 0.20)이 우측 상단의 분단위 표와 맞지 않음 — 계산식에 들어가기 전, 분단위 시간의 1의 자릿수에서 반올림하여 10분 단위로 일관화하는 과정 필요
3. 근무시간 항목이 근태기에 따라 자동세팅되는 구조를, 사용자가 임의로 수정할 수 있도록 개선 필요 (현재는 프로시저 단에서 `FIRST_IN` ~ `LAST_OUT`을 `BASE_DIS`로 가져오는 방식)
4. 근무시간 수정이 발생했을 때 뒤따르는 근태정보도 함께 수정되도록 처리 필요 — 3번이 해결되어 최초입실/최종퇴실을 임의로 저장할 수 있으면 함께 해결됨 (기존에도 입실·퇴실시간을 컨트롤러에서 가져온 뒤 계산·저장하는 구조라, 연결만 제대로 해주면 됨)

#### 4-2. 근무종합집계, 기간별 근태현황

5. 공통사항으로 특근시간 추가 필요 — 주말 근무 시 전체근무시간과 별도로 특근시간 항목 표시

### ㅇ 추가사항

- 수주처에서 수주를 받을 때 납기일이 자동 저장됨 → 수정사항이 생기면 `DELIVERY2`로 저장 (더 빨라지거나 더 늦어질 때)
- 수주 승인 시 생산계획 시작 (`TPR301`)
- 생산실적은 생산계획을 바탕으로 계산
- 수주품을 만들면 빠진 재고만큼 생산소모자재내역(`TPR601M`)에 저장
- 다 만든 수주품은 생산입고 창고에 입고 (`TPR601LOT`)
- 생산 프로세스: 압출 → 옵셋 → 실크 → 사출 → 캡사출 → 조립
- 다 만들고 나면 출하계획 → 출하
- 수주마감은 출하계획 생성 시 자동으로 처리됨

### 전체 구조

**구매 (사내)**

- 구매요청/확정(`TMA`) → 발주 → 가입고(`TMA`, 트리거) → 품질검사 → 입고(`TMA`) → 매입(거래명세서)
- 입고 시에는 재고 테이블에 쌓이도록 처리 (`TMA922`)

**영업 (사내)**

- 수주(납기일 등, `TSA300`대) → 생산계획(`TPR300`대) → 생산실적(`TPR600`대) → 출하계획(`TSA400`대) → 매출(매출마감, 세금계산서)(`TSA500`대)
- 생산실적: 소모자재, 생산입고 포함
- 제품: 회사에서 만든 것 / 상품: 회사에서 사들인 것
