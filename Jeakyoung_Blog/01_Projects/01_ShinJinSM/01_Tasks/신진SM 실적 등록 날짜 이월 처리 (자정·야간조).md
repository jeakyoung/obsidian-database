# 신진SM 실적 등록 날짜 이월 처리 (자정·야간조)

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | 신진SM 현장 |
| **요청일** | 2026-06-12 (최초 요청), 08-04/08-18 재보고 |
| **대상 시스템** | MES |
| **관련 화면·프로그램** | WPR559(생산실적등록) — 정확한 코드 위치는 이번 조사에서 특정하지 못함 |

> 세 차례에 걸쳐 회의록에 등장하는 같은 계열의 날짜 처리 버그를 한 문서로 묶었다. 조치를 시도했다는 기록은 있으나(06-26), 이후에도 같은 증상이 반복 보고돼(08-04, 08-18) 완전히 해결됐다고 보기 어렵다.

## 🔍 현상 및 원인

야간조(24:00~07:30) 실적을 등록할 때 수불일자를 전날 기준으로 붙여줘야 하는데, 날짜 계산이 꼬여서 실제로는 하루가 아니라 **이틀이 밀리는** 현상이 반복 보고됨.

- **06-12**: 요청사항 5번 — "실적등록시 주간/야간조가 구분됨, 야간조가 24~07시반까진 전날 기준 수불일자로 들어가야 함" (최초 요청)
- **06-26**: "야간조 날짜 자동 계산" 조치는 완료했으나 테스트하지 않음 — "기존에 정상 처리가 어떻게 가능했는지 파악이 안 됨"이라는 메모로 보아, 날짜 전처리 로직이 이미 중복되어 있었고 그 위에 조치를 얹은 상태였음
- **08-04**: "실적을 00시 넘어서 등록 시 이틀이 점프됨"
- **08-18**: "날짜 이월 시 야간반의 경우 2일 전으로 패스되는 경우" — 12일 00:01 시작·종료일을 넣고 저장하면 생산일보번호가 전전날로 찍힘("생산 일보 번호가 싹 다 이틀이 빠지는 중")

세 시점 모두 "이틀 밀림"이라는 동일 증상을 가리키고 있어, 06-26의 조치가 근본 수정이 아니었거나 회귀했을 가능성이 있음. 이번 문서화 과정에서는 실제 날짜 계산 코드(어느 파일의 어느 메서드인지)를 특정하지 못했다 — `ProdSLService.java`/`ProdReportService.java`에 `LocalDate`/`PROD_SDATE_CONVERT` 관련 로직이 있으나, 야간조 판정·이월 계산 지점을 명확히 확인하려면 추가 조사가 필요함.

## 🔧 조치 내용

06-26 시점 조치 내용(회의록 기준, 코드 근거는 확인 못함): 야간조 날짜 자동 계산 로직 추가. 다만 "날짜 전처리 로직이 중복되어있는 부분이 존재"한다는 메모가 남아있어, 이 조치가 기존 로직과 충돌했을 가능성을 배제할 수 없음.

이후 08-04, 08-18에 같은 증상이 재보고된 것으로 보아 **미해결 또는 회귀**로 판단하는 것이 안전함.

## ✅ 검증 및 결과

- [ ] 06-26 조치가 실제로 배포됐는지 확인
- [ ] 야간조 날짜 계산 로직의 정확한 코드 위치 특정 (`ProdSLService.java` / `ProdReportService.java` / 프론트 `WPR559_*.js` 중 어디인지)
- [ ] 08-04/08-18 재보고 건이 06-26 조치 이전 배포판에서 발생한 것인지, 조치 이후에도 재현되는지 구분 필요
- [ ] 회귀 테스트 케이스로 고정(자정 전후 시각 저장 시나리오)
