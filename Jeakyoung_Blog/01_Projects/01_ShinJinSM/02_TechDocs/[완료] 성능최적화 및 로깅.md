# 성능 최적화 및 로깅 구현

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | IPlusMES 전체 (Java 서블릿, `log4j2.xml`) |
| **적용 범위** | 요청 처리 지연(Spike) 파악, SQL 실행 로그 |
| **관련 모듈** | `src/log4j2.xml`, `@Log4j2`(Lombok, 프로젝트 전역 336개 파일에서 사용) |

## 🎯 배경 및 요구사항

[[신진SM 05.28 업무 미팅]](문서 내부 날짜 06-05)에서 논의된 "정상 응답 2-3초, 가끔 10초 이상 튀는 현상"에 대한 원인 파악. 회의 시점 기준 "포장/출하 공정만 로깅 완료, 절단공정은 미완료"로 정리됐던 항목.

## 🏗 설계 및 구현

### 실제 로깅 방식 — Log4j2 + 원본 SQL 문자열 로그

`src/log4j2.xml` 전체:

```xml
<Configuration status="INFO">
    <Appenders>
        <Console name="LogPrint" target="SYSTEM_OUT" />
        <RollingFile name="LogConsole">
            <FileName>C:/logs/Log.log</FileName>
            <FilePattern>C:/logs/%d{yyyy-MM-dd}.log</FilePattern>
            <Policies>
                <TimeBasedTriggeringPolicy interval="1" modulate="true" />
            </Policies>
        </RollingFile>
    </Appenders>
    <Loggers>
        <Root level="INFO" additivity="false">
            <AppenderRef ref="LogPrint" />
            <AppenderRef ref="LogConsole" />
        </Root>
    </Loggers>
</Configuration>
```

콘솔 + 일자별 롤링 파일(`C:/logs/YYYY-MM-DD.log`)로만 구성돼 있다. 구조화 로그(JSON), 메트릭 수집기, 대시보드 연동은 없다.

서블릿들은 Lombok `@Log4j2`를 붙이고(`jvWMA624_01_IUD`, `jvWMA624_01_VERIFY` 등 프로젝트 전역 336개 파일), 요청 처리 직전에 조립된 SQL 전체를 그대로 찍는 패턴이 일관되게 쓰인다:

```java
log.info(sql);   // 예: jvWMA624_01_IUD.service(), jvWMA624_01_VERIFY.service()
```

즉 지금 있는 "성능 관측"은 로그 파일에서 타임스탬프 간격을 grep으로 직접 비교하는 수준이다 — 응답시간을 자동 집계하는 코드는 확인되지 않았다.

> [!warning] SQL 전문이 그대로 로그 파일에 남는다
> `log.info(sql)`은 값이 인라인된(바인드 파라미터가 아닌) 완성된 SQL 문자열을 그대로 남긴다. 여기엔 `@REMARK`, `@OPMAN_CODE` 같은 사용자 입력값도 이스케이프된 채로 포함된다. 디버깅에는 유용하지만 로그 파일(`C:/logs/`)의 접근 권한을 신경 써야 하는 이유이기도 하다.

### 회의에서 제안됐던 것 vs 코드에서 확인된 것

| 항목 | 06.05 미팅 제안 | 코드 확인 결과 |
|---|---|---|
| 길이 절단 공정 로깅 | 시작/계산/재고업데이트/종료 단계별 로그 추가 | 코드베이스에서 절단공정 전용 로깅 추가 흔적을 찾지 못함 — 미착수로 보임 |
| 타임아웃 시 fallback/재시도 | exponential backoff 재시도 | `jvWMA624_01_IUD` 등 관련 서블릿에 재시도 로직 없음 — 예외 시 rollback 후 그대로 실패 응답 |
| 실시간 모니터링 대시보드 | 공정별 응답시간/Spike 건수 시각화 | 해당 기능 없음. 관측 수단은 `C:/logs/*.log` 직접 확인이 전부 |
| 쿼리 최적화(TMA536/TMA922 JOIN) | 진행 중이라고 언급 | 어떤 인덱스/쿼리가 실제로 바뀌었는지 특정할 자료를 찾지 못함 |
