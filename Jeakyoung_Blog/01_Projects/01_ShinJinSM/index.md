# 신진SM ERP · MES

신진SM 자체 ERP/MES(`iPlusERP_SJ`) 운영·개발 지원. MES 개발 담당(POP은 기술지원만). 더존(DZ) ERP와 실시간에 가깝게 데이터를 주고받아야 해서, 이 프로젝트의 기술 이슈 대부분은 "MES/신진ERP ↔ 더존ERP" 두 시스템 사이의 정합성 문제로 수렴한다. 자세한 배경은 [[신진SM 프로젝트 개요]], 타임라인은 [[신진SM 개발 이력]] 참고.

## 기술 스택

| 항목 | 내용/경로 |
|:--|:--|
| **담당 업무** | MES 개발 (POP은 기술지원만) |
| **웹 화면** | Sencha Ext JS — `WebContent/app/**` (MVC: `store`/`view`/`controller`) |
| **서버** | 순수 서블릿(`HttpServlet`) + JDBC, 프레임워크 없음 — `src/com/**` |
| **데이터베이스** | MSSQL `iPlusERP_SJ`, 저장 프로시저 중심(`EXEC SP_...`) |
| **더존 연동** | 별도 JDBC 커넥션(`urlDZ`/`usernameDZ`/`passwordDZ`, web.xml)으로 더존 DB에 직접 연결, `NEOE.*` 스토어드 프로시저 호출 |
| **POP (기술지원만)** | C# WPF, 별도 리포지토리(MES 개발 범위 밖) |
| **로깅** | Lombok `@Log4j2` + `log4j2.xml` (콘솔 + `C:/logs/` 일자별 롤링) — 프레임워크 레벨 APM/구조화 로그는 없음 |

> [!warning] MES 커밋과 더존 반영이 원자적이지 않음
> "MES 저장 확정 → 더존은 best-effort로 반영" 구조라, 더존 쪽 실패가 사용자에게 드러나지 않는다. 포장 중복(5월), 더존 월말 집계 불일치(8월), 더존 문서 중복 생성(9월)이 표면적으로는 다른 문제로 보고됐지만 근본 원인은 같다. 개별 가드(`SP_WPR559_02_IUD_TEST`의 `@ISEXISTS_OUT` 등)와 수동 정정 쿼리로 그때그때 대응해왔고, 아직 근본적으로 묶어서 해결한 적은 없다.

> [!warning] 하드코딩된 사업장/창고 코드가 반복적으로 문제의 근원이 됨
> 재고조정 화면의 사업장 `1000` 하드코딩(06-26 발견, 매핑 검증만 완료·코드 반영 여부는 미확인), 포장 단독 생산 시 창고코드가 `SL_ETC` 분기 없이 무조건 출하창고로 고정되는 버그(`ProdSLService.java`, 2026-09-18 기준 미수정)가 대표 사례. [[신진SM 개발 이력]]의 "결과 및 회고" 참고.

> [!note] 배포 순서 제약이 코드가 아닌 담당자 기억에 의존함
> 도면가공 체계 동기화 작업에서, DB 스크립트 3개를 먼저 적용한 뒤 Java를 배포해야 하는 순서 제약이 있다. 반대로 하면 SP 파라미터 개수 불일치로 저장 기능 전체가 즉시 실패한다.
