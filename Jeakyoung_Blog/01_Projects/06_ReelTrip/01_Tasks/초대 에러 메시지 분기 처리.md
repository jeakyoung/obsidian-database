# 초대 에러 메시지 분기 처리

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | — |
| **요청일** | 2026-09-02 |
| **대상 시스템** | Web |
| **관련 화면·프로그램** | `InviteMemberModal.tsx` |

> 팀스페이스 멤버 초대 실패 시 원인에 관계없이 같은 문구만 뜨던 걸 errorCode 기준으로 나눔

## 🔍 현상 및 원인

`InviteMemberModal`에서 초대 요청이 실패하면 `res.success`가 `false`일 때 무조건 아래 문구 하나만 보여주고 있었음.

```
"초대에 실패했습니다. 사용자 이름을 확인해주세요."
```

문제는 이 메시지가 "사용자를 못 찾은 경우"랑 "이미 멤버인 경우"를 구분 못 한다는 거다. 이미 멤버인 사람을 다시 초대했는데 "이름을 확인해주세요"라고 뜨면 사용자 입장에선 이름을 잘못 쓴 줄 알고 계속 재시도하게 됨. API 쪽(`apiRequest`)이 실패 시 `errorCode`를 같이 내려주고 있었는데 프론트에서 그 값을 안 쓰고 있었던 게 원인.

## 🔧 조치 내용

`handleSubmit`의 `else` 분기를 `errorCode` 기준으로 나눴다.

| 구분 | 대상 | 변경 내용 |
|:--|:--|:--|
| 컴포넌트 | `InviteMemberModal.tsx` | `res.errorCode`로 분기해서 메시지 세분화 |

```typescript
} else if (res.errorCode === "USER_NOT_FOUND") {
  setError("해당 사용자를 찾을 수 없습니다. 사용자 이름을 확인해주세요.");
} else if (res.errorCode === "ALREADY_MEMBER") {
  setError("이미 이 스페이스의 멤버입니다.");
} else {
  setError("초대에 실패했습니다. 잠시 후 다시 시도해주세요.");
}
```

`catch` 블록(네트워크/서버 오류)은 원래대로 "서버 오류가 발생했습니다." 유지 — 이건 errorCode 문제가 아니라서 건드릴 필요 없음.

## ✅ 검증 및 결과

- [x] 존재하지 않는 username 입력 → "해당 사용자를 찾을 수 없습니다." 확인
- [x] 이미 멤버인 username 입력 → "이미 이 스페이스의 멤버입니다." 확인
- [x] 정상 username 입력 → 초대 성공, 모달 닫힘 확인
