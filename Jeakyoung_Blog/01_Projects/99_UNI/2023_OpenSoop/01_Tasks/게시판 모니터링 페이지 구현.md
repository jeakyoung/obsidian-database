# 게시판 모니터링 페이지 구현

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | 김도원 (PL) |
| **요청일** | 2023-05-15 |
| **대상 시스템** | `OpenSoopBack` — `admin.process`/`admin.servlet` 패키지 |
| **관련 화면·프로그램** | `POST /FreeAdminSrv`, `/RequestAdminSrv`, `/MarketAdminSrv`, `/AskAdminSrv` |

> 관리자가 자유·건의·장터·질문 4종 게시판의 글을 한 곳에서 확인할 수 있도록, 게시판별로 목록을 뽑아주는 관리자 전용 API 4개를 구현했다.

## 🔍 현상 및 원인

### 재현 조건

관리자 계정으로도 게시판 내용을 확인하려면 일반 게시판 목록 API를 게시판마다 따로 호출해야 했고, 별도의 모니터링 화면이 없었다.

### 원인

`FreeAdmin`(자유), `RequestAdmin`(건의), `MarketAdmin`(장터), `AskAdmin`(질문) 4개를 각각 새로 만들어야 했는데, 이미 게시판 CRUD용으로 만들어져 있던 `select*BubInfo` 계열 매퍼 쿼리(학교코드·페이지네이션 조건 포함)를 그대로 재사용하는 구조라, Servlet·process 양쪽에서 필요한 파라미터를 빠짐없이 채워 넘기는 게 관건이었다.

## 🔧 조치 내용

| 구분 | 대상 | 변경 내용 |
|:--|:--|:--|
| Servlet | `FreeAdminSrv`/`RequestAdminSrv`/`MarketAdminSrv`/`AskAdminSrv` | `@WebServlet`으로 각각 엔드포인트 등록, 요청 바디를 직접 읽어 `JSONObject.fromObject`로 파싱 후 `NICK_NM`/`MEMB_SC_CD`/`MEMB_DEP_CD`/`TIT`/`CRE_DAT`/`CONT`를 `Map`으로 구성 |
| process | `FreeAdmin`/`RequestAdmin`/`AskAdmin` | 각 게시판의 `uni-account-mapping.select*BubInfo` 쿼리를 `selectList`로 호출, 결과를 `JSONObject`에 담아 반환 |
| process | `MarketAdmin` | 게시글 목록 조회에 더해, 게시글당 여러 장 등록 가능한 이미지 목록(`uni-community-mapping.selectMarkImgInfo`)을 2차원 배열 형태로 함께 조회하도록 확장 (2023-05-19) |
| SQL ID | `uni-community-mapping.xml` | 김도원이 2023-05-23 각 게시판의 실행 SQL id를 `select*BubInfo`로 통일 |

`FreeAdminSrv`에는 학교코드로 결과를 한정 짓기 위한 `SC_CD_IN` 파라미터를 추가로 붙여봤다(2023-05-19).

```java
// FreeAdminSrv.doPost
SccdIn = (jobj.get("SC_CD_IN") == null) ? "" : jobj.get("SC_CD_IN").toString();
param.put("SC_CD_IN", SccdIn);
```

당시 코드 주석에 "입력받을 학교코드 SccdIn추가. 근데 이 방식이 아닌거같다는 생각이 많이듬,," 이라고 남겨뒀는데, 실제로 `FreeAdmin.selectFreeBubInfo` 매퍼 쿼리는 `SC_CD_IN`이 아니라 `MEMB_SC_CD` 파라미터로 학교를 필터링하는 구조였어서 이 값은 쿼리에서 쓰이지 않는다.

## ✅ 검증 및 결과

- [x] 관리자 로그인 후 4개 엔드포인트에 요청 시 각각 응답이 오는 것까지 확인
- [ ] 다건 응답 검증 — `Free/Request/Ask` `Admin` 3개 모두 `for` 루프에서 조회된 각 행의 값을 같은 `JSONObject` 필드에 덮어쓰는 구조라, 게시글이 여러 건이어도 응답에는 마지막 행만 남는다. 자세한 내용은 [\[기술\] 게시판 모니터링 API 응답 구조와 한계](<../03_TechDocs/[기술] 게시판 모니터링 API 응답 구조와 한계.md>)
- [ ] `MarketAdmin`의 이미지 목록(`IMAGE_INFO`) — 조회까지는 되지만 응답 객체(`jobjMain`)에 붙이는 코드가 빠져 있어 실제 응답에는 포함되지 않는다
- [ ] 페이지네이션 파라미터(`REQ_PAGE`/`LIST_UNIT_CNT`) 미검증 — 4개 servlet 모두 이 값을 클라이언트로부터 받지 않는데, 재사용한 매퍼 쿼리는 이 값으로 결과 범위를 제한하므로 실제 목록이 정상적으로 나오는지는 별도 확인이 필요
