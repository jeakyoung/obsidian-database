# 반복주기 구조화 입력(CronBuilder)과 Quartz cron 변환

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | Scheduler-Service 프론트엔드 |
| **적용 범위** | UI/UX · 스케줄 입력 |
| **관련 모듈** | `CronBuilder.tsx`, `cronPatterns.ts` |

> 관리자가 Quartz cron 문법을 몰라도 스케줄 주기를 등록할 수 있도록, 년/월/일/시/분을 알람 설정하듯 구조화된 입력으로 받아 cron 문자열로 변환하는 컴포넌트.

## 🎯 배경 및 요구사항

사용자 직접 요청: "스케줄 설정 시에 크론 표현식으로 날짜를 받도록 하지 말고 년월일시분으로 받은 뒤에 서비스에서 크론으로 변환시켜, 일별·월별·년별·특정시간대와 같이 알람설정하듯 특정주기로 특정일자에 돌아가는 것을 직관적으로 볼 수 있게". "특정시간대"는 요일반복/간격반복/1회성 특정일시 3가지를 모두 지원해야 한다고 확정됐다.

## 🏗 설계 및 구현

### 구조 — 6가지 반복 유형

Quartz cron 필드 순서: `초 분 시 일(day-of-month) 월 요일(day-of-week) [년]`. day-of-month/day-of-week 중 하나는 반드시 `?`.

| # | 유형 | 입력 필드 | 생성 규칙(예) |
|:--|:--|:--|:--|
| 1 | 일별 | 시, 분 | `0 {mm} {HH} * * ?` |
| 2 | 월별 | 일(1~31), 시, 분 | `0 {mm} {HH} {일} * ?` |
| 3 | 년별 | 월, 일, 시, 분 | `0 {mm} {HH} {일} {월} ?` |
| 4 | 요일반복 | 요일 다중선택, 시, 분 | `0 {mm} {HH} ? * {MON,WED,FRI}` |
| 5 | 간격반복 | 시작/종료 시각, 간격값, 간격단위, 요일필터 | `0 {시작분}/{N} {시작시}-{종료시} ? * {요일}` (레거시 `HourSchedulerTask` 패턴과 동일 개념) |
| 6 | 1회성 특정일시 | 연-월-일, 시, 분 | `0 {mm} {HH} {일} {월} ? {연}` — Quartz의 선택적 7번째 "년" 필드로 그 순간 1회만 매칭 |

### 변환은 프론트엔드에서, 검증은 백엔드에서 (이중 체크)

**구조화 입력 ↔ cron 변환은 TypeScript(프론트)에서 수행**하고, 백엔드는 최종 저장 시 `CronExpression.isValidExpression`으로 **검증만** 한다.

- 6가지 패턴 모두 필드 위치가 고정된 결정적 문자열 생성이라 Quartz 라이브러리 없이도 TS로 정확히 만들 수 있다.
- 매 입력 변경마다 백엔드 왕복을 요구하면 UX가 나빠지고, 즉시 미리보기(생성된 cron/다음 실행 예시)를 보여줄 수 없다.
- 프론트 로직에 버그가 있어도 백엔드 검증이 안전망이 된다 — 잘못된 cron이 DB에 저장되는 일은 없음.
- 대안으로 백엔드 변환 엔드포인트를 두는 안도 검토했지만, 생성 규칙이 결정적이라 이득이 적어 기각.

### 역변환 — "고급: 직접 cron 입력"으로 폴백

스케줄 수정 시 저장된 cron을 6가지 생성 규칙의 "역" 패턴으로 매칭을 시도한다. 매칭되면 그 유형의 구조화 폼을 복원하고, 매칭 안 되면(레거시 임포트, 수동 편집 등) **"고급: 직접 cron 입력" 모드로 폴백** — 이 모드는 항상 선택 가능하게 남겨둔다(완전히 막지 않음).

> [!warning] 파일명 대소문자 충돌
> 로직 파일을 처음에 `cronBuilder.ts`로 만들었다가 `CronBuilder.tsx`와 대소문자만 다른 이름이라 Windows(대소문자 비구분 파일시스템)에서 `tsc`가 "파일명이 대소문자만 다름" 컴파일 에러를 냄 → `cronPatterns.ts`로 즉시 리네임.

## ✅ 검증

- [x] 6가지 생성 함수 각각 대표값 확인
- [x] "생성 → 역변환 → 원래 구조화 값과 일치" 왕복 테스트(간격반복의 경계케이스 포함)
- [x] 패턴에 안 맞는 임의 cron(`"0 0 12 1/2 * ?"` 등)에 역변환이 `null`(CUSTOM) 반환 → 고급모드 폴백 확인
- [x] 실제 백엔드에 6가지 패턴 대표값을 전송해 `CronExpression.isValidExpression` 검증 통과(엔드투엔드)
