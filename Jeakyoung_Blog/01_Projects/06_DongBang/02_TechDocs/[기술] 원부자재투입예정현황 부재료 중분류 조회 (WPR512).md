# 원부자재투입예정현황 부재료 중분류 조회 (WPR512)

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | iPlusERP (`iPlusERP_DONGBANG`) |
| **적용 범위** | 생산관리 - 원부자재투입예정현황(WPR512) |
| **관련 모듈** | `jvWPR512_01_LIST.java`, `WPR512_VW.js`, `WPR512_CT.js`, `SP_WPR512_01_LIST`, `jvWCO312_03_COMBO.java` |

> 자재구분 콤보에서 "부재료"를 선택했을 때만 중분류 콤보를 활성화하고, 부재료 마스터 등록 화면과 같은 콤보 소스를 재사용하는 작업.

## 🎯 배경 및 요구사항

원부자재투입예정현황 조회조건에 자재구분(`cbo_MatGbn`)이 있는데, 이 중 부재료(코드 `1120902`)를 선택했을 때만 자재 중분류(`cbo_midItem`)를 추가로 고를 수 있게 해달라는 요구사항. 중분류 콤보에 들어갈 항목 목록은 새로 만들지 않고 기준정보 - 자재관리 - 부재료 마스터 등록 화면이 쓰는 콤보(`jvWCO312_03_COMBO`)를 그대로 재사용한다.

## 🏗 설계 및 구현

### 자재구분 콤보 (`cbo_MatGbn`)

`WPR512_VW.js:139~151`:

```js
{
    itemId: 'cbo_MatGbn',
    fieldLabel: '자재구분',
    displayField: 'CODE_NAME',
    valueField: 'CODE_ID',
    value: '1120802',
    bind: { store: '{cboStore_MatGbn}' },
    editable: false,
}
```

기본값은 `1120802`이고, 부재료를 뜻하는 값은 `1120902`다(둘 다 `cboStore_MatGbn`에서 오는 코드값 — 각 코드가 실제로 무엇을 의미하는지 전체 목록은 스토어 정의 밖이라 미확인, `1120902`=부재료라는 매핑은 원본 작업노트와 아래 `onSetMidCombo` 로직에서 역으로 확인된 것).

### 중분류 콤보 활성화/비활성화 — `onSetMidCombo()`

`WPR512_CT.js:54~76`:

```js
onSetMidCombo: function () {
    var me = this;
    var store = this.getViewModel().getStore('cboStore_MidGbn');
    var matGbn = this.getView().down('#cbo_MatGbn').getValue();

    if (matGbn == '1120902') {
        me.getView().down('#cbo_midItem').setReadOnly(false);
        store.load({
            params: { ITEM_KIND1: '016' },
            callback: function (records, op, success) {},
        });
    } else if (matGbn != '1120902') {
        me.getView().down('#cbo_midItem').setValue(null);
        me.getView().down('#cbo_midItem').setReadOnly(true);
    }
},
```

> [!note] 원본 작업노트는 "disabled"라고 적었지만 실제 코드는 readOnly
> 원본 작업노트에는 "value만이 아니라 disabled도 CT에서 내려줄 수 있다"는 서술이 있었지만, 최종 코드는 `setDisabled`가 아니라 `setReadOnly`를 쓴다. 노트에 있던 별도 메모("disabled에선 툴팁이 동작하지 않아 readOnly로 바꿨다")와 일치하는 결과 — 즉 처음엔 `disabled`로 구현했다가 툴팁 문제로 `readOnly`로 바꾼 이력으로 보이며, 지금 코드베이스에 남은 최종 형태는 `readOnly` 쪽이다.

`cbo_MatGbn`의 `change`/`select` 이벤트에서 `onSetMidCombo()`를 호출하도록 연결되어 있다(`WPR512_CT.js:380~384`).

### 서버 - `jvWPR512_01_LIST.java`

`SP_WPR512_01_LIST`를 13개 파라미터로 호출한다:

```java
String sql = "EXEC SP_WPR512_01_LIST "
        + "'" + FACTORY_CODE + "'"
        + ",'" + PROD_TO_DATE + "'"
        + ",'" + PROD_FROM_DATE + "'"
        + ",'" + PROD_DEPT + "'"
        + ",'" + ITEM_NAME + "'"
        + ",'" + MATERIAL_NAME + "'"
        + ",'" + MATERIAL_CODE + "'"
        + ",'" + MIX_WORKDT_FLAG + "'"
        + ",'" + MAT_FLAG + "'"
        + ",'" + OPMAN_CODE + "'"
        + ",'" + MAT_EXP_FLAG + "'"
        + ",'" + NEW_MATREIAL_CODE + "'"
        + ",'" + MID_ITEM_CODE + "'";
```

> [!warning] 변수명과 실제 의미가 뒤바뀌어 있음
> `jvWPR512_01_LIST.java:48~49`:
> ```java
> String PROD_TO_DATE = request.getParameter("PROD_DATE_FROM")...
> String PROD_FROM_DATE = request.getParameter("PROD_DATE_TO")...
> ```
> 변수명 `PROD_TO_DATE`가 실제로는 요청 파라미터 `PROD_DATE_FROM`(시작일) 값을 담고, `PROD_FROM_DATE`가 `PROD_DATE_TO`(종료일) 값을 담는다 — 변수명이 실제 의미와 반대로 붙어 있다. SP 호출 시 `PROD_TO_DATE, PROD_FROM_DATE` 순서 그대로 넘어가므로 SP 파라미터 순서만 맞으면 동작 자체에는 문제가 없지만, 이 코드를 나중에 다시 읽을 때 변수명만 보고 판단하면 날짜 방향을 반대로 착각하기 쉽다.

`MAT_FLAG`가 실제 서버 파라미터명이며, `WPR512_CT.js`에서 `cbo_MatGbn`의 값을 그대로 실어 보낸다(`MAT_FLAG: me.getView().down('#cbo_MatGbn').getValue() ? ... : ''`, `WPR512_CT.js:176` 등). 원본 작업노트의 "MAT_GBN"이라는 파라미터명은 실제 서버 파라미터명이 아니라 화면 필드 itemId(`cbo_MatGbn`)를 혼동해서 적은 것으로 보인다. `MID_ITEM_CODE`는 `cbo_midItem`의 값을 그대로 실어 보낸다.

### 콤보 소스 재사용 — `jvWCO312_03_COMBO`

`src/com/CO/WCO310/jvWCO312_03_COMBO.java`가 존재함을 확인했다. 부재료 마스터 등록 화면(WCO312)이 쓰는 콤보 조회 서블릿을 원부자재투입예정현황(WPR512)의 중분류 콤보에서도 `ITEM_KIND1='016'` 조건으로 그대로 재사용하는 구조 — 새 콤보를 만들지 않고 기존 화면의 데이터 소스를 공유한 케이스.
