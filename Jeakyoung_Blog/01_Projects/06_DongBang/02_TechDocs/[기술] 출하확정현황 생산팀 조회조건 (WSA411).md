# 출하확정현황 생산팀 조회조건 (WSA411)

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | iPlusERP (`iPlusERP_DONGBANG`) |
| **적용 범위** | 영업관리 - 출하관리 - 출하확정현황/납품계획현황(WSA411) |
| **관련 모듈** | `jvWSA411_01_LIST.java`, `WSA411_VW.js`, `WSA411_CT.js`, `SP_WSA411_01_LIST` |

> 출하확정현황 조회조건에 생산팀 필터를 추가해달라는 요청 건(요청 사항 관리번호 444번).

## 🎯 배경 및 요구사항

영업관리 - 출하관리 - 출하확정현황(납품계획현황) 조회 화면에 생산팀 조회조건이 없어서, 생산팀 기준으로 좁혀서 보고 싶을 때 불가능했다. 공통코드(`TCO101`, `CODE_ID1='134'`)에 등록된 생산팀 코드를 콤보로 노출하고, 이 값으로 조회조건을 추가하는 작업.

## 🏗 설계 및 구현

### 조회조건 콤보 (`combo_03`)

`WSA411_CT.js`의 조회 파라미터 구성부(약 100~106행)에서 `SearchDep`이 화면의 `combo_03` 콤보 값을 그대로 담아 전송된다:

```js
{
    FACTORY, dtFromdate, dtTodate,
    SearchOrdCus: me.getView().down('#SearchOrdCus').getValue(),
    SearchItem: me.getView().down('#SearchItem').getValue(),
    SearchDep: me.getView().down('#combo_03').getValue(),
    OutputGbnFlag: ...,
    ViewFlag: ...,
    OPMAN_CODE: gUserId,
}
```

### 서버 - `jvWSA411_01_LIST.java`

`SP_WSA411_01_LIST`를 9개 파라미터로 호출한다:

```java
String sql = "EXEC SP_WSA411_01_LIST "
        + "'" + FACTORY + "'"
        + ",'" + dtFromdate + "'"
        + ",'" + dtTodate + "'"
        + ",'" + SearchOrdCus + "'"
        + ",'" + SearchItem + "'"
        + ",'" + SearchDep + "'"
        + ",'" + OutputGbnFlag + "'"
        + ",'" + ViewFlag + "'"
        + ",'" + OPMAN_CODE + "'";
```

`SearchDep`이 클라이언트 콤보 값부터 SP 파라미터까지 그대로 이어지는 것을 확인했다.

> [!note] SP 내부 조인 로직은 원본 작업노트 기준, DB 재검증 안 됨
> 원본 작업노트에는 `SP_WSA411_01_LIST` 내부에서 `TCO101`(공통코드, `CODE_ID1='134'`=생산팀), `TCO403`(자재-품목 매핑), `TPR504`(작업지시) 등을 조인해서 생산팀 코드를 끌어오는 SQL 스니펫이 남아 있었다:
> ```sql
> LEFT JOIN TPR504 B3 ON B.FACTORY_CODE = B3.FACTORY_CODE AND B.WORKDT_NO = B3.WORKDT_NO
> LEFT JOIN TCO101 B4 ON B3.PROD_DEPT_CODE = B4.CODE_ID2 AND B4.CODE_ID1 = '134'
> AND (@SearchDep = '' OR (@SearchDep <> '' AND B4.CODE_ID2 = @SearchDep))
> ```
> 이 스니펫은 작업 당시 개발자가 직접 작성/캡처한 것으로 신뢰도는 있지만, SP 소스 자체가 DB 안에만 있어 이 코드베이스로는 재검증이 불가능하다 — "당시 기준"으로만 취급한다. 작업 노트에는 "당시 테스트 DB에는 생산팀 001(생산팀)로 구성된 테스트 데이터만 있었다"는 제약사항도 함께 남아 있다.
>
> 또한 원본 노트에는 `TCO101`의 항목코드(`CODE_ID1='134'`) 데이터가 전부 `DELETE_FLAG=1`로 되어 있어 콤보에 아무 항목도 안 뜨는 문제가 있었고, `DELETE_FLAG`를 0으로 되돌려 항목을 재생성했다는 기록이 있다 — 이건 데이터 정정 작업이라 코드 변경 이력으로는 남지 않는다.

## ✅ 검증

- [x] `combo_03`(생산팀) → `SearchDep` 파라미터 → `SP_WSA411_01_LIST` 호출까지 이어지는 흐름 확인
- [ ] SP 내부에서 `TCO101`/`TCO403`/`TPR504` 조인 및 `@SearchDep` 필터링 방식 — DB 접근 없이 미확인, 원본 작업노트 기준으로만 기록
- [ ] 조회조건 미선택 시 전체 조회, 선택 시 필터링되는 동작 — 재현 테스트 안 됨(화면 스크린샷만 원본 노트에 남아 있음)
