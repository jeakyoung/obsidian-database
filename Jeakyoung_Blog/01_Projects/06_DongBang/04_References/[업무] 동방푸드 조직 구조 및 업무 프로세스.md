# 동방푸드 조직 구조 및 업무 프로세스

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **회사** | 동방푸드마스타(식품 납품업체, 소스 제작) / 동방MS(Meat Solution, 육류가공 — 별도 인수 법인) |
| **레시피 제공** | CJ |
| **ERP** | iPlusERP (동방푸드마스타·동방MS 공통, `iPlusERP_DONGBANG`) |

> 원본 작업노트("동방푸드 업무 프로세스")의 조직/프로세스 설명을 정리한 문서. 조직 구조와 업무 흐름 자체는 원본 노트(구술 정리) 기준이고, 화면/테이블 코드만 코드베이스로 재검증했다.

## 🏢 조직 구조 (원본 노트 기준, 코드베이스로 검증 불가)

- **영업** — 주문, 납품
- **연구소** — 개발(레시피 재설계), BOM(Bill of Material) 관리 — 제품 제조에 필요한 원자재 소모 정보
- **생산**
  - 1팀 — 분말, 시즈닝
  - 2팀 — 소스 + 드레싱
  - 3팀 — 소스
  - 건더기팀 — 예: 후라야게
- **자재(SCM팀)**
- **품질**

이 조직 분류(1~3팀, 건더기팀 등)는 원본 노트의 구술 정리이며, 코드베이스에서 확인 가능한 대상은 공통코드 `CODE_ID1='134'`(생산팀 구분 코드)뿐이다 — [\[기술\] 출하확정현황 생산팀 조회조건 (WSA411)](<../02_TechDocs/[기술] 출하확정현황 생산팀 조회조건 (WSA411).md>) 참고. 각 팀 코드값과 팀명의 정확한 매핑은 미확인.

## 🏗 업무 프로세스 흐름

원본 노트에 정리된 흐름과, 코드베이스에서 실제로 확인되는 화면/테이블 코드 대응:

| 단계 | 원본 노트 상 테이블(T코드) | 코드베이스 확인 결과 |
|:--|:--|:--|
| 수주 | TSA307(메인) / TSA308(상세) | `TSA307`은 실제 테이블명으로 확인됨(`WSA311_CT.js`의 `TABLE : 'TSA307'` 주석, `jvStoreFunction_INSERT_TSA307DD` 서블릿) — 해당 테이블을 다루는 화면은 `WSA311_VW.js`(수주관리로 추정)로 보임. `TSA308`은 코드베이스에서 직접 참조를 찾지 못함 — 미확인 |
| 작업지시 | TPR504 | `SP_TPR504_COPY` 호출 확인(`jvWPR302_WIN02_01_IUD.java`), 화면은 `WPR504_VW.js` 존재 확인 |
| 계량 | TPR602 | 코드베이스에서 직접 참조를 찾지 못함 — 미확인 |
| 생산실적 | TPR601 | `jvWPR503_01_IUD.java` 주석에 `TPR601` 언급 확인, 화면 코드까지는 특정 못함 — 부분 확인 |
| 출하(계획/확정) | TSA407(계획) / TSA407L(확정) | 코드베이스에서 직접 참조를 찾지 못함 — 미확인. 참고로 출하확정현황 화면은 `WSA411`([\[기술\] 출하확정현황 생산팀 조회조건 (WSA411)](<../02_TechDocs/[기술] 출하확정현황 생산팀 조회조건 (WSA411).md>)) |
| 거래명세서 | TSA402 / TSA403 / TSA403L | `TSA402` 관련 로직이 `WSA402_CT.js`(`onLfn_TDO704_TSA402A_IUD` 등)에서 확인됨 — 화면은 `WSA402_VW.js`로 추정. `TSA403`은 미확인 |
| 매출마감 | — | 미확인 |
| 세금계산서 | TSA501 / TSA501A | 코드베이스에서 직접 참조를 찾지 못함 — 미확인 |

> [!note] T코드=테이블명, W코드=화면(View/Controller) ID
> 이 ERP의 명명 규칙상 `T`로 시작하는 코드(TSA307, TPR504 등)는 DB 테이블명이고, `W`로 시작하는 코드(WSA311, WPR504, WMA202 등)는 Sencha 화면(View/Controller/Store) ID다. 둘은 보통 같은 숫자 접미사를 공유하지만(`TPR504` ↔ `WPR504`) 항상 1:1은 아니라서(`TSA402` 계열이 `WSA402`에 대응하는지는 화면 내부 로직 확인 수준이지 화면 타이틀까지 직접 확인한 것은 아님), 이 문서의 대응관계는 "코드베이스에서 grep으로 찾은 근거가 있는지" 기준으로 표시했다.

원본 노트에 있던 나머지 서술(배송일-생산일-수주일 관계, POC 파일럿 사업으로 생물학적 검사기간 단축, AI Agent 활용 계획 등)은 프로세스/계획에 대한 메모이지 코드베이스로 검증할 수 있는 대상이 아니라서 그대로 미확인으로 남긴다.

## ⚠️ 주의사항

- 이 문서의 조직 구조·업무 흐름 서술은 원본 작업노트(구술 정리) 그대로이며, 코드베이스 검증은 표에 명시한 테이블/화면 코드 존재 여부까지만이다.
- SP 내부 로직(각 테이블 간 실제 흐름을 구현한 SQL)은 DB 접근 없이는 검증 불가.
