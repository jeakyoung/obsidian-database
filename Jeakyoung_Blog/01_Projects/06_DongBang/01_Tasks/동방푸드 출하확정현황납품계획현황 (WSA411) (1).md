## 🔧 조치 내용

![[image 113.png]]

공통코드 `TCO101`에서 생산팀 코드를 조회:

```sql
SELECT * FROM TCO101
WHERE CODE_ID1 = '134'
-- 조회조건 CODE_ID1 134, CODE_ID2 001~004, 표시값은 CODE_NAME_FULL
```

![[image 114.png]]

134에 대한 항목코드의 `DELETE_FLAG`가 전부 1(삭제됨)로 되어 있어서, 콤보에 아무 항목도 뜨지 않았다 — 0으로 되돌려 항목을 재생성했다(데이터 정정 작업이라 코드 변경 이력으로는 안 남음).

조회조건 콤보 값은 `@SearchDep VARCHAR(3)` 파라미터로 SP에 넘겨받는다. 아래는 원본 메모에 남아있는 SP 내부 조인/WHERE절 스니펫이다 — 작업 당시 캡처한 것으로 신뢰도는 있으나, SP 소스 자체가 DB 안에만 있어 이 코드베이스로는 재검증 불가(미확인, 당시 기준으로만 취급). 클라이언트→서버까지의 `SearchDep` 파라미터 전달 자체는 코드로 재확인했다 — [\[기술\] 출하확정현황 생산팀 조회조건 (WSA411)](<../02_TechDocs/[기술] 출하확정현황 생산팀 조회조건 (WSA411).md>) 참고.

```sql
JOIN TCO403 A1
				ON	A.ITEM_CODE = A1.MATERIAL_CODE
					LEFT JOIN TCO101 A22
					ON A1.STORE_METHOD = A22.CODE_ID2 
					AND A22.CODE_ID1 = '161'				

					LEFT JOIN TCO101 A134
					ON A1.PROD_DEPT = A134.CODE_ID2
					AND A134.CODE_ID1 = '134'	
```

```sql
LEFT JOIN TPR504 B3
				ON B.FACTORY_CODE = B3.FACTORY_CODE
				AND B.WORKDT_NO = B3.WORKDT_NO
				LEFT JOIN TCO101 B4
				ON B3.PROD_DEPT_CODE = B4.CODE_ID2
				AND B4.CODE_ID1 = '134'	
```

CODE_ID2 조인절 위에, WHERE절 검색조건 추가:

```sql
AND (@SearchDep = '' OR (@SearchDep <> '' AND B4.CODE_ID2 = @SearchDep)) -- 생산팀에 따른 조회조건 추가
```

테스트용 DB에는 생산팀 001(생산팀)로 구성된 테스트 데이터만 있어서, 다른 생산팀 값으로는 실제 필터링 결과를 확인하지 못했다.

## ✅ 검증 및 결과

- `combo_03`(생산팀) 선택 → `SearchDep` 파라미터 → `SP_WSA411_01_LIST` 호출까지 이어지는 흐름, 코드로 확인 완료
- SP 내부의 `TCO101`/`TCO403`/`TPR504` 조인과 `@SearchDep` 필터링은 원본 메모 기준으로만 기록, DB 접근 없이 미확인
- 조회조건 선택/미선택 시 결과 차이는 당시 스크린샷(`image 115/116.png`, 현재 유실)으로만 확인된 상태이고, 재현 테스트는 안 됨
