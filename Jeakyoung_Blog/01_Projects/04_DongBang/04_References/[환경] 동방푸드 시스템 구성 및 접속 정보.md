# 동방푸드 시스템 구성 및 접속 정보

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **프론트엔드** | Sencha Ext JS (`iPlusERP/WebContent/app/**`) |
| **백엔드** | 순수 서블릿(`GenericServlet`) + JDBC, 프레임워크 없음 (`iPlusERP/src/com/**`) |
| **데이터베이스** | MSSQL, 저장 프로시저 중심(`EXEC SP_...`) |
| **개발 환경** | Eclipse(Enterprise) + Tomcat 9.0 (로컬), SVN |

## ⚙️ 환경 및 전제

### SVN

작업 디렉토리(`E:\ajk\dev\sencha\DONGBANG`)는 `.svn`으로 관리되는 워킹카피다. `svn info` 기준 실제 저장소 경로:

```
Repository Root: https://218.155.74.6/svn/DONGBANG
```

원본 작업노트에 언급된 `https://218.155.74.6/svn/DONGBANG_MS/`(동방MS용으로 추정)는 이 워킹카피의 `svn info` 결과에는 나타나지 않는다 — 별도 저장소로 존재할 가능성이 있으나 이 워킹카피에서는 확인 불가.

이 SVN 워킹카피 안에 `iPlusERP`(동방푸드마스타 ERP 본체) 외에도 `iPlusPOP`, `iPlusSCM`, `iPlusCustOrder`, `iPlusSampleOrder`, `iPlusTV`, `iPlusTVAdmin`, `DIDBASIC`, `MatalInspector`, `VBSource` 등 여러 개의 별도 Eclipse 프로젝트가 같이 체크아웃되어 있다. 동방푸드 ERP 화면(WMA202, WRD203, WSA411, WPR512 등)의 소스는 전부 `iPlusERP` 안에 있다.

### 로컬 개발 서버

`Servers/Tomcat v9.0 Server at localhost-config/server.xml` 기준, 로컬 Tomcat 9.0의 HTTP 커넥터는 `8080` 포트로 설정되어 있다:

```xml
<Connector connectionTimeout="20000" port="8080" protocol="HTTP/1.1" redirectPort="8443"/>
```

원본 작업노트의 "이클립스에서 8080접속?"이라는 메모가 실제 설정과 일치함을 확인했다.

### 운영 접속 주소

> [!note] 접속 URL은 원본 작업노트에서 마스킹된 채로 남아 있음
> 동방푸드마스타(ERP)와 동방MS 접속 URL은 원본 노트에 `REDACTED_DOMAIN`으로 마스킹되어 기록되어 있었다. 이 문서에서도 마스킹을 그대로 유지한다 — 실제 도메인을 추측하거나 복원하지 않는다.

| 시스템 | 접속 | 비고 |
|:--|:--|:--|
| 동방푸드마스타 (ERP) | `http://REDACTED_DOMAIN/`(원본 노트 기준) | |
| 동방MS (POP) | `http://REDACTED_DOMAIN/pop`(원본 노트 기준) → 운영 | POP는 출고 프로세스 담당 |

### iPlusERP ↔ POP 관계

원본 작업노트: "POP → 출고", "iplusERP를 POP로 이동 → 센차"라는 메모가 있다. 즉 출고 관련 화면/프로세스 일부가 iPlusERP에서 POP(`iPlusPOP` 프로젝트로 추정) 쪽으로 이관되었거나, POP가 출고를 전담하는 구조로 보인다 — 구체적으로 어떤 화면/기능이 이관되었는지는 원본 노트에 명시되어 있지 않아 미확인. `iPlusPOP`도 같은 SVN 워킹카피 안에 별도 Eclipse 프로젝트로 존재한다.

## ⚠️ 주의사항

1. SP 소스 자체(저장 프로시저 본문)는 DB 안에만 존재하고 이 SVN 워킹카피에는 포함되어 있지 않다 — SP 이름/파라미터는 이를 호출하는 Java 서블릿 코드로 검증 가능하지만, SP 내부 로직은 DB 접근 없이 검증 불가.
2. 접속 URL/계정 정보는 마스킹된 원본 그대로 유지한다.
