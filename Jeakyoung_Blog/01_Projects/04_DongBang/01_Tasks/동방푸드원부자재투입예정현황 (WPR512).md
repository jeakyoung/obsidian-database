## 🔍 현상 및 원인

원부자재투입예정현황(WPR512) 조회조건의 자재구분 콤보(`cbo_MatGbn`)에서 "부재료"(코드 `1120902`)를 선택했을 때만 자재 중분류 콤보(`cbo_midItem`)를 추가로 선택할 수 있게 해달라는 요구사항. 자재 대분류 체계는 액상/분말/건조건더기/야채류/유지류/고형물/부재료/기타/향료·색소 등으로 구성되어 있고(부재료 하위에 PD/PE/PK/박스/캡/필름/파우치/라벨/비닐/용기/기타 등 포장재 세분류가 존재), 부재료를 선택했을 때만 이 세분류(중분류)를 고를 수 있어야 한다.

## 🔧 조치 내용

새 콤보를 만들지 않고, 기준정보 - 자재관리 - 부재료 마스터 등록 화면이 쓰던 콤보 조회 서블릿(`jvWCO312_03_COMBO`)을 재사용했다. `ITEM_KIND1='016'`(대분류 자재구분 코드) 조건으로 고정해서 콤보 데이터만 가져오고, 선택된 값은 `MID_ITEM_CODE` 파라미터로 `SP_WPR512_01_LIST` 조회조건에 실어 보낸다.

### ㅇ 요청사항

![[동방_430_요청사항.png]]

자재 대분류 코드(1~9): 액상/분말/건조건더기/야채류/유지류/고형물/부재료/기타/향료·색소. 부재료 세분류 코드(PD/PE/PK, B박스, C캡, F필름, P파우치, L라벨, V비닐, Y용기, K기타).

`D.MATERIAL_CODE_ALTER + D.MATERIAL_CODE = NEW_MATERIAL_CODE` 조합, `TCO403.MATERIAL_FLAG`(자재구분정보)로 부재료 여부 필터링, `TCO403.ITEM_KIND2` 비교 — 원본 메모 기준, SP/테이블 데이터 내부 로직이라 코드베이스로 재검증 불가(미확인).

`SP_WCO313_01_IUD`는 원본 메모에 "운영에만 존재함"이라고 기록되어 있음 — DB 객체라 검증 불가.

작업부: BE `jvWPR512_01_LIST`, SQL `SP_WPR512_01_LIST`, 콤보 소스 `jvWCO312_03_COMBO`(`ITEM_KIND1='016'` 고정).

아래는 원본 메모에 남아있던 코드 스니펫 — 초기 구현(`setDisabled`)과 최종 구현(`setReadOnly`)의 차이를 보여준다. 최종 코드베이스 확인 결과는 [\[기술\] 원부자재투입예정현황 부재료 중분류 조회 (WPR512)](<../02_TechDocs/[기술] 원부자재투입예정현황 부재료 중분류 조회 (WPR512).md>) 참고.

```javascript
else if (matGbn != '1120902') {
            me.getView().down('#cbo_midItem').setValue(null);
            me.getView().down('#cbo_midItem').setDisabled(true);
```

초기 구현은 value뿐 아니라 disabled 상태도 CT(컨트롤러)에서 내려주는 방식이었다.

```javascript
 listeners: {
               afterrender: function (cmp) {
               Ext.create('Ext.tip.ToolTip', {
                  target: cmp.getEl(),
                  html: '부재료 선택시 구분이 활성화됩니다.',
                });
              },
            },
```

부재료 선택 안내용 툴팁을 붙였는데, disabled 상태에서는 툴팁이 동작하지 않아서 최종적으로 readOnly 방식으로 바꿨다.

```javascript
onSetMidCombo: function () {
        var me = this;

        var store = this.getViewModel().getStore('cboStore_MidGbn');
        var matGbn = this.getView().down('#cbo_MatGbn').getValue();

        if (matGbn == '1120902') {
            me.getView().down('#cbo_midItem').setReadOnly(false);
            store.load({
                params: {
                    ITEM_KIND1: '016',
                },
                callback: function (records, op, success) {
                    if (success) {
                    }
                },
            });
        } else if (matGbn != '1120902') {
            me.getView().down('#cbo_midItem').setValue(null);
            me.getView().down('#cbo_midItem').setReadOnly(true);
        }
    },
```

최종적으로 적용된 `onSetMidCombo()` 구현 — readOnly 방식.

## ✅ 검증 및 결과

- `cbo_MatGbn == '1120902'`일 때만 `cbo_midItem`이 활성화(readOnly 해제)되고 `ITEM_KIND1='016'`으로 콤보가 로드되는 흐름, 코드로 확인 완료
- `jvWPR512_01_LIST.java`의 `SP_WPR512_01_LIST` 호출 파라미터 13개 확인 — 검증 과정에서 `PROD_TO_DATE`/`PROD_FROM_DATE` 변수명이 실제 의미(요청 파라미터 `PROD_DATE_FROM`/`_TO`)와 반대로 붙어있는 것을 추가로 발견함(기능 동작에는 영향 없음, 상세는 TechDocs 참고)
- SP 내부에서 `MAT_FLAG`/`MID_ITEM_CODE`를 실제로 어떻게 필터링하는지는 DB 접근 없이 미확인
- [[동방푸드 DB 재반영, 테스트 (WRD203, WPR512, WMA202)]]에 재반영 기록 있음(구체적 테스트 결과는 해당 문서에 미기재)
