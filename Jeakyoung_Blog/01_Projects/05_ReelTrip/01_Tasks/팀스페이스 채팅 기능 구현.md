# 팀스페이스 채팅 기능 구현

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | — |
| **요청일** | 2026-06-30 |
| **대상 시스템** | Web + API |
| **관련 화면·프로그램** | `ChatScreen.tsx`, `chat` 패키지 (Spring) |

> WebSocket 안 쓰고 5초 폴링으로 채팅을 구현한 이유

## 🔍 현상 및 원인

`ChatScreen`이 `DUMMY_MESSAGES`로 채팅 UI만 보여주고 있었고, 팀스페이스별 실시간 채팅(1 스페이스 = 1 채팅방)을 실제로 붙여야 했다. WebSocket으로 진짜 실시간을 구현할 수도 있었지만, 이 시점에 Mobile/Web 어느 쪽에도 WebSocket 인프라가 없고 배포 환경(Railway)에서 커넥션을 오래 유지하는 것도 부담이라, 5초 폴링으로 방향을 잡았다.

## 🔧 조치 내용

`Notification` 레이어 패턴을 그대로 따라 `Message` 레이어를 새로 만들었다 — 이미 검증된 구조를 재사용하는 쪽이 새 패턴을 고민하는 것보다 빠르다고 판단.

| 구분 | 대상 | 변경 내용 |
|:--|:--|:--|
| DB | `V7__add_chat_messages.sql` | `chat_messages` 테이블 |
| 백엔드 | `chat` 패키지 | `Message`(model), `MessageResponse`/`SendMessageRequest`(dto), `MessageMapper`, `MessageService(Impl)`, `MessageController` |
| 백엔드 | `SecurityConfig` | `/api/messages/**` 인증 추가 |
| 프론트 | `domains/chat/api.ts` | `listMessages`, `sendMessage` |
| 프론트 | `ChatScreen.tsx` | `DUMMY_MESSAGES` 제거, 5초 폴링(`setInterval` + `clearInterval`)으로 교체 |

```typescript
const timer = setInterval(fetchMessages, POLL_INTERVAL_MS);
return () => clearInterval(timer);
```

폴링 타이머는 컴포넌트 언마운트 시 반드시 `clearInterval`로 정리해야 메모리 누수가 안 나서, cleanup 함수를 빼먹지 않는 게 이 작업에서 제일 신경 쓴 부분. `GET /api/messages?spaceId=`는 `sent_at ASC`로 정렬해서 오래된 순으로 내려주고, 프론트는 그걸 그대로 쌓아서 렌더링한다.
