> 실DB 전환 1번 타자. TravelHeroCard가 "D-12" 같은 가짜 값을 계속 보여주던 원인이 여기 있었음

## 🔍 현상 및 원인

`TravelHeroCard`가 `space.events[0].startDate`로 D-day랑 여행 기간을 계산하는데, `toTeamSpace()` 매퍼가 `events: []`로 무조건 빈 배열을 박아놓고 있었다. 그래서 실제로 팀스페이스를 API에서 가져와도 이벤트는 항상 비어있고, 화면엔 "D-12", "2026.08.01 (토) ~ 08.04 (화) · 3박 4일" 같은 하드코딩 fallback 문자열만 계속 노출됨.

추가로 `teamspace/mock.ts`의 `MOCK_TEAM_SPACES`는 어디서도 import 안 되는 죽은 코드였다.

## 🔧 조치 내용

| 구분 | 대상 | 변경 내용 |
|:--|:--|:--|
| 삭제 | `teamspace/mock.ts` | 미사용 dead code 제거 |
| 매퍼 | `teamspace/mappers.ts` | `toTripEvent(res: EventResponse): TripEvent` 추가 |
| 화면 | `DashboardScreen.tsx` | 선택된 space의 events를 `listEvents(spaceId, null, token)`으로 fetch해서 merge |

space 전환(`setSelectedSpaceId`)할 때마다 다시 fetch하는 방식으로 처리했다. 캐싱은 안 넣었음 — 어차피 나중에 TanStack Query로 교체할 계획이라 지금 단계에서 캐시 로직을 따로 짜는 게 낭비라고 판단.

## ✅ 검증 및 결과

- [x] TypeScript 타입 오류 없음 (`tsc --noEmit`)
- [x] events가 채워지면서 TravelHeroCard의 하드코딩 fallback이 자연스럽게 사라짐 (별도 수정 불필요했음)
