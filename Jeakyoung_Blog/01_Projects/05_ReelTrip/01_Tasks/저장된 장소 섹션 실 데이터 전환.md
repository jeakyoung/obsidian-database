# 저장된 장소 섹션 실 데이터 전환

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **요청자** | — |
| **요청일** | 2026-07-22 |
| **대상 시스템** | Web |
| **관련 화면·프로그램** | `DashboardScreen.tsx` > AiRecommendSection |

> 이름은 "AI 추천"인데 실제로는 AI가 추천한 적이 없는 섹션 — 이름부터 바로잡음

## 🔍 현상 및 원인

`AiRecommendSection`이 `DUMMY_PLACES`를 참조하고 있었는데, 정작 섹션 제목은 "AI 추천 장소"였다. `place/api.ts`의 `listPlaces()`로 가져오는 데이터는 사실 팀원들이 URL 파서로 직접 저장한 장소지, AI가 추천한 게 아니다. 진짜 AI 추천 기능은 `AiScreen.tsx`의 `DUMMY_AI_RECS`로 완전히 별개 존재. 실 데이터로 바꾸면서 이름까지 잘못 붙어있던 걸 그대로 유지할 이유가 없어서 제목도 같이 고쳤다.

## 🔧 조치 내용

| 구분 | 대상 | 변경 내용 |
|:--|:--|:--|
| 화면 | `AiRecommendSection` | `places: PlaceResponse[]` prop 수신, 제목 "AI 추천 장소" → "저장된 장소" |
| 화면 | `DashboardInner` | `places` state + `listPlaces()` fetch 추가 (events fetch와 동일 패턴), 최대 3개만 전달 |

`DUMMY_PLACES`엔 없던 필드(`thumbnailUrl`, `category`)가 실 데이터엔 있어서 카드 렌더링도 같이 손봤다 — 썸네일 있으면 이미지, 없으면 기존 그라디언트+이모지 fallback 유지. 태그는 원래 더미가 `"#바다"`처럼 `#`을 포함해서 저장했는데 실 데이터는 `"바다"`만 오길래 렌더링할 때 `#`을 붙이는 쪽으로 처리. 하드코딩 페이지네이션 dot(5개 고정)은 실 데이터 개수랑 무관한 장식이라 제거.

## ✅ 검증 및 결과

- [x] TypeScript 타입 오류 없음 (`tsc --noEmit`)
- [x] thumbnailUrl 유무에 따른 이미지/이모지 fallback 확인
- [x] 저장된 장소 없을 때 "저장된 장소가 없습니다" 빈 상태 확인
