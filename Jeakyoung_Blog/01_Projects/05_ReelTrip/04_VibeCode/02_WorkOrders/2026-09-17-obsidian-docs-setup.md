## 요구사항 분석 요약

- 옵시디언 vault(`jeakyoung/obsidian-database`)를 `obsidian/` 경로에 git submodule로 편입한다.
- 편입 후 코드베이스(Web/Mobile/API)를 분석해 아키텍처·기술스택 문서와 태스크 문서를 옵시디언 컨벤션으로 작성한다.
- 자동화(훅/CI)는 이번 범위에 포함하지 않는다 — 1회성 수동 생성.
- [?] vault가 private repo일 경우 인증 실패 가능 → clone 시도 후 실패하면 즉시 보고하고 인증 방법을 재확인받음.
- [?] vault 내부에 이미 특정 폴더 컨벤션(PARA 등)이 있을 수 있어, clone 직후 구조를 보고 문서 배치 위치를 그 자리에서 조정할 수 있음 (사전에 완전히 고정하지 않음).

## 작업 계획

### 1단계: 분석 및 준비
- [ ] `git submodule add https://github.com/jeakyoung/obsidian-database.git obsidian` 실행
- [ ] 서브모듈 clone 결과 확인, 인증 오류 발생 시 중단하고 보고
- [ ] vault 내부 기존 폴더 구조/네이밍 컨벤션 확인

### 2단계: 구현
- [ ] 레포 개요/아키텍처 문서 작성 (모노레포 구조, Web/Mobile/API 각 앱 설명)
- [ ] 기술스택 문서 작성 (Next.js 15, Expo, Spring Boot 3, PostgreSQL/Neon, MyBatis, Flyway, pgvector, OpenAI 임베딩 등)
- [ ] 태스크 문서 작성 (`docs/workOrders`의 미완료 항목 기반으로 옵시디언 태스크 노트 정리)
- [ ] 문서 간 `[[위키링크]]` 연결 및 YAML 프론트매터(태그 등) 적용

### 3단계: 검증
- [ ] 생성된 문서가 옵시디언에서 정상적으로 렌더링될 마크다운 문법인지 확인 (프론트매터, 위키링크 문법)
- [ ] `.gitmodules` 및 서브모듈 상태가 `git status`에서 예상대로 보이는지 확인
- [ ] 커밋/푸시는 사용자 확인 없이 진행하지 않음
