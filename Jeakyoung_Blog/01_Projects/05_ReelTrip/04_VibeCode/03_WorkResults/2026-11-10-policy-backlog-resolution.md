## 변경 사항 상세

### 사용자 확정 결론 (정책 미결 5건 + 설계 선택 3건)

| 항목 | 지난 분류 | 이번 확정 |
|------|-----------|-----------|
| 모바일 실제 지도 | 백로그(설계 선택) | **제외** — Google Maps API 키 미보유 |
| 관리자 권한(`users.role`) | 정책 미결 | **제외** — 구체적 admin 기능이 없어 인프라만 만드는 건 무의미 |
| "Pro로 업그레이드" | 정책 미결(상품/결제) | **축소** — 실제 결제 연동 대신 "준비중" 비활성화 |
| "계정 탈퇴" | 정책 미결(법적/개인정보) | **구현** — 소프트 삭제, 보관기간/법적 문구는 플레이스홀더 |
| 장소 공개동의 | 정책 미결(법적/약관) | **구현** — 동의 저장 기능만, 약관 문구는 플레이스홀더 |
| AI추천 알림 토글 | 정책 미결(제품) | **축소** — "준비중" 비활성화 |
| "비슷한 장소" + documents 파이프라인 | 백로그(설계 선택 A/B) | **옵션 B 채택** — `places` 전용 embedding 컬럼, documents/recommend와 독립 |

### 묶음 B — 계정 탈퇴(소프트 삭제)

**변경 전:** "계정 탈퇴" 버튼에 `onClick`이 없었다.

**변경 후:** `DELETE /api/user/account`(JWT 본인 확인만으로 동작, 다른 계정 지정 불가)가 `is_deleted=true` + `deleted_at` 세팅 + 해당 사용자의 refresh token 전체 삭제를 수행. 로그인(`login()`)과 토큰 재발급(`refresh()`) 양쪽에 탈퇴 계정 거부 가드를 추가했다.

**리뷰에서 발견·수정된 문제:** 최초 구현은 `login()`에만 `isDeleted` 체크가 있고 `refresh()`에는 없어, "탈퇴 API와 토큰 재발급 API가 동시에 들어오는" 좁은 타이밍 창에서 이론적으로 탈퇴 직후에도 새 토큰이 발급될 여지(TOCTOU)가 있었다. `refresh()`에도 동일한 가드를 추가해 토큰 삭제 타이밍에 의존하지 않는 독립적 방어선을 확보했다(커밋 `ff2f1f6`).

**소프트 삭제라 발생하지 않는 문제:** `users` 행이 그대로 남아 FK가 가리키는 대상이 사라지지 않아 고아 데이터는 생기지 않는다. 다만 탈퇴한 사용자가 오너인 팀스페이스는 소유권 이전 메커니즘이 없어 오너 전용 작업이 막힌 채로 남는다 — 이번 범위 밖으로 남겨둔 후속 과제다.

### 묶음 C — 장소 공개동의 저장

**변경 전:** 모바일 `PlaceDetailScreen.tsx`의 `onConsent` 콜백이 TODO 주석만 있고 아무 동작도 하지 않았다.

**변경 후:** 기존 장소 수정 엔드포인트(`PATCH /api/places/{id}`)에 동의 필드를 추가하고, 멤버십 체크를 그대로 거친다. 약관 문구는 상수(`CONSENT_PLACEHOLDER_TEXT`류)로 분리해 추후 실제 법무 문구로 쉽게 교체할 수 있게 했다.

### 묶음 D — "비슷한 장소" 추천 (옵션 B)

**변경 전:** `similar={[]}` 하드코딩.

**변경 후:** `places` 테이블에 전용 `embedding vector(1536)` 컬럼을 추가(documents/recommend 도메인과 완전히 독립), 장소 추가/수정 시 기존 AI 클라이언트로 임베딩을 생성해 저장(실패해도 장소 저장 자체는 성공하는 best-effort 방식), pgvector 코사인 유사도로 전체 장소 풀에서 유사 장소를 검색하는 `GET /api/places/{id}/similar`를 신설했다.

**설계상 중요한 지점(리뷰에서 확인):** "전체 장소 풀에서 검색"이라는 설계이므로 결과에 다른 팀스페이스의 장소가 포함될 수 있는데, (1) `consent_given=true`인 장소만 필터링하고 (2) 응답 DTO에서 소유자/스페이스/정확한 위치를 노출하지 않아 "익명 추천"이라는 동의 문구의 약속을 실제로 지키도록 설계했다.

## 잔여 이슈 / 후속 작업

- **제외된 항목**: 모바일 실제 지도(Google Maps API 키 필요), 관리자 권한 인프라(구체적 admin 기능 없음) — 필요 시 별도 사이클로.
- **플레이스홀더로 남은 정책 문구**: 계정 탈퇴 경고 문구, 장소 공개동의 약관 문구 — 실제 법무 검토 후 교체 필요.
- **팀스페이스 소유권 이전 메커니즘 없음**: 오너가 탈퇴하면 그 팀스페이스는 오너 전용 작업(설정/멤버 관리)이 영구히 막힌다. 별도 요구사항으로 다룰 필요.
- `TeamSpaceServiceImpl.inviteMember()`가 탈퇴한 사용자를 걸러내지 않아 멤버 목록에 유령처럼 남을 수 있다(로그인 불가라 실질적 피해는 없음) — 경미한 후속 과제.
- 전체 커밋은 로컬에서만 생성되었고, push 여부는 사용자 확인 후 진행한다.

## 특이 사항

- 이번 사이클은 "새로 조사"가 아니라 "이미 조사된 보류 항목을 사용자가 일괄 확정한 결론을 구현"하는 성격이라, 플래너가 1~2단계(조사/우선순위)를 건너뛰고 바로 TASKS.md "4. 개발" 섹션을 채우는 방식으로 진행했다.
- 계정 탈퇴(묶음 B)와 비슷한 장소 추천(묶음 D) 모두 "데이터는 지워지지 않지만 접근은 차단/익명화된다"는 공통된 설계 패턴을 썼다 — 소프트 삭제는 FK 무결성을, 익명 추천은 동의 문구의 약속을 각각 지키면서도 실제 데이터 삭제/하드 스코프 제한 없이 구현을 단순화한 선택이다.
