## 변경 사항 상세

### 지도 실연동 (병행 A) — 좌표가 아예 없던 문제의 근본 해결

조사 결과 가장 근본적인 공백은 "지도 마커가 하드코딩"이 아니라 **저장된 장소에 위도/경도가 애초에 저장되는 경로 자체가 없었다**는 점이었다. URL 파싱으로 장소를 추가하는 유일한 경로(Gemini 프롬프트)에 좌표 추출이 빠져 있었고, 수동 입력 UI도 없었다.

**변경 후:** 장소 추가/수정 시 주소를 OSM Nominatim(무료, API 키 불필요)으로 지오코딩해 좌표를 채우도록 했다. Nominatim 공식 Usage Policy(분당 1회 제한, `User-Agent` 헤더 필수)를 실제 코드(동기화 블록 + sleep, 헤더 빌더)로 준수했고, 지오코딩 실패해도 장소 저장 자체는 성공하는 best-effort 구조다. 기존에 이미 저장된 장소들도 일회성 배치로 소급 지오코딩했다. 지도에는 좌표가 확보된 장소만 조용히 필터링되어 표시된다.

### 운영시간 구조화 (순차 B) — 자유 텍스트와 구조화 데이터 병행

기존 `hours` 컬럼은 완전 자유 텍스트("월~금 11:00~22:00" 같은 임의 형식)라, "운영시간 밖이면 비활성화"를 안정적으로 구현하려면 구조화가 선행되어야 했다.

**변경 후:** `hours_structured`(JSONB, 요일별 open/close) 컬럼을 신설하고, Gemini 프롬프트에 이 구조로 추출하는 지시를 추가했다(best-effort, 모호하면 null). 기존 자유 텍스트 `hours`는 사람이 읽는 표시용으로 그대로 유지된다. 기존에 저장된 장소의 자유 텍스트를 재파싱해 소급 적용하는 것은 신뢰도가 낮아 범위에서 제외했다 — 이 장소들은 `hours_structured = null`로 남아, 향후 비활성화 로직에서 자연스럽게 "항상 허용"으로 처리된다. 모바일 보완 UI(`PlaceCorrectSection`)에도 요일별 수동 입력을 추가해, AI가 놓친 경우 사람이 직접 보정할 수 있다.

### 일정-장소 연관관계 (순차 C) — 백엔드까지 완료, 프런트는 다음 사이클

**변경 후:** `events` 테이블에 `place_id`(FK, nullable)와 `start_time`/`end_time`을 추가했고, 이벤트 생성/수정 API가 장소를 선택하면 해당 장소의 `name`/`hours`/`hoursStructured`를 함께 응답하도록 백엔드를 완성했다. `placeId`가 null인 기존 방식(자유 텍스트 `location`만 쓰는 이벤트)도 완전히 독립적으로 계속 정상 동작한다.

**다음 사이클에서 이어서 할 일(C3~C5, D):** 웹/모바일의 이벤트 생성 폼을 자유 텍스트 장소 입력에서 "저장된 장소 선택" 드롭다운으로 교체하고 시간 입력 UI를 추가하는 작업(C3/C4), 선택한 장소의 운영시간 밖 시간대를 비활성화하는 로직(C5), 그리고 캘린더를 정적 타임라인/블록형 뷰로 보여주는 작업(D)이 남아 있다.

## 잔여 이슈 / 후속 작업

- **C3/C4(프런트 폼 연동)**: 리뷰에서 발견된 주의사항 — `EventServiceImpl.update()`가 새로 추가된 `placeId`/`startTime`/`endTime` 필드도 기존 필드처럼 무조건 덮어쓰는 방식이라, 수정 폼에서 기존 값을 프리필하지 않으면 저장 시 데이터가 날아갈 수 있다. 다음 작업 시 반드시 유의.
- **C5(운영시간 비활성화)**: C3/C4가 완성되어야 실제로 동작할 수 있다. `hoursStructured`가 없는 장소(대다수의 기존 장소)는 자연히 "항상 허용"으로 처리되므로, 실효성은 신규 추가되는 장소부터 점진적으로 커진다.
- **D(블록형 캘린더)**: 정적 타임라인 표시로 범위를 확정했음(드래그앤드롭 재배치는 제외). 신규 라이브러리 없이 커스텀 컴포넌트로 구현 가능하다고 조사됨.
- **운영상 비차단 참고사항(A4)**: 소급 지오코딩 배치가 실패 시 플래그를 복구하지 않으면 반복 실행될 수 있고, 멀티 인스턴스 배포 시 중복 호출될 수 있다 — 현재 단일 인스턴스 규모에서는 위험이 낮다고 판단했으나 규모가 커지면 재검토 필요.
- 전체 커밋은 로컬에서만 생성되었고, push 여부는 사용자 확인 후 진행한다.
