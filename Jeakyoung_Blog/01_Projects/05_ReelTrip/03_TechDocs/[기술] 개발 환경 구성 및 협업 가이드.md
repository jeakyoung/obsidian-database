# ReelTrip 개발 환경 구성 가이드

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **대상 시스템** | Web / Mobile / API 전체 |
| **적용 범위** | 개발환경 |
| **관련 모듈** | 루트 `package.json`, `turbo.json`, `apps/*/package.json`, `apps/api-spring/pom.xml` |

> 이전 버전(NoNAME 시절) 문서는 Java 11 · Redis · Kubernetes 기준으로 작성돼 있었는데, 실제 코드베이스랑 안 맞아서 지금 구성 그대로 다시 씀

## 🎯 배경 및 요구사항

기존 문서가 실제로 이 저장소에 없는 것들(Redis, Kubernetes, Jenkins, JUnit 커버리지 80%)을 전제로 쓰여 있었다. 포트폴리오용으로 쓸 거면 실제로 돌아가는 구성 그대로 적어야 의미가 있어서, `package.json` / `pom.xml` / `application.yml` / `Dockerfile`을 직접 열어보고 다시 정리함.

## 🏗 설계 및 구현

### 필수 도구

| 도구 | 버전 | 근거 |
|:--|:--|:--|
| Node.js | 20+ | 루트 `package.json` `engines.node` |
| npm | 10.9.2 | `packageManager` 필드로 고정 |
| Java | 17 | `pom.xml` `<java.version>` — `spring-boot-starter-parent` 3.3.5 기준 |
| Maven | wrapper 사용 | `apps/api-spring/mvnw` |

> **Java 버전 표기 정리 필요**
> 루트 `README.md`엔 "Java 21+"라고 적혀 있는데, 실제 빌드 기준(`pom.xml`)은 17이고 `Dockerfile`도 `amazoncorretto:17-alpine`을 씀. README 쪽이 낡은 값이라 17로 맞춰서 씀.

### 모노레포 구조

```
reel-trip/
├── apps/
│   ├── web/           # Next.js 15 (App Router)
│   ├── mobile/        # Expo ~54 · Expo Router v6
│   └── api-spring/    # Spring Boot 3
├── packages/
│   ├── types/         # 공유 TS 타입 (ApiResponse 등)
│   └── utils/
└── turbo.json
```

npm workspaces(`apps/*`, `packages/*`) + Turborepo 조합. `apps/mobile`은 Metro 번들러가 워크스페이스 구조랑 안 맞는 부분이 있어서 루트 스크립트(`build`/`dev`/`lint`/`type-check`)에서 `--filter=!./apps/mobile`로 항상 빼고, mobile은 자기 디렉토리에서 직접 `npm run dev`(=`expo start`)로 돌린다.

### 환경변수

**`apps/api-spring`** — `application.yml`이 전부 `${VAR:기본값}` 형태라 로컬은 기본값으로 뜨고, 실제 배포는 환경변수로 덮어씀.

| 변수 | 용도 |
|:--|:--|
| `DATABASE_URL` | Supabase Postgres 연결 문자열 |
| `JWT_SECRET` / `JWT_EXPIRATION` / `JWT_REFRESH_EXPIRATION` | 액세스·리프레시 토큰 |
| `OPENAI_API_KEY` | 임베딩(`text-embedding-3-small`) |
| `GEMINI_API_KEY` | AI 파서 (`gemini-2.5-flash`) |
| `APIFY_API_TOKEN` | URL 파서용 크롤링 |
| `ALLOWED_ORIGINS` / `ALLOWED_ORIGIN_SUFFIXES` | CORS |

> **README에 있는 `ANTHROPIC_API_KEY`는 지금 안 쓰임**
> `AiService` 인터페이스 주석엔 "Claude API"라고 적혀 있고 `ErrorCode`에도 `ANTHROPIC_API_KEY_MISSING`이 있는데, 실제 구현(`AiServiceImpl.extractTravelInfo`)은 `geminiApiKey`를 체크하고 Gemini로 호출한다. Claude로 시작했다가 Gemini로 갈아탄 흔적이 이름에만 남아있는 상태 — 나중에 정리 대상.

**`apps/web`** — `.env.local` (gitignored), `.env.example` 참고.

```env
# 서버사이드 전용 — NEXT_PUBLIC_ 접두사 절대 안 붙임
API_URL=http://localhost:4000
NEXT_PUBLIC_APP_URL=http://localhost:5173
```

`NEXT_PUBLIC_API_URL`을 안 쓰는 이유는 `next.config.ts`의 rewrites 프록시 설계 때문 — 브라우저가 백엔드 URL을 직접 알면 CORS를 우회해서 바로 쏘게 되고, 그럼 API 서버 CORS 설정이 무의미해진다. `/api/:path*` 요청을 Next 서버가 받아서 `API_URL`로 대신 쏴주는 구조라 브라우저 입장에선 항상 same-origin. 인증 흐름 자체는 [[Web API 클라이언트 토큰 재발급 흐름]] 참고.

**`apps/mobile`** — Metro 호스트를 런타임에 자동 추론해서 `EXPO_PUBLIC_API_URL`을 비워둬도 실기기/에뮬레이터 둘 다 동작. Android 에뮬레이터만 예외적으로 `10.0.2.2:4000` 수동 지정 필요.

### 로컬 실행

```bash
npm install

# 개별 실행
cd apps/api-spring && ./mvnw spring-boot:run   # :4000
cd apps/web && npm run dev                      # :5173 (package.json에 -p 5173 고정)
cd apps/mobile && npm run dev                    # expo start
```

로컬용 Postgres 컨테이너 설정(docker-compose 등)은 저장소에 없다 — 개발 중에도 원격 Supabase 인스턴스에 바로 붙는 방식.

### 배포

| 앱 | 대상 | 방식 |
|:--|:--|:--|
| API | Railway | `railway.toml` → `apps/api-spring/Dockerfile` (Maven 멀티스테이지, `-DskipTests`) |
| Web | Vercel | Root Directory `apps/web` |
| Mobile | EAS | `eas.json` — development/preview/production 프로필, `app.config.js`에서 `APP_VARIANT`로 앱 아이디·스킴 분기 |
