## 🏗 진행 내용

### 1. 저장소 리네이밍 — Haccp → foodlink-service (2026-06-10)

첫 확인 가능한 커밋(`e864e54`)이 이미 리네이밍 커밋이다. `{Haccp => foodlink-service}/.gitignore`, `F1Soft.Starmap.Core`, `F1Soft.Starmap.Service.sln` 등 폴더 전체가 `Haccp`에서 `foodlink-service`로 옮겨졌고, `foodlink-service/API.md`가 이때 처음 생겼다. 네임스페이스(`F1Soft.Starmap.*`)는 I-Frog 원본에서 그대로 가져온 것이라 리네이밍 이후에도 바뀌지 않았다.

### 2. 아키텍처 기반 정리 (2026-06-25)

`a4c82b2` "디렉토리 구조개선 및 Response Body 형식 통일화" — 50개 파일, +1471/-1935 규모. `IDatabaseHelper` 기반 SQLServer/Oracle/PostgreSQL 헬퍼 3종 분리, `ApiResponse<T>` 응답 봉투 도입, Auth를 `TokenService`/`UserService`로 재정리. 지금 레이어링·응답 규약의 원형이 이 시점에 만들어졌다. 자세한 내용은 [[01_Projects/07_DataBoucher/01_Tasks/데이터 바우처 DB Helper 계층 분리 및 ApiResponse 통일화 06.25]].

### 3. 멀티테넌시 구조 도입 (2026-06-30)

`8533590` "티커에" — 회사별로 나뉘어 있던 `Dev/Stg/PrdEnvService` 클래스를 없애고, `SECURITY_CODE` 헤더 기반 `SecurityCodeMapper`/`TickerMiddleware`/`EnvService` 조합으로 교체했다. 배포 하나로 여러 회사·환경을 서빙하는 지금 구조의 시작점. 자세한 내용은 [[01_Projects/07_DataBoucher/01_Tasks/데이터 바우처 TickerMiddleware·EnvService 멀티테넌시 구조 최초 구현 06.30]].

## ✅ 결과 및 회고

- **I-Frog 카피 기반 출발이 초기 속도를 크게 끌어올렸다.** 멀티테넌시·레이어링·응답 규약 같은 기반 구조를 새로 설계하지 않고 검증된 코드를 가져온 덕분에, 6월 말~7월 초 한 달 안에 입고·이미지·검색 도메인 CRUD가 거의 다 갖춰졌다.
- **다만 카피해온 부분과 새로 손댄 부분이 시간이 지나며 갈라지기 시작했다.** 예를 들어 `EnvService`는 I-Frog 쪽에서 Postgres 테이블 기반으로 진화했지만 이 저장소는 여전히 `appsettings.json` 기반 원본 구조를 쓴다 — 같은 이름의 클래스가 프로젝트마다 다르게 동작하니 코드를 옮겨쓸 때 항상 확인이 필요하다.
- **v1.0.0 태그와 프로젝트 문서화(`PROJECT_OVERVIEW.md`, `CLAUDE.md`)가 같은 날 함께 들어간 건 우연이 아니라, 기능이 어느 정도 갖춰진 시점에 구조를 정리해두자는 판단으로 보인다.** 다만 그 커밋에서 `Zone.Identifier` 파일이 같이 커밋된 건 실수였고, 한 달 뒤에야 정리됐다 — Windows에서 받은 설정 파일을 커밋할 때는 탐색기 창에서 직접 끌어놓기보다 `git add`로 대상 파일만 명시하는 게 안전하다.
- **원래 목표(AI 분석 연동)는 아직 시작 전이다.** 지금까지의 작업은 전부 "데이터를 어떻게 잘 모을 것인가"에 집중돼 있고, `TB_LabelMaster`의 `ANALYSIS_STATUS` 컬럼과 주석 처리된 `SP_APP_LABEL_LIST` 연동만 스케폴딩으로 남아있다.
