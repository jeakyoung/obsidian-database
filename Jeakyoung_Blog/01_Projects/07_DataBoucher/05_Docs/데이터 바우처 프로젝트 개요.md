# 데이터 바우처 프로젝트 개요

## 📋 개요

| 항목 | 내용 |
|:--|:--|
| **프로젝트** | 데이터 바우처 |
| **기간** | 2026-06 ~ 진행중 |
| **역할** | 모바일 백엔드 API 개발 (데이터 수집 파이프라인) |
| **기술 스택** | C# .NET Core, MSSQL, FTP |

> 입고등록 대상 라벨 사진을 대량 수집해 AI 모듈로 함량표시 변경 여부를 자동 분류·모니터링하는 신규사업. [[01_Projects/03_iFrog/index.md|I-Frog]]와 같은 `F1Soft.Starmap.Service` 코드베이스를 카피해서 시작했다.

## 🎯 목표 및 범위

프로젝트 전체 목표는 "사진 → AI 분석 → 함량표시 변경 모니터링"이지만, 이 저장소가 담당하는 건 그 앞단인 **데이터 수집 단계**뿐이다 — 모바일에서 입고대상 라벨을 촬영하고, 서버가 FTP에 저장한 뒤 DB(`TB_LabelMaster`)에 이력을 쌓는 것까지. AI 분석(함량표시 변경 판별) 자체는 별도 모듈이며 이 저장소 범위 밖이다.

| 도메인 | 담당 범위 |
|:--|:--|
| **Image** | 라벨 이미지 촬영·업로드·FTP 저장·`TB_LabelMaster` 적재 |
| **Input** | 입고 대상/완료 거래처 조회, 입고 등록 시 이미지 임베디드 저장 |
| **Search** | 거래처/원료/창고/용도 등 모바일 콤보·목록 조회 |
| **Auth** | I-Frog와 동일 구조(JWT + `SECURITY_CODE`) 그대로 사용 — 이 프로젝트에서 별도로 손댄 부분 없어 자체 TechDoc 작성은 생략, [[01_Projects/03_iFrog/index.md|I-Frog]] 쪽 문서 참고 |

## 🏗 진행 내용

- 멀티테넌시(SECURITY_CODE → Ticker/Env) 구조, Controller→Service→DatabaseHelper 레이어링, `ApiResponse<T>` 응답 봉투 — I-Frog 원본에서 카피해온 뒤 이 프로젝트 안에서 다시 자리잡음
- 입고(Input) 등록/조회, 라벨 이미지 촬영·업로드 파이프라인, Search 조회 API 7종 구현 완료
- FTP 저장 경로를 평면 구조에서 `yy/MM/` 날짜 디렉토리 구조로 개선
- 거래처 검색 파라미터 정리, 이미지 업로드 시 거래처코드 필수→선택 전환(진행중)

아직 안 끝난 것:

- **AI 분석 결과 연동 미구현** — `TB_LabelMaster.ANALYSIS_STATUS`/`SP_APP_LABEL_LIST` 스케폴딩만 있고 컨트롤러/서비스에서 주석 처리된 채 비활성 상태. 프로젝트 최종 목표(AI 분류)로 가려면 이게 핵심 남은 작업
- `UploadImageRequest.CustomerCode` 선택값 전환 건 미커밋 (진행중)

## ✅ 결과 및 회고

I-Frog 코드베이스를 그대로 카피해서 시작한 덕분에 멀티테넌시·레이어링·응답 규약 같은 기반 구조는 빠르게 갖춰졌고, 입고·이미지·검색 도메인 CRUD도 비교적 짧은 기간(2026-06 ~ 07)에 완성됐다. 이후로는 버그 픽스와 자잘한 개선(FTP 경로, 검색 파라미터) 위주로 진행 중이며, 원래 목표였던 AI 분석 연동은 아직 손대지 않은 상태 — 데이터가 충분히 쌓인 뒤 진행할 것으로 보인다.
