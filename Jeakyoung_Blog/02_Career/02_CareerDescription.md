F1soft에서 여러 고객사의 ERP/MES 시스템(Sencha Ext JS + Java 서블릿 + MSSQL)과 신규 모바일 백엔드 API(C# .NET Core) 프로젝트를 함께 담당하고 있습니다. 프레임워크가 대신 처리해주는 부분이 거의 없는 순수 서블릿+JDBC 코드베이스에서 기존 로직을 읽고 고치는 일이 많다 보니, 남의 코드를 정확히 추적하고 최소 변경으로 안전하게 수정하는 데 익숙해졌습니다.

### IPACK 근태 시스템 — 시간 계산 로직 및 근태 기능 (2025 ~ 진행중)

- 근태 계산에서 지각/조퇴는 올림(ceil), 초과근무는 내림(floor), 표준 근무시간은 반올림(round) — 항목마다 반올림 규칙이 다르다는 걸 코드에서 직접 확인하고, 10분 단위로 일관되게 적용하도록 계산 함수(`convertToMinusHour`/`convertToPlusHour`/`convertToDecimalHour`)를 정리했습니다.
- 주차별 근무조 등록(WHR316) 기능을 처음부터 구현했습니다 — 근무조 일괄적용/변환, 근태 년-월·주차 조회조건, 사원 LIKE 검색 등을 세부 기능 단위로 진행했습니다.
- 매출마감처리(WSA503), 수주승인처리 등 영업(SA) 화면 유지보수를 병행했습니다.

> 이 시스템은 Java 서블릿이 SQL 문자열을 직접 이어붙여 저장 프로시저를 호출하는 구조입니다(`"EXEC SP_... '" + value + "'"`). 구조적인 SQL Injection 패턴이라는 걸 파악했고, 현재 담당 범위 밖이라 아직 개선하지는 못한 상태입니다.

### I-Frog — 그룹웨어/ERP 연동 백엔드, 서버 통합 (2026.06 ~ 진행중)

합류 당시 Auth/Approval/Board/Calendar/Emp의 기본 틀은 이미 있었습니다(업체마다 서비스 코드를 커스터마이징해 그 업체 서버에 따로 얹는 방식). Approval·Board·Calendar는 다시 손봤고, 이후 진행한 **서버 통합**(업체별 커스텀 서버 → 단일 백엔드)은 직접 설계·구현했습니다.

- 요청 헤더의 보안 코드(SECURITY_CODE)로 회사(Ticker)와 DB 환경(Dev/Stg/Prd)을 구분해 `EnvService`가 연결 문자열을 골라주는 멀티테넌시 구조 설계
- FCM(Firebase Cloud Messaging) 기반 업무연락 알림, 결재함 문서 알림 기능 구현
- SAP RFC 연동(`Controllers/Interface/Sap`), 원시 쿼리 실행 컨트롤러(Oracle/PostgreSQL/SQLServer) 구현

### 신진SM ERP/MES — 더존 연동 정합성 문제 대응 (2026.04 ~ 진행중)

신진SM의 MES는 저장이 완료되면 별도 JDBC 커넥션으로 더존(DZ) ERP의 `NEOE.*` 프로시저를 호출해 데이터를 반영하는 구조인데, 이 두 커밋이 원자적이지 않다는 게 반복적으로 문제의 근원이 되고 있습니다. 포장 중복(5월), 더존 월말 재고 집계 불일치(8월), 더존 문서 중복 생성(9월)이 표면적으로는 다른 문제로 보고됐지만 전부 같은 구조에서 비롯됐습니다.

- `SP_WPR559_02_IUD_TEST`에 `@ISEXISTS_OUT` OUTPUT 파라미터를 추가하고 `ProdReportService`/`ProdSLService`가 이 값을 보고 더존 문서 재생성을 생략하도록 수정
- 더존-MES 사업장 코드 매핑 불일치(하드코딩된 `1000` 등) 확인 및 검증 쿼리 작성
- 더존 `MM_OHSLINVM`(월별 집계) vs `MM_OHSLINVD`(일별 상세) 불일치를 탐지/정정하는 절차 표준화 — 프로시저 재실행은 `MM_PINVN` 이중 반영 위험이 있어 금지하고, 탐지 → 세부 확인 → UPDATE 3단계로 분리

> 아직 근본적으로 "MES 커밋 = 더존 커밋"을 보장하는 구조로 묶어서 해결하지는 못했고, 발생할 때마다 개별 가드와 수동 정정으로 대응해온 단계입니다.

### 데이터 바우처 — 라벨 이미지 수집 파이프라인 (2026.06 ~ 진행중)

입고등록 대상 라벨 사진을 대량 수집해 AI로 함량표시 변경 여부를 자동 분류하는 신규사업의 데이터 수집 단계를 담당했습니다. I-Frog(`F1Soft.Starmap.Service`) 코드베이스를 카피해 시작했습니다.

- 모바일에서 촬영한 입고 라벨 이미지를 FTP에 업로드하고 `TB_LabelMaster`에 이력을 적재하는 파이프라인 구현
- Controller → Service → DatabaseHelper 계층 구조와 `ApiResponse<T>` 공통 응답 포맷 통일
- `SECURITY_CODE` 헤더 기반 멀티테넌시(TickerMiddleware) 구조를 I-Frog에서 그대로 가져와 적용

> AI 분석(함량표시 변경 판별) 연동은 스케폴딩만 되어 있고 아직 비활성 상태입니다 — 이 저장소 범위 밖의 별도 모듈입니다.

### ReeL-Trip — 개인 프로젝트, 풀스택 (2026.02 ~ 진행중)

여행 콘텐츠 링크(유튜브 쇼츠/인스타 릴스)를 던지면 파싱해서 장소 후보로 등록하는 서비스를 Web(Next.js)/Mobile(React Native)/API(Spring Boot) 세 개를 같이 굴리며 만들고 있습니다.

- 백엔드를 NestJS로 시작했다가 Spring Boot 3 + MyBatis로 마이그레이션 (프론트/백엔드 런타임 분리, CORS 이슈 해결 과정 포함)
- 액세스 토큰 24시간 → 30분으로 줄이고 DB 저장 리프레시 토큰(30일) 회전 구조 도입
- 유튜브 쇼츠는 공식 oEmbed + 자체 스크래핑, 인스타 릴스는 Apify 액터로 수집하는 플랫폼별 전략 패턴 구현
- 테스트 코드는 아직 없음 — 기능 구현을 우선했고, 다음 단계 과제로 남겨둔 상태

### 동방푸드 ERP — 조회조건·데이터 정합성 기술지원

동방푸드마스타·동방MS 대상 iPlusERP 기술지원. 화면 조회조건 추가와 데이터 정합성 조치 위주였습니다.

- 조회조건 파라미터가 서버에서 잘못 읽히는 버그(WRD203) 분석 — `jvWRD203_01_LIST.java`가 서로 다른 세 파라미터를 전부 같은 이름(`PROC_GBN`)으로 읽어들여 일부 값이 버려지는 구조를 파악
- 조직 구조·업무 프로세스를 문서화해 이후 대응 속도를 높임

### 그 외 단기 기술지원

세한MT(POP 생산실적 화면 수정, 소스 형상관리 체계 구축), 뉴파워 프라즈마(NPP, 정부지원 신규사업 — AI 관제/LLM 대시보드/폴리싱 공정 자동화, 현재 요구사항·인프라 검토 단계) 등 규모가 작거나 초기 단계인 프로젝트를 병행하고 있습니다.

## 🏆 성과 및 역량

- **레거시 코드 파악 능력**: 프레임워크 없는 순수 서블릿 코드베이스에서 기존 로직을 읽고 최소 변경으로 안전하게 고치는 작업에 익숙함
- **다중 시스템 연동 문제 분석**: MES-더존 ERP처럼 두 시스템이 비동기·비원자적으로 연동되는 구조에서 문제의 근본 원인을 추적하는 경험
- **처음부터 끝까지 만들어본 경험**: ReeL-Trip에서 백엔드 프레임워크 교체, 인증 구조 설계, 외부 API 연동까지 진행
- **사실 기반 기술 문서화**: 확인 안 되는 내용은 미확인으로 남기고, 코드와 다른 부분은 있는 그대로 적는 걸 원칙으로 함
