## 🧭 경력 요약

평택대학교 정보통신학과를 졸업하고 2025년 7월부터 F1soft에서 ERP·MES 백엔드와 모바일 백엔드 API 개발을 맡고 있습니다.

## 🛠 주요 수행 내용

### 성장 배경 및 개발자 지향

실무에 처음 투입됐을 때는 프레임워크 하나 제대로 안 써본 상태였습니다. 지금 담당하는 시스템들은 대부분 Spring이나 JPA 같은 익숙한 프레임워크가 아니라, 순수 서블릿 + JDBC로 저장 프로시저를 직접 호출하는 구조입니다. 처음엔 낯설었지만, 오히려 이 구조 덕분에 "프레임워크가 대신 해주는 부분"이 아니라 요청이 실제로 어떻게 SQL까지 이어지는지를 직접 보면서 배울 수 있었습니다.

### 담당 업무를 통해 배운 것

**신진SM ERP/MES — 서로 다른 시스템을 연동할 때의 함정**

신진SM MES는 저장이 끝나면 별도 커넥션으로 더존 ERP의 프로시저를 호출해 데이터를 반영합니다. 문제는 이 두 저장이 하나의 트랜잭션이 아니라는 것 — MES는 저장됐는데 더존 반영만 실패하는 경우가 사용자에게 드러나지 않았고, 포장 중복·재고 집계 불일치 같은 서로 다른 이름의 문제가 사실은 같은 구조에서 반복적으로 나오고 있다는 걸 확인했습니다. 개별 가드(`@ISEXISTS_OUT` 같은 방식)를 하나씩 추가하며 대응해왔고, 아직 근본적으로 두 시스템의 커밋을 하나로 묶어서 해결하지는 못했습니다 — 이 문제를 계속 붙잡고 있습니다.

**IPACK 근태 시스템 — 숫자 계산은 대충 넘어갈 수 없다는 것**

지각·조퇴는 올림, 초과근무는 내림, 표준 근무시간은 반올림 — 항목마다 반올림 규칙이 다르다는 걸 파악하지 못하면 근무시간 계산이 조금씩 어긋납니다. 이런 규칙을 코드에서 정확히 읽어내고 일관되게 적용하는 일을 하면서, 겉보기엔 단순해 보이는 계산 로직도 엣지 케이스를 놓치면 바로 실제 급여·근태 기록에 영향을 준다는 걸 체감했습니다.

**ReeL-Trip — 혼자 처음부터 끝까지 만들어보기**

회사 업무와는 별개로, 여행 콘텐츠 링크를 던지면 장소 정보를 자동으로 뽑아주는 서비스를 개인적으로 만들고 있습니다. 백엔드를 NestJS로 시작했다가 Spring Boot로 갈아엎었고, 유튜브/인스타그램처럼 플랫폼마다 콘텐츠 접근 방식이 완전히 다른 문제를 전략 패턴으로 풀었습니다. 테스트 코드가 아직 없다는 것도 알고 있고, 다음 단계 과제로 남겨두고 있습니다.

### 핵심 강점

1. **레거시/저수준 코드 파악력**: 프레임워크 없는 서블릿 코드에서 실제 동작을 정확히 추적하는 데 익숙합니다.
2. **시스템 간 연동 문제 분석**: 두 시스템이 비동기로 연동될 때 생기는 정합성 문제의 근본 원인을 끝까지 따라가려고 합니다.
3. **정직한 기술 문서화**: 확인 안 되는 내용은 "미확인"으로 남기고, 과장하지 않고 사실 기반으로 기록하는 걸 중요하게 생각합니다.
4. **끝까지 만들어보는 경험**: ReeL-Trip에서 프레임워크 교체 판단부터 배포까지 혼자 해봤습니다.

### 앞으로 하고 싶은 것

지금까지는 이미 있는 시스템을 유지보수하고 고치는 일이 많았다면, 앞으로는 처음부터 설계하는 경험을 더 쌓고 싶습니다. 특히 여러 시스템이 얽혀서 데이터 정합성이 깨지는 문제(신진SM에서 계속 마주하고 있는 문제)를 구조적으로 해결하는 데 관심이 있습니다.

## 🏆 성과 및 역량

- 프레임워크 없는 레거시 서블릿 코드베이스 유지보수 경험
- 다중 시스템(MES↔ERP) 연동 정합성 문제 분석 경험
- 개인 프로젝트에서 백엔드 프레임워크 마이그레이션(NestJS → Spring Boot) 판단·실행 경험
