# 프로젝트 문서 표준 양식 가이드

이 가이드는 **모든 프로젝트 폴더**에 적용되는 통일된 문서 양식입니다.

---

## 1. 문서 유형별 양식

### 📋 유형 1: 회의록 (회의/인수인계/교육)

```yaml
---
type: 회의록
title: [프로젝트명] [YYYY-MM-DD] [회의 구분]
date: YYYY-MM-DD
attendees: [참석자]
status: 완료
category:
  - 회의록
---
```

**필수 구조:**
- 회의 목적 (한 문장)
- 주요 안건 (bullet + 세부 설명)
  - 논점/현황
  - 결정 사항
  - 담당자 및 기한
- 첨부 (이미지/파일)
- 다음 회의 일정

---

### 🔧 유형 2: 기술문서 (이슈/개선/기능)

```yaml
---
type: 기술문서
title: [상태] [기능/이슈명]
date: YYYY-MM-DD
status: 미해결/진행중/완료
priority: 높음/중간/낮음
assignee: [담당자]
category:
  - 기술문서
---
```

**필수 구조:**
- 개요 (배경/현황)
- 문제 상황 / 요구사항
- 기술 내용
  - 관련 쿼리/코드
  - 연동 부분
  - 구현 방식
- 해결 방안 / 구현 계획
- 진행 상황 (체크리스트)
- 성과 측정 지표 (해당 시)

---

### 📚 유형 3: 참고문서 (기술 레퍼런스)

```yaml
---
type: 참고문서
title: [분류] [대상]
category: SQL/배포/API/기타
database: [해당하는 DB명]
---
```

**필수 구조:**
- 개요 (목적)
- 명령어/설정 (코드블록)
- 예시 (구체적 사용 방법)
- 주의사항 / 트러블슈팅

---

### 📊 유형 4: 프로젝트 인덱스

```yaml
---
type: 인덱스
title: [프로젝트명] 전체 문서 인덱스
status: 진행중
updated: YYYY-MM-DD
---
```

**필수 구조:**
- 프로젝트 개요 (목표/상태)
- 회의록 목록 (시간순)
- 기술 문서 목록 (우선순위순)
- 참고 문서 목록 (카테고리순)
- 진행 상황 (체크리스트)
- 다음 단계

---

## 2. 파일 명명 규칙

### 회의록
```
[YYYYMMDD] [프로젝트명] [주제].md
예: [20260605] IPACK 근태시스템 협의.md
```

### 기술문서
```
[상태] [주제].md
예: [진행중] 포장중복문제 분석.md
예: [완료] 배치 작업 자동화.md
```

### 참고문서
```
[분류] [대상].md
예: [SQL] SP_WMA624_01_IUD.md
예: [배포] Docker 설정.md
```

## 3. 폴더 구조 (권장)

```
프로젝트 DB/
├── _INDEX.md                    ← 메인 진입점
├── 문서 표준 양식 가이드.md      ← 프로젝트별 (선택)
├── 회의록/                       ← [YYYYMMDD] 형식
│   ├── [20260428] 프로젝트개시.md
│   └── [20260605] 주요안건논의.md
├── 기술문서/                     ← [상태] 형식
│   ├── [진행중] 이슈분석.md
│   └── [완료] 기능개선.md
├── 참고문서/                     ← [분류] 형식
│   ├── [SQL] 쿼리모음.md
│   └── [배포] 설정가이드.md
└── 아카이브/ (선택)
    └── [2026-05] 완료된항목/
```

## 4. 메타데이터 필수 항목

모든 문서의 YAML 헤더에 포함:

| 항목 | 필수 | 설명 |
|------|------|------|
| type | ⭐ | 회의록/기술문서/참고문서/인덱스 |
| title | ⭐ | 명확하고 구체적인 제목 |
| date | ⭐ | 작성/갱신 날짜 (YYYY-MM-DD) |
| status | ⭐ | 완료/진행중/미해결 (기술문서), 완료 (회의록) |
| priority | 기술문서 | 높음/중간/낮음 |
| assignee | 기술문서 | 담당자명 |
| category | ⭐ | 분류 태그 |

## 5. 콘텐츠 작성 원칙

### ✅ 해야 할 것
- 명확한 제목과 소제목 사용 (H2, H3)
- 구체적인 문제 상황 / 현황 기술
- 관련된 코드/쿼리 (코드블록으로)
- 담당자와 예상 완료 일정 기록
- 이전 회의/이슈와의 연결 표기
- 진행 상황은 **항상 업데이트**

### ❌ 하지 말아야 할 것
- 매우 짧고 불명확한 설명
- 문맥 없이 코드만 나열
- 상태/담당자 미기입
- 타이핑 오류 방치
- 오래된 정보를 최신인 척 표기

## 6. 상호 참조 (중요!)

문서들을 **[[링크]]** 형식으로 연결:

```markdown
### 관련 문서
- [[20260605] 포장중복문제 및 성능최적화]] - 기술 검토
- [[진행중] 포장중복문제 분석]] - 근본 원인
- [[SQL] SP_WMA624_01_IUD]] - 저장 프로시저 상세
```

**효과:**
- 한 문서에서 관련 정보로 쉽게 이동
- 프로젝트 전체 맥락 파악 용이

---

## 7. 버전 관리

큰 변화가 생긴 경우:

```
원본: [진행중] 포장중복문제 분석.md
↓
V2로 업데이트 시:
[V2-진행중] 포장중복문제 분석.md
```

**구 버전 관리:**
- 파일명에 버전 명시
- 기존 파일은 아카이브 폴더로 이동

## 10. FAQ

### Q: 기존 문서는 어떻게 하나요?
**A:** 이 양식을 참고하여 점진적으로 개선. 긴급할 경우 최소한 메타데이터만 추가.

### Q: 프로젝트마다 다른 양식 사용해도 되나요?
**A:** 이 표준 양식을 기본으로. 프로젝트 특성에 맞게 세부 조정 가능.

### Q: 링크가 깨진 경우는?
**A:** 파일명 변경 시 링크 자동 업데이트되지 않으므로, 변경 전에 모든 참조 확인.
