## 기존 LIST Service 방식

```java
public ArrayList<Edu4_1Model> getFirstList(ServletRequest request, ServletContext sc) {
        ArrayList<Edu4_1Model> list = new ArrayList<>();
        Connection conn = dbconnect.getConnection2(sc);
        PreparedStatement pstmt = null;
        ResultSet rs = null;
        try {
            String sql = "EXEC SP_HHR101_LIST " + " @FACTORY_CODE = ? ";

            pstmt = conn.prepareStatement(sql);
            pstmt.setString(1,  request.getParameter("FACTORY_CODE"));

            rs = pstmt.executeQuery();
            System.out.println(sql);
            while (rs.next()) {
                Edu4_1Model model = new Edu4_1Model();
                model.setFACTORY_CODE   (rs.getString("FACTORY_CODE"));
                list.add(model);
            }
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            DBClose.close(conn, pstmt, rs);
        }
        return list;
    }
```

기존 코드내에서의 실질적인 조회는 해당부에서 발생했음. 축약하긴 했지만 리스트내에 있는 모든항목에 대해 @WORK_CODE = ?  와같은 쿼리를 작성하여 PreStatement 방식으로 요청을 넣어 리스트에 필요한      전체 항목을 파라미터로 담아온 뒤 모델내에 set해주는 방식을 사용하고 있음.

## 기존 Servlet

```java

@WebServlet("/com/edu/jvEdu5_01_LIST")
public class jvEdu5_01_LIST extends HttpServlet {
    public void service(ServletRequest request, ServletResponse response) throws ServletException, IOException {
        response.setContentType("application/json; charset=UTF-8");
        request.setCharacterEncoding("UTF-8");
        JSONArray result = new JSONArray();
        //02List내 주석처리 완료
        try {
            EduService service = new EduService();
            ArrayList<Edu4_1Model> list = service.getFirstList(request, this.getServletContext());
            
            for (Edu4_1Model model : list) {
            	
                JSONObject obj = new JSONObject();
                obj.put("FACTORY_CODE", 	  model.getFACTORY_CODE());
                result.add(obj);
            }
        } catch (Exception e) {
            JSONObject error = new JSONObject();
            error.put("success", false);
            error.put("message", e.toString());
            result.add(error);
        }

        PrintWriter out = response.getWriter();
        out.print(result.toJSONString());
        out.flush();
    }
}

```

모든 라인의 정보를 쿼리로 일일히 가져온뒤 model에 set된 상태에서 서블릿단에서는 모델내에 Set되어 

있는 정보를 일일히 다시 Get해온뒤 list에 담아주는 과정을 거치고있음.

## 현 코드의 문제점

- List 프로시저이기 때문에 조회에 필요한 쿼리 이외로는 사용되는바가 없음 (service단에 sql이 무의미함)
- 조회기능만 수행하면 되는데 List 서블릿에서 모델을 설정하고 Service를 호출해서 쿼리를 실행한뒤에 모델에 담고 그 모델을 get해오는 과정이 매우 비효율적임.
