# 스프링 MVC(**Spring MVC**)

- 스프링 MVC는 모델-뷰-컨트롤러(MVC) 아키텍처를 기반으로 한 웹 애플리케이션 개발을 위한 프레임워크입니다.
- 역할
    - **모델(Model)**
        - 비즈니스 로직을 처리하고 데이터를 다룹니다.
        - 데이터베이스와의 상호 작용, 데이터 가공, 비즈니스 로직 구현 등을 수행합니다.
    - **뷰(View)**
        - 클라이언트에게 보여지는 화면을 생성하고 표현합니다.
        - HTML, JSP, Thymeleaf 등의 템플릿 엔진을 사용하여 동적인 웹 페이지를 생성합니다.
    - **컨트롤러(Controller)**
        - 클라이언트의 요청을 받아들이고, 요청에 대한 처리를 담당합니다.
        - 적절한 모델을 호출하여 비즈니스 로직을 처리하고, 그 결과를 적절한 뷰에 전달하여 응답을 생성합니다.

- 스프링 MVC는 `**@Controller**` 어노테이션을 사용하여 컨트롤러를 정의하고, HTTP 요청을 처리할 수 있습니다.
- 뷰는 JSP, Thymeleaf, Freemarker 등의 템플릿 엔진을 사용하여 생성할 수 있습니다.

## 동작원리

1. 클라이언트의 HTTP 요청이 들어오면, 스프링 MVC는 요청을 처리할 적절한 컨트롤러를 결정합니다.
2. 해당 컨트롤러는 요청에 따라 적절한 모델을 호출하여 비즈니스 로직을 처리합니다.
3. 처리된 결과는 적절한 뷰에 전달되어 뷰는 이를 템플릿 엔진을 사용하여 클라이언트에게 보여줍니다.
4. 클라이언트에게 응답이 전달됩니다.

## 예시

**전자상거래 웹 애플리케이션에서의 주문 관리**

### **모델(Model)**

- 모델은 주문 정보를 처리하는 데 사용됩니다.
- 주문 정보를 데이터베이스에 저장하거나 검색하는 등의 작업을 수행합니다.
- 예를 들어, 사용자가 제품을 주문하면, 주문 정보를 생성하여 데이터베이스에 저장하고, 주문 상태를 확인하거나 취소하는 등의 작업을 처리합니다.

### **뷰(View)**

- 뷰는 사용자에게 보여지는 화면을 생성하고 표현하는 데 사용됩니다.
- 제품 상세 페이지는 제품의 이미지, 설명, 가격 등을 포함하고 있습니다.
- 사용자가 웹 페이지를 방문하면, 제품 상세 정보가 동적으로 생성되어 보여집니다.
- 사용자는 이 페이지에서 제품을 구매할 수 있습니다.

### **컨트롤러(Controller)**

- 컨트롤러는 클라이언트의 요청을 받아들이고, 해당 요청을 처리하는 역할을 합니다.
- 예를 들어, 사용자가 주문을 완료하면, 주문 처리를 위한 컨트롤러가 이를 수신합니다.
- 컨트롤러는 해당 요청을 처리하기 위해 주문 서비스를 호출하고, 주문 정보를 생성하거나 데이터베이스에 저장합니다.
- 그 후, 적절한 뷰에 결과를 전달하여 사용자에게 응답합니다.


5. 클라이언트가 요청을 보냅니다.
6. 요청을 받은 컨트롤러는 해당 요청을 처리하기 위해 적절한 모델을 호출합니다.
7. 모델은 요청을 처리하고 결과 데이터를 생성합니다.
8. 컨트롤러는 결과 데이터를 적절한 뷰에 전달합니다.
9. 뷰는 결과 데이터를 사용하여 사용자에게 적절한 방식으로 정보를 표시합니다.
10. 클라이언트는 뷰에서 제공된 정보를 받아들이고 사용자 인터페이스를 통해 사용자와 상호 작용합니다.

- `**@Controller**`는 주로 View와 함께 사용되어 HTML을 반환하거나 동적인 웹 페이지를 렌더링하는 데에 사용됩니다.
- `**@RestController**`는 주로 데이터를 반환하고, 클라이언트와의 API 통신에 사용됩니다. 반환된 데이터는 직렬화되어 클라이언트에게 전송됩니다.
