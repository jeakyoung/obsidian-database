# 재고 보정 및 ERP/MES 데이터 동기화

## 목표

신진SM ERP 시스템의 창고별 재고 정확성을 확보하고, MES 시스템과의 데이터 동기화를 정상화

---

## 현황 분석

### 재고 불일치 원인

```
포장 중복 문제 발생
  ↓
MES: 롤백 성공 (올바른 상태)
  ↓
ERP: 롤백 실패
  ↓
ERP에 마이너스(-) 재고 발생
  ↓
수불 상태 왜곡 → 장부와 실제 불일치
```

### 영향 받는 창고

| 창고코드 | 창고명 | 상태 | 조정 필요 |
|---------|--------|------|----------|
| 1000 | 공장 창고 | 미정 | ✓ |
| 001 | 자재창고(정남) | 마이너스 재고 발생 | ✓ |
| (상품창고) | 정남 상품창고 | 미정 | ✓ |

## 재고 보정 계획

### 1단계: 데이터 감사 및 현황 파악

#### 확인 대상
```sql
-- 마이너스 재고 조회
SELECT 
    WAREHOUSE_CODE,
    WAREHOUSE_NAME,
    MATERIAL_CODE,
    SYSTEM_LOT_NO,
    SUM(IN_QTY) - SUM(OUT_QTY) AS CURRENT_QTY,
    CASE WHEN SUM(IN_QTY) - SUM(OUT_QTY) < 0 
         THEN '마이너스' 
         ELSE '정상' 
    END AS STATUS
FROM TMA922M
WHERE PLANT_CODE = '000001'
GROUP BY WAREHOUSE_CODE, WAREHOUSE_NAME, MATERIAL_CODE, SYSTEM_LOT_NO
HAVING SUM(IN_QTY) - SUM(OUT_QTY) < 0
```

#### 수집 항목
- 마이너스 재고 목록
- 발생 날짜 및 공정
- 원인 추정 (포장 중복/기타 오류)
- 수량

### 2단계: 정정 입고 등록

#### 개요
더존 ERP에 정정 입고(계정 대체 입고)를 등록하여 마이너스 재고를 정상화

#### 절차

**단계 2-1: 정정 입고 데이터 준비**
```json
{
  "FACTORY_CODE": "000001",
  "PLANT_CODE": "000001",
  "PLANT_NAME": "정남사업장",
  "IO_TYPE": "계정대체입고",
  "INPUT_WAREHOUSE_CODE": "001",
  "INPUT_WAREHOUSE_NAME": "자재창고(정남)",
  "MATERIAL_CODE": "0000792977",
  "MATERIAL_NAME": "PLATE SM후판",
  "SYSTEM_LOT_NO": "A0000116371",
  "IO_QTY": 5,
  "IO_DATE": "20260610",
  "REMARK": "포장중복문제 정정입고"
}
```

**단계 2-2: SP_WMA624_01_IUD 호출**
```sql
EXEC SP_WMA624_01_IUD
    @FACTORY_CODE = '000001',
    @IO_NO = '',  -- 자동 생성
    @IO_FLAG = '1',  -- 입고
    @ACC_FLAG = '001',  -- 계정 대체
    @ALTER_MATERIAL_CODE = '0000792977',
    @IO_DATE = '20260610',
    @IO_QTY = 5,
    @IN_WAREHOUSE_CODE = '001',
    @IN_LOCATION_CODE = '000000',
    @SYSTEM_LOT_NO = 'A0000116371',
    @PLANT_CODE = '000001',
    @REMARK = '포장중복문제 정정입고',
    @IRU = 'IU'
```

**단계 2-3: 더존 동기화**
```java
// UP_PU_ITR_UPDATE 호출로 더존 ERP에도 반영
callDozenFunction("UP_PU_ITR_UPDATE", 
    materialCode = '0000792977',
    systemLotNo = 'A0000116371',
    qty = 5,
    warehouseCode = '001'
)
```

### 3단계: 수불 상태 확인 및 정정

#### 확인 대상
```
공장(1000) 
  ↓ 제품
  → 상품창고(정남) 
    ↓ 수불 상태 확인
```

#### 수불 상태 검증
```sql
-- 공장 → 상품창고 이송 현황
SELECT 
    A.MATERIAL_CODE,
    A.SYSTEM_LOT_NO,
    A.WAREHOUSE_CODE,
    SUM(A.IN_QTY) - SUM(A.OUT_QTY) AS STOCK_QTY,
    B.STATUS
FROM TMA922 A
LEFT JOIN TMA536 B  -- 계정 대체 출고
    ON A.MATERIAL_CODE = B.MATERIAL_CODE
    AND A.SYSTEM_LOT_NO = B.SYSTEM_LOT_NO
WHERE A.PLANT_CODE = '000001'
  AND A.WAREHOUSE_CODE IN ('1000', '???')  -- 공장 및 상품창고
GROUP BY A.MATERIAL_CODE, A.SYSTEM_LOT_NO, A.WAREHOUSE_CODE, B.STATUS
```

## 기술 상세

### 관련 테이블 및 프로시저

#### 테이블 구조
```
TMA536 (계정대체출고)
├─ FACTORY_CODE (사업장)
├─ IO_NO (입출고번호)
├─ IO_FLAG (입출고 구분: 1=입고, 2=출고)
├─ ACC_FLAG (계정코드)
├─ MATERIAL_CODE (자재코드)
├─ SYSTEM_LOT_NO (LOT번호)
├─ IO_QTY (수량)
├─ WAREHOUSE_CODE (창고)
└─ IO_DATE (거래일자)

TMA922M (재고 현황)
├─ WAREHOUSE_CODE
├─ MATERIAL_CODE
├─ SYSTEM_LOT_NO
├─ IN_QTY (입고누계)
└─ OUT_QTY (출고누계)
```

#### ERP/MES 데이터 흐름
```
MES 작업 완료
  ↓
SP_WMA624_01_IUD (우리 ERP)
  ├─ TMA536 업데이트
  ├─ TMA922 업데이트
  ↓
더존 ERP 동기화
  ├─ UP_PU_ITR_UPDATE 호출
  └─ 더존 시스템 반영
```
