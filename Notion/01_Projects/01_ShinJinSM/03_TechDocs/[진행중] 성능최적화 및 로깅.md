# 성능 최적화 및 로깅 구현

## 목표

신진SM 시스템의 응답 속도 개선 및 병목 구간 식별을 위한 로깅 시스템 구축

---

## 현황

### 로깅 완료 구간
- ✅ 포장 공정
- ✅ 출하 공정

### 로깅 필요 구간
- ❌ 길이 절단 공정 (우선순위 1)
- ❌ 기타 공정

---

## 성능 병목 분석

### 발생 패턴
```
정상 응답: 2-3초
Spike (튀는 현상): 10초 이상

발생 빈도: [TBD - 데이터 수집 필요]
원인: [TBD - 로그 분석 필요]
```

### 성과 측정 방식

#### 1. 시간대별 분석
```
시간대: 09:00-10:00, 10:00-11:00, ...
측정: 각 시간대별 평균 응답 시간
목표: 구간별 편차 30% 이내
```

#### 2. 횟수별 튀는 현상(Spike) 추적
```
측정 항목: 5초 이상 지연 발생 건수
기준: 일일 건수, 시간대별 건수
목표: 월 5건 이하로 감소
```

#### 3. 개선 전후 비교
```
개선 전 (2026-05-01 ~ 05-31):
  - 평균 응답 시간: [TBD]
  - Spike 발생률: [TBD]
  
개선 후 (2026-06-01 ~ 06-30):
  - 목표: 30% 이상 개선
```

## 구현 방안

### 1단계: 길이 절단 공정 로깅 추가

#### 로그 수집 위치
```
길이 절단 공정 시작
  ↓ [로그 기록 - 시작 시간]
길이 계산
  ↓ [로그 기록 - 계산 시간]
재고 업데이트
  ↓ [로그 기록 - 업데이트 시간]
길이 절단 공정 완료
  ↓ [로그 기록 - 종료 시간, 총 소요 시간]
```

### 2단계: 타임아웃 재시도 메커니즘

#### Fallback 및 재시도 정책
```
요청 → 처리 시작
  ↓
5초 경과 감지
  ↓
[Fallback 1] 캐시 반환 또는 부분 결과 반환
  ↓
1초 대기 (exponential backoff)
  ↓
[Retry 1] 재시도
  ↓
실패 → [Retry 2] 2초 대기 후 재시도
  ↓
최종 실패 → 오류 응답 및 로깅
```

#### 재시도 설정
```java
public class ProcessRetryConfig {
    public static final int MAX_RETRIES = 3;
    public static final long TIMEOUT_MS = 5000; // 5초
    public static final long INITIAL_BACKOFF_MS = 1000; // 1초
    
    // exponential backoff: 1초, 2초, 4초
    public long getBackoffTime(int attemptNumber) {
        return INITIAL_BACKOFF_MS * (long) Math.pow(2, attemptNumber - 1);
    }
}
```

### 3단계: 실시간 모니터링 대시보드

#### 수집할 메트릭
- 공정별 평균 응답 시간
- 시간대별 응답 시간 분포
- 5초 이상 지연 발생 건수 (일일/주간/월간)
- 재시도 발생 빈도
- 최종 실패율
