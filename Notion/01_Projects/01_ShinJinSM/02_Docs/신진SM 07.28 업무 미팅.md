작업 배경
                                                                                                                                                                        
  IPlusMES 프로젝트 (E:\ajk\dev\SINJIN\IPlusMES)에서 일반수주 포장(WORK_CODE=005) 저장 시 포장입고가 항상 출하창고로 생성되는 버그가 있다. 이전 공정 실적이 없이 포장
  단독으로 생산일보를 생성하는 경우에는 제품창고로 입고되어야 한다.                                                                                                     
                  
  ---
  흐름 정리

  1. 프론트(WPR559_CT.js) 에서 WORK_CODE=005 선택 후 저장 시 packing=1 파라미터를 jvWPR559_01_IUD 서블릿으로 전송
  2. jvWPR559_01_IUD.java에서 packing=1이면 ProdSLService.processSLCrossMove() 호출
  3. processSLCrossMove() 진입 전에 jvPROD_DATA_FETCH.fetchProductionPlanSecure()가 실행되어 해당 생산계획(PRODPLAN_DATE + PRODPLAN_SEQ)에 WORK_CODE != '005'인 이전
  실적이 있으면 SL_ETC에 TCO102.ETC 값을 세팅, 없으면 null
  4. ProdSLService.java 226라인에서 SL_ETC == null 여부로 분기
    - SL_ETC == null → 이전 실적 없음(포장 단독) → 생산일보 + 창고이동 전체 생성
    - SL_ETC != null → 이전 실적 있음 → 포장만 처리
  5. 버그: 라인 982~990에서 이 분기와 무관하게 창고코드를 plantCode 기준으로 무조건 016(출하창고)으로 하드코딩

  수정 내용

  SL_ETC 값 기준으로 창고코드를 분기 처리한다.
  - SL_ETC에 값이 있음(이전 실적 있음) → 출하창고
  - SL_ETC가 null(포장 단독 생성) → 제품창고

  수정 전:
  String warehouseCode = "";
  if("000001".equals(plantCode)) {
      warehouseCode = "016";
  } else if("000002".equals(plantCode)){
      warehouseCode = "225";
  }

  수정 후 방향 (제품창고 코드는 아래 쿼리로 먼저 확인 후 반영):
  String warehouseCode = "";
  String slEtc = sanitizeInput(String.valueOf(jsonObject.get("SL_ETC")));
  boolean hasPrevRecord = slEtc != null && !slEtc.isEmpty() && !"null".equals(slEtc);

  if (hasPrevRecord) {
      // 이전 실적 있음 → 출하창고
      if("000001".equals(plantCode)) { warehouseCode = "016"; }
      else if("000002".equals(plantCode)) { warehouseCode = "225"; }
  } else {
      // 포장 단독 → 제품창고 (TCO102 조회 후 코드 확정 필요)
      if("000001".equals(plantCode)) { warehouseCode = "확인필요"; }
      else if("000002".equals(plantCode)) { warehouseCode = "확인필요"; }
  }
