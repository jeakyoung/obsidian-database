## 주요 안건

### 1️⃣ 포장 중복 문제 (우선순위: ⭐⭐⭐⭐⭐)

**문제 상황:**
- **발생 위치:** 제품창고 - 절단공정
- **원인:** 처리 중 타임아웃 → 롤백 → 동일 작업 재진행 시 중복 발생
- **현재 상태:**
  - MES: 포장 원천 차단 완료
  - ERP: 여전히 중복 데이터 발생 (마이너스 데이터)

**기술적 문제:**
- MES에서는 트랜잭션 롤백 정상 작동
- ERP에서는 롤백 미작동
- 시스템 완료 피드백과 실제 완료 상태 불일치

**해결 방안:**
- SP_WMA624_01_IUD 저장 동작 시 더존 UP_PU_ITR_UPDATE 함수 함께 호출
- ERP 상에도 자동 반영될 수 있도록 수정

**담당자:** [미정] | **예상 완료:** 2026-06-10

**기술 개선:**
- 타임아웃 발생 시 fallback 후 자동 재시도 메커니즘 추가

### ERP/MES 연동 아키텍처

#### 문제점 분석
```
MES 처리 결과    →    [타임아웃/롤백]    ←    ERP 반영 결과
   (정상)                              (미동기)
```

#### 해결 방안: 연동 함수 추가

**더존 입고조정 함수 호출:**
- `UP_PU_ITR_UPDATE` - 입고조정
- `UP_PU_CGI_UPDATE` - (기타 조정)

**Java 연결 코드:**

### 저장 프로시저 상세 (SP_WMA624_01_IUD)

**위치:** `iPlusERP_SJ.dbo.SP_WMA624_01_IUD`

**주요 기능:**
- IO_NO 자동 생성 (없을 경우)
- 재고 부족 시 오류 처리
- 계정대체출고(TMA536) 테이블 업데이트/삽입/삭제

**재고 검증 로직:**
```sql
-- 재고 부족 검증 (IO_FLAG = '2')
IF @IO_FLAG = '2' BEGIN
    -- 재고량 정보 JOIN으로 검증
    -- STOCK_QTY < @IO_QTY 인 경우 오류 발생
    SET @ERR_MSG = '[LOT] ' + @SYSTEM_LOT_NO + ' 현재재고가 변경되어 수량이 부족합니다.'
END
```
