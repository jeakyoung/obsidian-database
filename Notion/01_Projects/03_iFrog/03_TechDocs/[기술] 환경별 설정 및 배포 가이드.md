# I-Frog 환경별 설정 및 배포 가이드

**시스템:** I-Frog POS 시스템  
**범위:** 개발, 테스트, 운영 환경 설정

## 📋 개요

I-Frog의 3가지 환경(DEV, TEST, PROD)에 대한 설정 자동화 및 배포 절차

### 환경 특성

| 환경 | 용도 | 성능 요구 | 보안 수준 | 데이터 | 규모 |
|------|------|---------|---------|--------|------|
| **DEV** | 개발/테스트 | 낮음 | 낮음 | 더미 데이터 | 소규모 |
| **TEST** | QA/통합테스트 | 중간 | 중간 | 테스트 데이터 | 중규모 |
| **PROD** | 운영 | 높음 | 높음 | 실제 데이터 | 대규모 |

## ⚙️ 환경 설정 (Env 다형성)

### 1️⃣ 설정 파일 구조

```
src/main/resources/
├── application.yml (공통 설정)
├── application-dev.yml (개발)
├── application-test.yml (테스트)
├── application-prod.yml (운영)
└── config/
    ├── dev-firebase.json
    ├── test-firebase.json
    └── prod-firebase.json
```

### 2️⃣ 공통 설정 (application.yml)

```yaml
spring:
  application:
    name: ifrog-pos-system
  
  jpa:
    hibernate:
      ddl-auto: validate  # 환경별로 override
    show-sql: false
    
  datasource:
    hikari:
      minimum-idle: 5
      maximum-pool-size: 20
      
logging:
  level:
    root: INFO
```

### 3️⃣ 개발 환경 (application-dev.yml)

```yaml
spring:
  profiles: dev
  
  datasource:
    url: jdbc:sqlserver://localhost:1433;databaseName=ifrog_dev
    username: sa
    password: ${DB_PASSWORD_DEV}
    driver-class-name: com.microsoft.sqlserver.jdbc.SQLServerDriver
    hikari:
      maximum-pool-size: 10
      connection-timeout: 10000
  
  jpa:
    hibernate:
      ddl-auto: update  # 테이블 자동 생성
    show-sql: true
  
  redis:
    host: localhost
    port: 6379
    database: 0  # 개발용 DB
  
server:
  port: 8080
  
firebase:
  credentials-path: classpath:config/dev-firebase.json
  project-id: ifrog-dev-project
  
logging:
  level:
    root: DEBUG
    org.springframework.web: DEBUG
    org.hibernate.SQL: DEBUG
```

### 4️⃣ 테스트 환경 (application-test.yml)

```yaml
spring:
  profiles: test
  
  datasource:

      maximum-pool-size: 15

    root: INFO
```

### 5️⃣ 운영 환경 (application-prod.yml)

```yaml
spring:
  profiles: prod
  
  datasource:
    url: jdbc:sqlserver://prod-db:1433;databaseName=ifrog_prod

    password: ${DB_PASSWORD_PROD}
    hikari:

      connection-timeout: 30000

  level:
    root: WARN
    com.ifrog: INFO

    name: /var/log/ifrog/application.log
    max-size: 10MB
    max-history: 30
```

## 🚀 배포 프로세스

### 1️⃣ 빌드 단계

```bash
# 개발 환경 빌드
mvn clean package -P dev

# 테스트 환경 빌드
mvn clean package -P test

# 운영 환경 빌드 (최적화)
mvn clean package -P prod -DskipTests
```

### 2️⃣ Docker 배포

#### Dockerfile
```dockerfile
FROM openjdk:11-jre-slim

ARG ENVIRONMENT=prod

COPY target/ifrog-pos-system.jar app.jar

ENV SPRING_PROFILES_ACTIVE=${ENVIRONMENT}
ENV JAVA_OPTS="-Xmx1g -Xms512m"

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "/app.jar"]
```

#### Docker Compose (개발 환경)
```yaml
version: '3.8'
services:
  ifrog-dev:
    build:
      context: .
      args:
        ENVIRONMENT: dev
    ports:
      - "8080:8080"
    environment:
      SPRING_PROFILES_ACTIVE: dev
      DB_PASSWORD_DEV: ${DB_PASSWORD_DEV}
    depends_on:
      - sqlserver-dev
      - redis-dev
    networks:
      - ifrog-network
  
  sqlserver-dev:
    image: mcr.microsoft.com/mssql/server:2019-latest
    environment:
      SA_PASSWORD: ${SA_PASSWORD}
      ACCEPT_EULA: "Y"
    ports:
      - "1433:1433"
    networks:
      - ifrog-network
  
  redis-dev:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    networks:
      - ifrog-network

networks:
  ifrog-network:
    driver: bridge
```

### 3️⃣ Kubernetes 배포 (운영)

#### Deployment 매니페스트
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ifrog-prod
spec:
  replicas: 3
  selector:
    matchLabels:
      app: ifrog-prod
  template:
    metadata:
      labels:
        app: ifrog-prod
    spec:
      containers:
      - name: ifrog-pos
        image: registry.example.com/ifrog:latest
        imagePullPolicy: Always
        ports:
        - containerPort: 8080
        env:
        - name: SPRING_PROFILES_ACTIVE
          value: "prod"
        - name: DB_USER_PROD
          valueFrom:
            secretKeyRef:
              name: ifrog-secrets
              key: db-user
        - name: DB_PASSWORD_PROD
          valueFrom:
            secretKeyRef:
              name: ifrog-secrets
              key: db-password
        resources:
          requests:
            memory: "512Mi"
            cpu: "250m"
          limits:
            memory: "1Gi"
            cpu: "500m"
        livenessProbe:
          httpGet:
            path: /actuator/health
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /actuator/health/readiness
            port: 8080
          initialDelaySeconds: 20
          periodSeconds: 5
```

## 🔒 보안 설정

### 1️⃣ 환경 변수 관리

```bash
# .env.dev
DB_PASSWORD_DEV=
FIREBASE_ADMIN_SDK_DEV=$(cat config/dev-firebase.json | base64)

# .env.test (테스트 서버에만)
DB_USER_TEST=testuser
DB_PASSWORD_TEST=${DEV_TEST_PASSWORD}

# .env.prod (운영 서버 - 절대 커밋 금지)
DB_USER_PROD=produser
DB_PASSWORD_PROD=${SECURE_PROD_PASSWORD}
```

### 2️⃣ Secrets 관리 (Kubernetes)

```bash
# Secret 생성
kubectl create secret generic ifrog-secrets \
  --from-literal=db-user=produser \
  --from-literal=db-password= \
  --from-file=firebase-key=config/prod-firebase.json

# Secret 확인
kubectl get secrets ifrog-secrets -o yaml
```

### 3️⃣ HTTPS/SSL 설정

```yaml
# application-prod.yml
server:
  ssl:
    key-store: classpath:keystore.p12
    key-store-password: ${SSL_KEYSTORE_PASSWORD}
    key-store-type: PKCS12
    key-alias: ifrog-prod
    enabled: true
  http2:
    enabled: true
```

## 🔄 배포 롤백 절차

### 1️⃣ 이전 버전으로 롤백

```bash
# 현재 배포 확인
kubectl get deployment ifrog-prod -o wide

# 이전 버전으로 롤백
kubectl rollout undo deployment/ifrog-prod

# 롤백 히스토리 확인
kubectl rollout history deployment/ifrog-prod

# 특정 버전으로 롤백
kubectl rollout undo deployment/ifrog-prod --to-revision=2
```

### 2️⃣ 데이터베이스 롤백

```bash
# 마지막 백업 복원
sqlserver-cli -S prod-db -U sa -P password << EOF
RESTORE DATABASE ifrog_prod 
FROM DISK = '/backups/ifrog_prod_20260611.bak'
GO
EOF
```
