## 🔧 주요 수정 사항

### 1️⃣ 근무조별 일근태등록 (WHR314_VW) 개선

**요청 배경:**  
근무조별 일근태등록 화면에서 사용자 경험 개선 및 데이터 정확성 확보 필요

**주요 수정 내용:**

#### 1-1. 기본근무 자동 적용
```javascript
// 기본근무 적용 시
근무조 선택 → 해당 근무조 기본근무시간 자동 입력
예) 주간조 선택 → 09:00~18:00 자동 입력
기록 컬럼에 'O' 마킹
```

**상태:** ✅ 완료

#### 1-2. 시간 계산식 정확화
- **문제:** 분단위 표와 계산 결과 불일치
- **원인:** 분단위 반올림 규칙 미적용
- **해결:** 분단위를 10분 단위로 일관화 처리
  ```
  반올림 규칙:
  - 지각, 조퇴: ceil 처리 (올림)
  - 시간외: floor 처리 (내림)
  ```

**상태:** ✅ 완료

#### 1-3. 근무시간 시간 수정 기능
- **문제:** 입실/퇴실 시간 수정 시 뒷쪽 근태정보가 자동 수정 안됨
- **원인:** 시간 수정과 근태정보 계산이 분리되어 있음
- **해결:** 수정 시 자동 재계산 로직 추가

**상태:** ✅ 완료

#### 1-4. 외출 시간 조건 개선
- **문제:** 외출시간이 다음 날로 넘어가는 경우 조건 오류 발생
- **원인:** BETWEEN 절에서 범위 제한이 부정확
- **해결:** KT_DATE(당일)에만 비교하는 조건으로 수정

**상태:** ✅ 완료

### 2️⃣ 시간계산 로직 개선 (WHR314_CT.js)

**수정 배경:**  
시간 계산 함수에서 출퇴근 시간, 외출 시간, 특근 시간의 계산이 부정확하고 일관성 부족

**수정 함수:**

#### convertToMinusHour (지각/조퇴 - 올림)
```javascript
// 지각, 조퇴 등 불리한 항목: ceil 처리
convertToMinusHour(rawTime) {
  // 분 단위: ceil(분/10)*10
  minutes = Math.ceil(minutes / 10) * 10;
  // 60분 → 1시간 올림
  return (hours + minutes/60).toFixed(2);
}
```

#### convertToPlusHour (초과근무 - 내림)
```javascript
// 시간외: floor 처리
convertToPlusHour(rawTime) {
  // 분 단위: floor(분/10)*10
  minutes = Math.floor(minutes / 10) * 10;
  return (hours + minutes/60).toFixed(2);
}
```

#### convertToNightHour (야간근무)
```javascript
// 야간근무 계산: 24시간 기준
nightHour = 24.0 + (hours + minutes/60)
// 예: 22:00 ~ 06:00 = 8시간
```

**주요 개선:**
- 시간:분 형식 처리 (HH:MM)
- HHMM 형식 처리 (HHMM)
- NULL/빈값 처리
- 올림/내림 일관화

**상태:** ✅ 완료

### 4️⃣ 기간별 근태현황 (WHR313) 최적화

**문제점:**
- 조회 속도가 매우 느림
- 데이터 일관성 문제
- TIN334 테이블 KT_DATE 조회 오류

**기술 분석:**

#### 문제 원인
```
1. TIN334_GET_KDDATE 프로시저 동작 오류
   → CTE 조건으로는 분별 불가능한 데이터 발생

2. 저장 여부에 따른 테이블 다름
   - 저장 안된 경우: TIN334 참조
   - 저장된 경우: TIN313 참조
   → 두 경로 모두 처리 필요

3. 성능 이슈
   - 대량 데이터 조회 시 timeout 발생
   - 쿼리 최적화 필요
```

**개선 계획:**
1. KT_DATE 조건 검증 로직 추가
2. 저장 상태별 조회 로직 분리
3. 쿼리 인덱스 최적화
4. 캐싱 메커니즘 추가

**상태:** 🔄 진행중 (2026-01 예정)
