## 💡 주요 프로젝트를 통한 역량 증명

### 프로젝트 1: 신진SM ERP/MES 통합 시스템 - 성능 최적화 리드

**상황 (Situation):**  
신진SM의 ERP/MES 연동 시스템에서 **응답 지연 문제**와 **데이터 동기화 오류**가 발생하고 있었습니다. 포장 시스템에서 중복 데이터가 생성되어 재고 정합성이 깨지는 심각한 문제였습니다.

**과제 (Task):**  
문제의 근본 원인을 파악하고 응답시간을 **30% 이상 단축**하면서 데이터 정합성을 **100% 보장**해야 했습니다.

**행동 (Action):**

1. **문제 분석 (근본 원인 파악)**
   - MES/ERP 간 동기화 로직 상세 분석
   - 3가지 근본 원인 식별 (타이밍 이슈, 중복 검증 부재, 타임아웃 미처리)
   - 4단계 해결 방안 수립

2. **성능 최적화 구현**
   ```
   최적화 전략:
   - SQL 쿼리 리팩토링 (N+1 문제 해결)
   - 인덱스 재설계
   - 캐싱 메커니즘 도입 (자주 조회하는 데이터)
   - 배치 처리 로직 개선
   ```
   - 길이 절단 공정의 로깅 추가로 병목 지점 파악
   - 타임아웃 재시도 메커니즘 구현

3. **데이터 정합성 보장**
   - 중복 검증 로직 추가
   - 마이너스 재고 정정 프로세스 정의
   - 데이터 마이그레이션 검증 프로세스 구축

**결과 (Result):**
- 응답시간 **30% 이상 개선** (목표 달성)
- 포장 중복 문제 **근본 해결**
- 데이터 정합성 **100% 보장 메커니즘 구축**
- 실시간 모니터링 대시보드 완성

**배운 점:**
> "복잡한 문제일수록 근본 원인을 정확히 파악하는 것이 중요하다. 겉으로 보이는 증상이 아닌 시스템 전체를 통합적으로 분석해야 한다."

### 프로젝트 2: IPACK 근태 시스템 - 정확도 개선

**상황 (Situation):**  
근태 시스템의 시간 계산 로직에 오류가 있어 직원들의 근무 시간이 정확하게 집계되지 않고 있었습니다. 지각, 조퇴, 초과근무 시간 계산에 일관성이 없었습니다.

**과제 (Task):**  
근무 시간 계산 로직을 개선하여 **정확도 100% 달성**해야 했습니다.

**행동 (Action):**

1. **근본 원인 분석**
   - 시간 계산식의 반올림 방식 문제 파악
   - 외출 조건 로직 오류 발견
   - 근무조별 자동 적용 로직 부재

2. **개선 사항 구현**
   ```
   Before: 다양한 반올림 방식으로 인한 오차
   After: ceil/floor 처리로 지각/조퇴/초과시간 명확히 구분
   ```
   - 외출 시간을 동일 날짜 조건으로 제한
   - 기본근무 선택 시 자동 계산 로직 추가
   - JSP UI 업데이트

3. **검증 및 문서화**
   - 다양한 시나리오 테스트
   - 기술 가이드 작성 (미래 유지보수 대비)

**결과 (Result):**
- 근무 시간 계산 정확도 **100% 달성**
- 근무자 민원 **0건**
- 유지보수 시간 **30% 단축** (문서 덕분)

**배운 점:**
> "숫자 계산 로직은 절대 대충할 수 없다. 엣지 케이스를 고려하고 테스트를 철저히 해야 한다."

### 프로젝트 3: I-Frog POS 시스템 - 아키텍처 설계

**상황 (Situation):**  
음식점의 주문 정보를 **실시간으로 알림**하는 기능이 필요했습니다. 또한 시스템의 응답 지연으로 인한 사용자 불편이 있었습니다.

**과제 (Task):**
- Firebase FCM을 이용한 **실시간 알림 시스템** 구현
- 데이터베이스 **Connection Pool 최적화**
- **환경별 배포 자동화** (개발/스테이징/운영)

**행동 (Action):**

1. **FCM 알림 시스템 설계**
   - API 엔드포인트 설계 (5개)
   - 실시간 주문 알림 시나리오 정의 (3가지)
   - 실패 시나리오 대응 방법 정의

2. **데이터베이스 최적화**
   ```
   최적화 항목:
   - Connection Pool 설정 (HikariCP)
   - TGI003 테이블 구조 설계 (정규화)
   - 자주 쿼리하는 데이터 캐싱
   ```

3. **배포 자동화 문서화**
   - 3가지 환경별 yml 완전 예제 작성
   - Docker 이미지 빌드 가이드
   - Kubernetes 배포 스크립트
   - 보안 설정 (환경변수 관리)

**결과 (Result):**
- FCM 기본 기능 **완전히 구현**
- 배포 시간 **50% 단축** (자동화)
- 신규 개발자 온보딩 시간 **50% 감소** (문서)

**배운 점:**
> "좋은 아키텍처는 성능뿐 아니라 유지보수성과 확장성을 모두 고려한다. 특히 배포 자동화는 팀 전체의 생산성을 높인다."
