# 서블릿(Servlet)

서블릿(Servlet)은 자바 언어로 웹 애플리케이션을 개발하기 위한 기술입니다. 웹 서버와 통신하여 동적인 웹 컨텐츠를 생성하고 제공하는 자바 클래스입니다. 이를 통해 클라이언트의 요청을 처리하고 응답을 생성할 수 있습니다. 

[[[JAVA]Servlet]]

# 스프링 부트 **(Spring Boot)**

- 스프링 부트는 스프링 프레임워크 기반의 독립적으로 실행 가능한 웹 애플리케이션을 쉽게 개발하고 배포할 수 있도록 도와주는 도구입니다.
- 스프링 부트는 내장된 서블릿 컨테이너를 제공하며, 기본적으로 내장된 톰캣을 사용합니다. 이를 통해 별도의 서버 설정 없이도 쉽게 애플리케이션을 실행하고 배포할 수 있습니다.
- 또한, 스프링 부트는 스프링 프레임워크의 다양한 기능을 활용하여 웹 애플리케이션을 개발할 수 있도록 지원합니다. 이는 주로** 스프링 MVC**, 스프링 데이터, 스프링 시큐리티 등의 모듈을 통해 구현됩니다.
- 스프링 부트는 강력한 자동 구성(Auto-configuration) 기능을 제공하여 개발자가 별도의 설정 없이도 애플리케이션을 쉽게 구성할 수 있도록 도와줍니다.

# 비교

## **구조적 비교**

### **서블릿(Servlet)**

- 서블릿은 자바 기반의 웹 애플리케이션을 개발하기 위한 기술입니다.
- 서블릿은 HTTP 요청을 처리하고, HTTP 응답을 생성하는 자바 클래스입니다.
- 개발자가 직접 서블릿 클래스를 작성하고, 요청 및 응답을 처리하는 로직을 구현해야 합니다.

### **스프링 부트의 MVC(MVC Framework)**

- 스프링 부트의 MVC 프레임워크는 서블릿을 기반으로 동작하며, 스프링 프레임워크에서 제공하는 기능을 더욱 편리하게 사용할 수 있도록 지원합니다.
- 스프링 부트의 MVC는 서블릿 컨테이너 내에서 동작하며, 스프링의 컨트롤러(Controller)와 뷰(View) 기능을 사용하여 웹 애플리케이션을 개발합니다.

## **요청 처리 비교**

### **서블릿**

- 서블릿은 클라이언트의 HTTP 요청을 받아들이고, 서블릿 컨테이너에 의해 실행됩니다.
- 개발자는 서블릿 클래스 내에서 요청을 처리하고, 응답을 생성하는 로직을 작성해야 합니다.

### **스프링 부트의 MVC**

- 스프링 부트의 MVC는 요청 처리를 담당하는 컨트롤러(Controller)를 정의하여 사용합니다.
- 개발자는 `**@Controller**` 어노테이션을 사용하여 컨트롤러를 작성하고, 각각의 요청을 처리하는 메서드를 정의합니다.

## **응답 생성 비교**

### **서블릿**

- 서블릿은 HTTP 응답을 생성하는 로직을 서블릿 클래스 내에서 작성해야 합니다.
- 개발자는 `**HttpServletResponse**` 객체를 사용하여 응답을 생성하고, 클라이언트에게 전송합니다.

### **스프링 부트의 MVC**

- 스프링 부트의 MVC는 뷰(View) 템플릿 엔진을 사용하여 응답을 생성합니다.
- 개발자는 컨트롤러에서 모델을 준비하고, 뷰 템플릿 엔진을 사용하여 해당 모델을 템플릿에 전달하여 응답을 생성합니다.

## **비즈니스 로직 처리 비교**

### **서블릿**

- 서블릿은 비즈니스 로직을 서블릿 클래스 내에서 직접 구현해야 합니다.
- 데이터베이스 액세스, 파일 처리 등의 로직은 개발자가 서블릿 클래스 내에서 구현해야 합니다.

### **스프링 부트의 MVC**

- 스프링 부트의 MVC는 서비스(Service)나 DAO(Data Access Object)와 같은 레이어를 사용하여 비즈니스 로직을 분리할 수 있습니다.
- 개발자는 컨트롤러에서 비즈니스 로직을 호출하고, 해당 로직은 서비스나 DAO에서 구현됩니다.

# 톰캣(Tomcat)

 톰캣은 자바 서버 페이지(JSP) 및 서블릿을 실행하는 데 사용되며, 동적인 웹 애플리케이션을 구축하기 위한 기반을 제공합니다. 

## ** 웹 서버와 서블릿 컨테이너**

- 톰캣은 웹 서버와 서블릿 컨테이너의 기능을 모두 제공합니다.
- 웹 서버 기능은 정적인 콘텐츠(HTML, 이미지 등)를 제공하고, 동적인 콘텐츠 요청을 서블릿 컨테이너로 전달합니다.
- 서블릿 컨테이너 기능은 동적인 웹 애플리케이션의 개발 및 실행을 담당합니다.

[[Notion/정보 저장소/Backend 동작원리 및 과정/Tomcat 서블릿 컨테이너]]

## **동작 과정**

### **클라이언트 요청 수신**

- 클라이언트로부터 HTTP 요청이 톰캣에 도착합니다.
- 톰캣의 웹 서버 부분이 요청을 수신하고, 해당 요청을 처리합니다.

### **정적 콘텐츠 처리**

- 요청된 자원이 정적인 경우(HTML 파일, 이미지 등) 톰캣의 웹 서버는 해당 자원을 찾아 클라이언트에 직접 반환합니다.

### **동적 콘텐츠 요청**

- 요청된 자원이 동적인 경우(서블릿, JSP 등) 톰캣의 서블릿 컨테이너가 요청을 받아들입니다.

### **서블릿 검색 및 실행**

- 서블릿 컨테이너는 요청된 URL에 해당하는 서블릿을 찾습니다.
- 서블릿이 메모리에 로드되어 있지 않은 경우, 필요한 서블릿을 메모리에 로드합니다.

### **서블릿 요청 처리**

- 요청된 서블릿은 해당 요청을 처리하고, 동적인 콘텐츠를 생성합니다.
- 서블릿은 요청에 따라 비즈니스 로직을 실행하고, 데이터베이스 액세스 등의 작업을 수행합니다.

### **응답 생성**

- 서블릿은 요청에 대한 처리가 완료되면, 클라이언트에게 반환할 응답을 생성합니다.
- 응답은 HTTP 응답 헤더와 본문으로 구성되며, 톰캣의 웹 서버를 통해 클라이언트에게 전송됩니다.

### **클라이언트 응답**

- 클라이언트는 톰캣으로부터 받은 응답을 처리하고, 사용자에게 콘텐츠를 표시합니다.


## **톰캣의 구성 요소**

- **Connector(커넥터)**: 클라이언트와의 연결을 관리하고, 요청을 서블릿 컨테이너로 전달합니다. 주로 HTTP, HTTPS, AJP 등의 프로토콜을 지원합니다.

[[Notion/정보 저장소/Backend 동작원리 및 과정/Tomcat Connector]]

- **Container(컨테이너)**: 서블릿 컨테이너와 JSP 컨테이너를 포함하며, 서블릿 및 JSP의 실행 환경을 제공합니다.
    [[[Tomcat] Container]]
- **Realm(렐름)**: 사용자 인증 및 권한 부여를 관리하는 컴포넌트로, 사용자 인증 정보를 제공합니다.
- **Logger(로거)**: 톰캣의 로그 메시지를 관리하고 기록하는 기능을 제공합니다.

# Spring Boot & Tomcat 

1. 클라이언트가 웹 애플리케이션에 HTTP 요청을 보냅니다.
2. 톰캣이 클라이언트의 요청을 받아들이고, 해당 요청을 처리하기 위해 스프링 부트 내장 서블릿 컨테이너로 전달합니다.
3. 스프링 부트는 요청에 해당하는 컨트롤러(Controller)를 찾아 실행합니다. 이때 스프링의 IoC(제어의 역전) 컨테이너가 관리하는 빈(Bean) 객체를 활용합니다.
    [[Notion/정보 저장소/Backend 동작원리 및 과정/Spring Boot IOC]]
4. 컨트롤러는 필요한 비즈니스 로직을 수행하고, 데이터를 처리하여 적절한 뷰(View)를 반환합니다.
5. 스프링 부트는 컨트롤러에서 반환한 뷰를 템플릿 엔진을 사용하여 렌더링하고, 클라이언트에게 응답으로 전송합니다.
6. 톰캣은 클라이언트로부터 받은 응답을 전달하고, 클라이언트는 해당 응답을 처리하여 결과를 표시합니다.
