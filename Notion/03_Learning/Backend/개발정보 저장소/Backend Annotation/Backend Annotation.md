# Annotation

어노테이션(Annotation)은 자바 프로그래밍 언어에서 소스 코드에 추가적인 정보를 제공하는 메타데이터의 형태입니다. 코드에 메타데이터를 포함시킴으로써 컴파일러나 다른 도구들이 프로그램을 분석하고 처리할 때 추가적인 정보를 활용할 수 있습니다.

- 메타데이터(metadata)란 데이터에 대한 데이터로, 즉 데이터를 설명하거나 해석하는 데 사용되는 데이터를 말합니다. 다시 말해, 메타데이터는 다른 데이터에 대한 정보를 제공하거나 해당 데이터를 이해하고 처리하는 데 도움이 되는 정보입니다.
    - 메타데이터는 일반적으로 데이터의 특성, 구조, 의미, 포맷, 유효성, 소유자 등에 대한 정보를 포함할 수 있습니다. 예를 들어, 음악 파일의 메타데이터에는 제목, 아티스트, 앨범, 장르, 발매 연도 등의 정보가 포함될 수 있습니다. 또한, 문서 파일의 메타데이터에는 작성자, 제목, 생성 날짜, 수정 날짜 등의 정보가 포함될 수 있습니다.

자바에서 어노테이션은 `**@**` 기호로 시작.

## 특징

1. **컴파일러에게 정보 제공:** 어노테이션은 컴파일러에게 소스 코드에 대한 부가적인 정보를 제공합니다. 이를 통해 컴파일러는 코드를 분석하고 특정한 작업을 수행할 수 있습니다.
2. **런타임에 사용 가능:** 어노테이션은 런타임에도 사용할 수 있습니다. 런타임에 리플렉션(reflection)을 통해 어노테이션 정보를 읽고 처리할 수 있습니다.
3. **코드의 문서화:** 어노테이션은 코드에 추가적인 문서화 정보를 제공할 수 있습니다. 이를 통해 코드를 보는 다른 개발자들이 코드의 의도를 더 잘 이해할 수 있습니다.
4. **커스텀 어노테이션:** 자바에서는 사용자가 직접 커스텀 어노테이션을 정의할 수 있습니다. 이를 통해 프로그램에 특정한 의미를 부여하거나 사용자 정의한 규칙을 적용할 수 있습니다.

## 목적

- 컴파일 타임 체크: 코드의 유효성 검사 또는 경고 메시지를 생성합니다.
- 런타임 처리: 런타임 환경에서 특정한 작업을 수행합니다.
- 코드 문서화: 코드의 의도를 문서화하거나 API 문서를 생성하는 데 사용됩니다.

## 어노테이션의 종류

5. **내장 어노테이션 (Built-in Annotations):** 자바에서 기본으로 제공하는 어노테이션으로, `**@Override**`, `**@Deprecated**`, `**@SuppressWarnings**` 등이 있습니다.
6. **메타 어노테이션 (Meta Annotations):** 다른 어노테이션을 위해 설계된 어노테이션으로, 어노테이션을 정의할 때 사용됩니다. `**@Target**`, `**@Retention**`, `**@Documented**`, `**@Inherited**` 등이 있습니다.
7. **사용자 정의 어노테이션 (Custom Annotations):** 개발자가 직접 정의하여 사용하는 어노테이션으로, 프로그램의 특정한 의미나 규칙을 부여하기 위해 만들어집니다.

### 내장 어노테이션

내장 어노테이션은 이미 자바에서 제공되는 어노테이션으로, 주로 코드의 구조나 동작을 명시하기 위해 사용됩니다.

```java
class Parent {
    void display() {
        System.out.println("Parent method");
    }
}

class Child extends Parent {
    @Override // @Override 어노테이션은 메소드가 부모 클래스의 메소드를 오버라이드 함을 나타냅니다.
    void display() {
        System.out.println("Child method");
    }
}

```

### **메타 어노테이션 (Meta Annotations)**

메타 어노테이션은 다른 어노테이션을 정의할 때 사용되며, 어노테이션의 동작을 제어하는 데 사용됩니다.

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME) // @Retention 어노테이션은 어노테이션의 유지 정책을 지정합니다.
public @interface CustomAnnotation {
    String value();
}

```

### `**@Target**`

`**@Target**` 어노테이션은 해당 어노테이션이 적용될 수 있는 대상(타겟)을 지정합니다. 스프링 부트에서는 보통 클래스, 필드, 메소드 등에 적용됩니다.

### `**@Retention**`

`**@Retention**` 어노테이션은 어노테이션의 유지 정책을 지정합니다. 스프링 부트에서는 주로 `**RUNTIME**` 유지 정책이 사용되어야 합니다. 이렇게 함으로써 런타임 시에 어노테이션 정보를 읽고 처리할 수 있습니다.

### ** **`**@Documented**`

`**@Documented**` 어노테이션은 해당 어노테이션이 자동으로 문서화되어야 함을 나타냅니다. 스프링 부트에서도 자동 문서화 기능을 활용하기 위해 이 어노테이션을 사용할 수 있습니다.

### ** **`**@Inherited**`

`**@Inherited**` 어노테이션은 어노테이션이 상속될 수 있음을 나타냅니다. 스프링 부트에서는 이 어노테이션이 자주 사용되지는 않지만, 필요에 따라 상속되는 어노테이션을 정의할 때 활용될 수 있습니다.

# 주요 어노테이션

### `**@Autowired**`

스프링 프레임워크에서 주입할 대상을 표시하는데 사용됩니다. 의존성 주입(Dependency Injection)을 위해 많이 활용됩니다.

### `**@RestController**`

스프링 MVC 컨트롤러에 대한 특수한 형태의 어노테이션으로, RESTful 웹 서비스의 엔드포인트를 정의하는 데 사용됩니다.

### `**@Service**`**, **`**@Repository**`**, **`**@Controller**`

스프링의 빈으로 등록될 클래스를 표시하는데 사용됩니다. 각각 비즈니스 로직, 데이터 액세스, 웹 컨트롤러에 사용됩니다.

### `**@RequestMapping**`**, **`**@GetMapping**`**, **`**@PostMapping**`

요청 매핑을 지정하는데 사용됩니다. 특정 URL에 대한 요청을 처리할 메소드를 지정하는 데 사용됩니다.

### `**@Transactional**`

 트랜잭션 관리를 위해 사용되는 어노테이션으로, 메소드나 클래스에 적용하여 트랜잭션 범위를 설정할 수 있습니다.

### `**@ComponentScan**`

스프링의 컴포넌트 스캔을 활성화하는데 사용됩니다. 지정된 패키지나 클래스를 기준으로 빈을 찾아 등록합니다.

### `**@Valid**`**, **`**@Validated**`

 데이터 유효성 검사를 수행하기 위해 사용됩니다. 주로 폼 데이터나 요청 객체의 유효성을 검증할 때 사용됩니다.

### `**@Configuration**`**, **`**@Bean**`

스프링의 자바 기반 설정을 표시하는데 사용됩니다. `**@Configuration**` 어노테이션이 붙은 클래스는 스프링의 설정 클래스로 인식되며, `**@Bean**` 어노테이션은 해당 메소드가 빈 객체를 생성하는 역할을 한다고 표시합니다.

### `**@RequestMapping**`**, **`**@GetMapping**`**, **`**@PostMapping**`

스프링 MVC에서 URL 매핑을 위해 사용됩니다. 각각 GET, POST, 그리고 HTTP 요청 메소드에 대한 매핑을 지정합니다.
