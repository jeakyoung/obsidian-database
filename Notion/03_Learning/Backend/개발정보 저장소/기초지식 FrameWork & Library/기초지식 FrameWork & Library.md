# 프레임워크 (Framework)

- **애플리케이션 개발을 위한 구조와 규칙을 정의한 큰 틀 또는 체계**
- 개발자가 프레임워크를 사용하면 특정 애플리케이션의 기본 구조와 동작 방식이 이미 정의되어 있어 개발 과정을 단순화하고 가속화할 수 있습니다.
- 주로 특정 도메인 또는 어플리케이션 유형에 맞는 기본 구조를 제공하며, 개발자는 이 구조 안에서 필요한 기능과 로직을 구현합니다.
- 프레임워크는 제어의 역전 (Inversion of Control) 원칙에 따라 동작하며, 개발자는 프레임워크가 정의한 규칙과 인터페이스를 따라야 합니다.
- 대표적인 프레임워크로는 Spring (Java), Ruby on Rails (Ruby), Django (Python), Angular (JavaScript) 등이 있습니다.

# 라이브러리 (Library)

- 라이브러리는 **재사용 가능한 코드 모음**으로,** 특정 기능 또는 작업을 수행하기 위한 함수, 클래스, 모듈 등을 포함**합니다.
- 개발자가 **라이브러리를 사용하면 해당 기능을 쉽게 활용**할 수 있으며, 애플리케이션의 **특정 부분에 필요한 라이브러리만 선택적으로 사용할 수 있습니다.**
- 라이브러리는** 애플리케이션의 일부분을 개선하거나 보완하는 데 사용**됩니다. 개발자는 **라이브러리를 호출하여 기능을 수행하며, 개발의 흐름을 제어**합니다.
- 라이브러리는 프**로젝트에 필요한 기능을 확장하기 위한 도구로, 일반적으로 개발자의 코드와 조화롭게 통합**됩니다.
- 예를 들어, NumPy (Python의 수치 계산 라이브러리), jQuery (JavaScript의 DOM 조작 라이브러리), Retrofit (Android의 HTTP 통신 라이브러리) 등이 라이브러리의 예입니다.

# 프레임워크와 라이브러리의 차이점

### 제어 흐름

**프레임워크는 개발자에게 제어 흐름을 주도적으로 넘깁니다**. 즉, **프레임워크가 애플리케이션의 실행 흐름을 제어하며 개발자는 프레임워크의 규칙**을 따라야 합니다. 반면 **라이브러리는 개발자가 직접 제어 흐름을 가지며 필요할 때 라이브러리의 기능을 호출**합니다.

### 기본 구조

프레임워크는 애플리케이션의 **기본 구조를 정의하고 제공**합니다. 라이브러리는 **특정 기능을 수행하기 위한 도구**로 사용됩니다.

### 의존성

**프레임워크는 높은 수준의 의존성을 가지며**, **프레임워크의 규칙과 구조**에 따라야 합니다. **라이브러리는 상대적으로 낮은 수준의 의존성을 가지며, 필요한 부분만 사용할 수 있습니다.**

### 확장성

프레임워크는 주로 특정 도메인에 맞는 확장성을 제공하며, 개발자는** 프레임워크 안에서 확장 작업을 수행**합니다. 라이브러리는** 개발자의 코드에 특정 기능을 추가하여 확장**됩니다.

### 예시

프레임워크로는 Django (웹 애플리케이션 개발), 라이브러리로는 NumPy (수치 계산)가 대표적인 예시입니다.

프레임워크는 **개발자에게 애플리케이션의 구조와 흐름을 제공**하며 개발자는 **프레임워크의 규칙**을 따라가야 합니다. 반면, **라이브러리는 개발자가 필요한 시점에 호출하여 사용**하며,** 개발자가 코드 흐름을 직접 제어**합니다.

프레임워크는** "흔들린다"는 개념**으로, 애플리케이션의 **주요 구조를 프레임워크가 통제**합니다. 반면, **라이브러리는 "개발자 주도"로, 개발자가 라이브러리를 호출하여 원하는 시점에 사용**합니다.

프레임워크는** 애플리케이션의 기본 구조를 정의**하며, 라이브러리는 **특정 작업을 수행하기 위한 도구로 사용**됩니다.
