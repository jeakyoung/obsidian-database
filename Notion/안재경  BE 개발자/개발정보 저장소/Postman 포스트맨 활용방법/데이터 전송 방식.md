HTTP에서 **POST**와 **GET**은 두 가지 다른 데이터 전송 방식입니다. 이 두 방식은 웹 애플리케이션과 웹 서버 간에 데이터를 주고받는 데 사용됩니다

## 차이점

### **데이터 전송 위치**

- **GET 방식**: **GET 요청은 URL의 일부로 데이터를 전송**합니다. 데이터는 URL의 쿼리 문자열에 포함되며, 주로 웹 서버에 데이터를 요청할 때 사용됩니다. 브라우저 주소 표시줄에 데이터가 노출되므로 보안에 취약할 수 있습니다. 또한 **URL에 데이터를 첨부하므로 전송할 수 있는 데이터 양에 제한**이 있습니다.
- **POST 방식**: **POST 요청은 HTTP 요청의 본문(body)에 데이터를 포함하여 전송**합니다. 데이터는 보통 폼(form) 데이터 또는 **JSON과 같은 데이터 형식으로 전송**됩니다. **POST 요청은 데이터를 URL에 노출시키지 않으므로 GET 방식보다 더 안전하며, 데이터 양에 제한이 없습니다.**

### **데이터 보안**

- **GET 방식**: GET 요청은 URL에 데이터를 노출시키므로 민감한 데이터(예: 비밀번호)를 전송하는 데 적합하지 않습니다. 브라우저 기록에 남을 수 있으며, URL을 통해 데이터가 전송되므로 보안에 취약합니다.
- **POST 방식**: POST 요청은 데이터를 HTTP 요청의** 본문에 포함**하므로 URL에 노출되지 않습니다. 이로써 GET 방식보다 더 안전한 방법으로 민감한 데이터를 전송할 수 있습니다.

### **캐싱**

- **GET 방식**: GET 요청은 데이터를 가져오는 목적이므로 캐싱이 가능합니다. 동일한 GET 요청은 동일한 결과를 반환하기 때문에 캐시에 저장하여 서버 부하를 줄일 수 있습니다.
- **POST 방식**: POST 요청은 데이터를 서버로 전송하는 목적이므로 캐싱되지 않습니다. 각각의 POST 요청은 서버에 새로운 데이터를 제공하므로 캐싱할 필요가 없습니다.

### **북마크 및 뒤로 가기**

- **GET 방식**: GET 요청은 URL에 노출되므로 사용자가 브라우저의 주소 표시줄에서 URL을 복사하거나 북마크로 저장할 수 있습니다. 사용자가 뒤로 가기 버튼을 누를 때, 이전 GET 요청의 결과를 볼 수 있습니다.
- **POST 방식**: POST 요청은 URL에 데이터가 노출되지 않으므로 북마크로 저장하거나 뒤로 가기로 이전 요청을 볼 수 없습니다.

### **데이터 길이 제한**

- **GET 방식**: GET 요청은 URL의 길이에 제한이 있으므로 매우 큰 데이터를 전송하기에는 적합하지 않습니다.
- **POST 방식**: POST 요청은 HTTP 본문에 데이터를 포함하므로 데이터 길이에 제한이 없습니다.
