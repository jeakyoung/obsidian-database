> [!note]+ ### **java.io.BufferedReader, writer;               	**
> → 버퍼를거쳐 전달되므로 기존에 쓰던 scanner와 print문 보다 효율이좋다. (많은데이터처리시유용)
> 
> →String 로 고정되며 엔터만 경계로 인식하기 때문에 입력받은 데이터를 가공하는 작업이 필요함
> 
> ```java
> BufferedReader bf = new BufferedReader(new InputStreamReader(System.in)); //선언
> String s = bf.readLine(); //String
> int i = Integer.parseInt(bf.readLine()); //Int
> ```
> 
> → 선언 방식이며 첫번째 줄에 readline의 return값은 String이므로 아래쪽과 같이 다른 형식 입력시 형식변환을 해주어야한다.
> 
> throw 이용 시
> 
> (1) 클래스를 import해주어야 한다.
> 
> *import java.io.IOException;*
> 
> (2) main 클래스 옆에 throws IOException를 작성한다.
> 
> *public static void main(String[] args) throws IOException {}*
> 
> Writer 이용시 버퍼로 잡혀있기에 **반드시** flush() / close()를 호출하여 뒷처리 해주어야한다.

> [!note]+ **private, public, protected**
> - public : 클래스 외부에서 사용할수 있도록 공개
> - private : 클래스 외부에서 사용할수 없도록 비공개
> - protected : 외부에서는 사용할수 없지만 상속받은 자식클래스에서는 사용가능
> 
> **Public**
> 
> public은 자료보호를 하지않고 외부에서 사용가능하도록 공개하는것이 목적이다.
> 
> **Private**
> 
> Private은 자료보호를 위해 외부에서 접근할수 없지만 public을 이용하여 한정적인 정보에 대해 접근할수 있도록 설정하는것이다.
> 
> **Protected**
> 
> protected는 private와 동일하지만 상속받은 클래스에서는 공개가 가능하다.
> 
> → JAVA 내의 상속개념에 대한 추가적인 공부필요

> [!note]+ **doGet, Post**
> 두가지 방식모두 이용하는 방법은 비슷하나 분명한 차이가 있음
> 
> - GET은 DB관점에서 SELECT에 가까우며 POST는 Create에 가깝다.
> 
> - **GET**
> 
> → GET요청은 브라우저 히스토리에 남으며 북마크가 가능하다. 이런 특징 때문에 GET요청은 
> 
> 파라미터로 전부다 확인가능하니 데이터를 요청할때만 이용하는것이 좋으며  캐시가 가능하다.
> 
> - **POST**
> 
> → POST 요청은 캐시되지 않으며 히스토리에 남지않고 북마크가 되지 않는다.  보통 HTML form을 통해서 서버로 전송된다.
> 
> 때문에 중요한 데이터는 완벽한 보안방식은 아니나 왠만해서는 POST방식을 이용하여 요청, 업데이트하는게 좋다. 하지만 BODY에서 뜯어보면 다보이니까 암복호화는 따로해야함.
>
